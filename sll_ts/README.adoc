= sll_ts — A thread-safe generics-based Go Singly Linked List

A generic, thread-safe singly linked list (SLL) of `*T` elements, where `T`
implements `comparable.Equality` (an `IsEqual(b Equality) bool` method).

This is the mutex-guarded variant of the `sll` package and exposes the same
API.  All methods on `Sll` and `SllIter` are protected by read/write mutexes
and are safe to call from multiple goroutines.

The list supports stack-like operations at the head (`Push`, `Pop`, `Peek`),
queue-like insertion at the tail (`InsertAfterTail`), value-based `Search`,
`Delete` and `DeleteFound`, in-place `Reverse`, and two kinds of iteration:

* a cursor iterator: `Front`/`Current` with `Done`/`Next`/`Value`/`Pos`
* Go 1.23 range-over-func iterators: `IterateOver` and `IteratePtr`

== Complexity

[cols="2,1,3"]
|===
|Operation |Complexity |Notes

|`NewSll`            |O(1) |
|`IsEmpty`           |O(1) |
|`Length`            |O(1) |
|`InsertBeforeHead`  |O(1) |also `Push`
|`InsertAfterTail`   |O(1) |maintains a tail pointer
|`Pop`               |O(1) |returns `ErrEmptySll` when empty
|`Peek`              |O(1) |returns `ErrEmptySll` when empty
|`Search`            |O(n) |head to tail, returns element and position
|`Delete`            |O(n) |returns `ErrNotFound` when missing
|`DeleteFound`       |O(n) |deletes by value of a found element
|`Reverse`           |O(n) |O(1) extra storage
|`Truncate`          |O(1) |drops all elements
|`Dump`              |O(n) |
|`IterateOver`/`IteratePtr` |O(n) |full traversal, O(n) snapshot
|===

== Example

[source,go]
----
package main

import (
	"fmt"

	"github.com/pschlump/pluto/comparable"
	"github.com/pschlump/pluto/sll_ts"
)

type Name string

func (a Name) IsEqual(x comparable.Equality) bool {
	b, ok := x.(Name)
	return ok && a == b
}

func main() {
	list := sll_ts.NewSll[Name]()
	a, b := Name("ada"), Name("bob")
	list.Push(&a)            // head: ada
	list.InsertAfterTail(&b) // ada, bob

	for i, v := range list.IterateOver() {
		fmt.Println(i, v)
	}

	v, _ := list.Pop() // v == ada
	_ = v
}
----

== Thread Safety

All methods are safe for concurrent use; each takes the list's read or write
lock as appropriate.  The range-over-func iterators (`IterateOver`,
`IteratePtr`) operate on a snapshot of the list taken when iteration begins,
so it is safe to mutate the list from inside the loop body — but changes made
after the snapshot are not visible to the ongoing iteration.

An element returned by `Search` is no longer protected by the list lock once
`Search` returns; treat it as read-only.
