= avl_tree_ts

A generic, self-balancing AVL binary search tree that is *safe for
concurrent use* — the thread-safe twin of
link:../avl_tree/[charon/avl_tree].  Every operation is guarded by a
`sync.RWMutex`: readers run in parallel with each other, writers are
exclusive.

Like `avl_tree`, it keeps the heights of the two child subtrees of every
node within one of each other, so `Insert`, `Delete` and `Search` are
*O(log₂ n) in the worst case* regardless of insertion order, and `Depth`
is O(1).  Ordering never goes through an interface method, so element
data is never boxed into an interface and never unboxed with a type
assertion.

* Elements are stored and returned *by value* (`T`, not `*T`); find-style
operations return `(T, bool)`.
* Trees of ordered key types (integers, floats, strings) are ordered by the
built-in `<` / `>` operators: `avl_tree_ts.NewAvlTree[int]()`.
* Trees of any other type — including structs ordered by a single field —
take a plain comparison function, with no interface to implement.

The public API is identical to `avl_tree` (plus the locking behavior
below), so switching between the two is a package-name change.

Runnable, tested copies of the examples live in
link:example_test.go[`example_test.go`] — they run under `go test` and appear
on pkg.go.dev.  The link:../avl_tree/[avl_tree README] documents the full API
usage and recipes; they all apply unchanged.

== Complexity

Same as `avl_tree`:

[options="header"]
|===
| Operation                                       | Complexity

| Insert / Delete / Search                        | O(log₂ n) worst case
| FindMin / FindMax / DeleteAtHead / DeleteAtTail | O(log₂ n) worst case
| Index                                           | O(n)
| Depth / IsEmpty / Len / Length / Truncate       | O(1)
| Walk* / WalkFunc / Dump                         | O(n)
| All / Backward (full iteration)                 | O(n) — plus an O(n) snapshot
| Copy / Union / Minus / Intersect                | O(n log₂ n)
|===

`Insert` returns `true` when a new node was added and `false` when a
duplicate replaced the stored value.  `Len` is an alias for `Length`,
matching the other charon tree packages.

== Locking behavior

* *Reads* (`Search`, `FindMin`, `FindMax`, `Index`, `Depth`, `Len`,
`Length`, `IsEmpty`) take the read lock and release it before returning —
they can run in parallel with each other.
* *Writes* (`Insert`, `Delete`, `DeleteAtHead`, `DeleteAtTail`,
`Reverse`, `Truncate`) take the write lock.
* *`Front`, `All` and `Backward` operate on a snapshot* of the tree taken
when they are called (under the read lock, released immediately after).
It is safe to mutate the tree while iterating — including from inside the
loop — and an iterator never observes modifications made after it was
created.  The snapshot costs one O(n) copy.
* *`WalkInOrder` / `WalkPreOrder` / `WalkPostOrder` and `Dump` hold the
read lock for the whole traversal.*  Their callbacks must *not* call
any method on the same tree — a write from a callback deadlocks on the
lock, and even a read can deadlock if a writer is waiting.  If you need
to mutate while visiting elements, iterate a snapshot with `All()`
instead.

[source,go]
----
for v := range tree.All() {
    tree.Delete(v) // safe: All iterates a snapshot
}
----

* *Set operations* (`Copy`, `Union`, `Minus`, `Intersect`) snapshot their
operands under each operand's own read lock before taking the
destination's write lock.  No two locks are ever held at once, so an
operand may safely alias the destination or the other operand, and
concurrent set operations cannot deadlock against each other.  The
result is ordered by the destination's comparison function; a zero-value
destination adopts an operand's.

== Panics

Identical to `avl_tree` — the package panics in exactly three situations,
all programmer errors with no sane fallback:

[options="header"]
|===
| Call | Why 

| `NewAvlTreeFunc(nil)` | nil comparison function, caught at construction time 
| `Insert` on a nil `*AvlTree` | a nil tree cannot store an element 
| `Insert` on a zero-value tree | no comparison function; the message names the constructors 
|===

Everything else tolerates a nil tree and the zero value as an empty tree
(the zero value of `sync.RWMutex` is a working lock), including nil
operands to the set operations, which act as the empty set.

== Usage

[source,go]
----
package main

import (
    "fmt"
    "sync"

    "github.com/pschlump/charon/avl_tree_ts"
)

func main() {
    tree := avl_tree_ts.NewAvlTree[int]()

    // Writers from many goroutines share one tree.
    var wg sync.WaitGroup
    for w := 0; w < 8; w++ {
        wg.Add(1)
        go func(w int) {
            defer wg.Done()
            for i := 0; i < 100; i++ {
                tree.Insert(w*1000 + i)
            }
        }(w)
    }
    wg.Wait()
    fmt.Println(tree.Len()) // 800

    // Deleting from inside an All loop is safe: it iterates a snapshot.
    for v := range tree.All() {
        tree.Delete(v)
    }
    fmt.Println(tree.IsEmpty()) // true
}
----
