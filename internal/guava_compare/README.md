# Guava comparison harness

This directory is the Phase 0 differential and benchmark harness. It is not a
production package. Normal `go test ./...` only reads committed JSON files; it
never starts Java, Maven, or JMH.

The smoke fixture compares a Go `map[string]int` counter model with Guava's
`HashMultiset`. The same corpus also drives the Phase 1a matched benchmarks for
Guava and Pluto hash/tree multisets and Go/Java map baselines. Raw and normalized
Phase 1a results are retained in `docs/benchmarks/multiset/`. Phase 1b adds a
three-variant multimap oracle and a separately seeded multimap corpus; those
results are retained in `docs/benchmarks/multimap/`.

## Run

`make guava-bench` requires Go, a JDK (11 or newer), Git, and either Maven or
the executable `note/guava/mvnw` wrapper. The target:

1. verifies that `note/guava` is at commit
   `36e3995499d6c3b74b1207d362fa9e19915d2589`;
2. builds that source checkout and the Java drivers;
3. executes the same trace in Go and Java and compares canonical output and the
   committed golden byte-for-byte;
4. runs matched `testing.B` and JMH workloads using the same corpus; and
5. writes raw and normalized results under `internal/guava_compare/results/`
   (ignored by Git).

The normalized JSON records machine, OS/architecture, Go and JDK versions,
Guava commit, JMH settings, capacity, input distribution, and random seed.
Latency/throughput, allocations, and allocated bytes remain separate metrics;
no speed ratio is calculated.

## Trace contract

Version 1 trace files have `version`, `fixture`, `seed`, and `operations`.
The `counter` fixture accepts these operations:

- `add` and `remove`: require a string `value` and positive `count`, and return
  the resulting count. Removing more than the current count saturates at zero.
- `setCount`: requires a nonnegative `count` and returns the resulting count.
- `count`: returns the count for `value`.
- `size` and `distinctSize`: return total occurrences and distinct values.

Canonical results contain one integer result per operation and a final state.
Final entries are sorted by value so map iteration order cannot affect output.
The committed `testdata/counter.golden.json` is generated by the Java oracle.

## Generate and normalize

Regenerate deterministic trace and corpus files from the repository root:

```sh
go run ./internal/guava_compare/cmd/guava-compare generate
```

After a deliberate trace change, run `make guava-bench`, review
`results/java-oracle.json`, and install it as `testdata/counter.golden.json`.
Normal tests use only the committed result.

To normalize existing raw output:

```sh
go run ./internal/guava_compare/cmd/guava-compare normalize \
  -go internal/guava_compare/results/go-bench.txt \
  -jmh internal/guava_compare/results/jmh.json \
  -output internal/guava_compare/results/normalized.json
```

## Updating Guava

A deliberate Guava update must update the pin in `trace.go`, `CounterOracle`,
`run.sh`, and `docs/guava-to-dev-plan.md`; regenerate and review the golden and
benchmark baseline; and record the new commit with those results. Do not update
to an unrelated released Guava artifact: Maven builds the pinned local source.
