= stack_sll_ts

A generic *LIFO stack* built on a singly linked list that is *safe
for concurrent use*.  Every operation is guarded by a `sync.RWMutex`:
readers run in parallel with each other, writers are exclusive.

The element type needs *no constraints at all* and the zero value of
`Stack` is an empty stack ready to use without a constructor.  Elements
are stored and returned *by value* (`Pop` and `Peek` return
`(T, error)`).

== Why not the slice-backed `stack` + a mutex?

Pluto's `sll_ts` requires an equality function at insert (its
`Search` needs one), but a stack never compares elements — so wrapping
would force a dummy comparator and break the constraint-free contract.
Like every pluto `_ts` package this one is self-contained, with its own
lock and a plain singly linked list underneath.

The practical difference from the slice-based link:../stack/[`stack`] is
*memory behavior*: pushes and pops allocate and free one small node
each and never reallocate, so memory use is stable across arbitrary
push/pop patterns (the slice-backed stack periodically reallocates as
its window walks).  Trade-off: one allocation per push.

== Operations

[options="header"]
|===
| Operation                    | Description                               | Complexity

| `Push`                       | Insert at the top                         | O(1)
| `Pop`                        | Remove and return the top                 | O(1)
| `Peek`                       | Look at the top without removing          | O(1)
| `IsEmpty` / `Len` / `Length` | Size queries                              | O(1)
| `Truncate`                   | Remove all elements                       | O(1)
| `All` / `Backward`           | Range-over-func iterators over a snapshot | O(n)
| `Slice`                      | Fresh `[]T` snapshot, TOP DOWN            | O(n)
| `String` / `StringFunc`      | Render the elements: `[a b c]`            | O(n)
| `Equal`                      | Same sequence (ORDER-SENSITIVE)           | O(n)
| `Clone`                      | Deep copy                                 | O(n)
|===

`All` iterates from the *top* (most recently pushed, index 0) to the
bottom; `Backward` from the bottom to the top.  `Len` is an alias for
`Length`, matching the other pluto packages.

== Locking behavior

* *Reads* (`Peek`, `Len`, `Length`, `IsEmpty`) take the read lock and
release it before returning — they can run in parallel with each other.
* *Writes* (`Push`, `Pop`, `Truncate`) take the write lock.
* *`All` and `Backward` operate on a snapshot* taken when they are
called (one O(n) copy, under the read lock).  It is safe to mutate the
stack while iterating — including from inside the loop — and an
iterator never observes modifications made after it was created.

[source,go]
----
for _, v := range stk.All() {
    stk.Pop() // safe: All walks a snapshot
    _ = v
}
----

== Set-convenience capabilities

Sequences get the minimal menu only — `Slice`, `String`/`StringFunc`,
`Equal` and `Clone`, in link:capabilities.go[`capabilities.go`].
Sequences are not sets, so there is deliberately no `Contains`, no batch
insert/delete and no predicate bulk delete: an O(n) membership scan over
a sequence would be a footgun.

[source,go]
----
stk.Push(1)
stk.Push(2)

fmt.Println(stk.String())   // [2 1] — top down
fmt.Println(stk.Slice())    // [2 1]
dup := stk.Clone()
fmt.Println(stk.Equal(dup)) // true
----

`Equal` is the one *order-sensitive* `Equal` in pluto — `[2 1]` (2 on
top) is not equal to `[1 2]` (1 on top); every set-shaped package
compares membership instead.  It compares elements pairwise with Go's
`==` through interface conversion, so the element type must be
comparable: a non-comparable element type (a slice, map or function)
panics with Go's runtime comparison panic, but only when two elements
are actually compared — stacks of different lengths, and nil or empty
stacks, are answered without touching any element.

All four are total functions — none panics on a nil stack — and all four
follow the lock discipline above: `Slice`, `String`/`StringFunc` and
`Clone` snapshot under the read lock and compute outside it (the format
callback may call back into the stack), and `Equal` snapshots each side
separately, one lock at a time, so two stacks can be compared from
concurrent goroutines without deadlock.

== Errors and panics

The empty stack is reported with an error (compare with `errors.Is`):

[options="header"]
|===
| Error | Meaning 

| `ErrEmptyStack` | `Pop`/`Peek` on an empty stack 
|===

The package has exactly *one* panic:

[options="header"]
|===
| Call | Why 

| `Push` on a nil stack | a nil stack cannot store an element 
|===

Everything else — including the zero value, which is fully usable because
there is no comparison or equality function to configure — tolerates a
nil stack as an empty stack.  The capability methods add no panics of
their own; the only caveat is `Equal`, which inherits Go's runtime
comparison panic when the element type is non-comparable and two
elements are actually compared (see above).

== Usage

[source,go]
----
package main

import (
    "fmt"
    "sync"

    "github.com/pschlump/pluto/stack_sll_ts"
)

func main() {
    var stk stack_sll_ts.Stack[int]

    // Writers from many goroutines share one stack.
    var wg sync.WaitGroup
    for w := 0; w < 8; w++ {
        wg.Add(1)
        go func(w int) {
            defer wg.Done()
            for i := 0; i < 100; i++ {
                stk.Push(w*1000 + i)
            }
        }(w)
    }
    wg.Wait()
    fmt.Println(stk.Len()) // 800

    // Concurrent poppers drain it.
    for !stk.IsEmpty() {
        if _, err := stk.Pop(); err != nil {
            break
        }
    }
    fmt.Println(stk.IsEmpty()) // true
}
----
