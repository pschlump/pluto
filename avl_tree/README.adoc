= avl_tree

A generic, self-balancing AVL binary search tree.  The heights of the two
child subtrees of every node are kept within one of each other, so
`Insert`, `Delete` and `Search` are *O(log₂ n) in the worst case* —
regardless of insertion order, unlike the unbalanced
link:../binary_tree/[`binary_tree`].  Every node caches its subtree height, so
`Depth` is O(1).  See
link:https://en.wikipedia.org/wiki/AVL_tree[]
for the theory.

It is a rework of
link:https://github.com/pschlump/pluto/tree/main/avl_tree[pluto/avl_tree]
that replaces the `comparable.Comparable` interface constraint with pure
Go type parameters, so element data is never boxed into an interface and
never unboxed with a type assertion.

* Elements are stored and returned *by value* (`T`, not `*T`); find-style
operations return `(T, bool)`.
* Trees of ordered key types (integers, floats, strings) are ordered by the
built-in `<` / `>` operators: `avl_tree.NewAvlTree[int]()`.
* Trees of any other type — including structs ordered by a single field —
take a plain comparison function, with no interface to implement:
`avl_tree.NewAvlTreeFunc(func(a, b Item) int { ... })`.

Runnable, tested copies of the examples live in
link:example_test.go[`example_test.go`] — they run under `go test` and appear
on pkg.go.dev.

== Operations

[options="header"]
|===
| Operation                                        | Description                                     | Complexity

| `Insert`                                         | Add an element; duplicates replace the old data | O(log₂ n)
| `Delete`                                         | Remove an element; reports whether it was found | O(log₂ n)
| `Search`                                         | Return the stored element equal to the probe    | O(log₂ n)
| `FindMin` / `FindMax`                            | Return the smallest / largest element           | O(log₂ n)
| `DeleteAtHead` / `DeleteAtTail`                  | Remove the smallest / largest element           | O(log₂ n)
| `Index`                                          | Return the Nth element in in-order sequence     | O(n)
| `IsEmpty` / `Len` / `Length` / `Depth`           | Tree size and height queries                    | O(1)
| `Truncate`                                       | Remove all elements                             | O(1)
| `Reverse`                                        | Mirror the tree (mainly useful for testing)     | O(n)
| `WalkInOrder` / `WalkPreOrder` / `WalkPostOrder` | Apply a function to every node                  | O(n)
| `Copy` / `Union` / `Minus` / `Intersect`         | Whole-tree set operations                       | O(n log₂ n)
| `Front` + `Next`/`Value`/`Done`                  | Old-style in-order iterator                     | O(n) total
| `All` / `Backward`                               | Range-over-func iterators                       | O(n)
|===

`Insert` returns `true` when a new node was added and `false` when a
duplicate replaced the stored value.

The tree is *not* safe for concurrent use.

== Usage

[source,go]
----
tree := avl_tree.NewAvlTree[int]()

// Sorted input still leaves a shallow tree: the AVL rotations keep the
// two child subtrees of every node within one height of each other.
for i := range 1000 {
    tree.Insert(i)
}
fmt.Println(tree.Depth()) // 10, not 1000
----

Structs ordered by a field — the element type implements no interface, and
the exported `Compare` helper builds the field comparison:

[source,go]
----
type Employee struct {
    ID   int
    Name string
}

byID := avl_tree.NewAvlTreeFunc(func(a, b Employee) int {
    return avl_tree.Compare(a.ID, b.ID)
})
byID.Insert(Employee{ID: 3, Name: "Ada"})

// A search probe only needs the fields the comparison reads: the ID.
if e, found := byID.Search(Employee{ID: 3}); found {
    fmt.Println(e.Name) // Ada
}
----

=== Set operations

`Copy`, `Union`, `Minus` and `Intersect` rebuild the destination from
snapshots of their operands, so an operand may safely alias the
destination.  The result is ordered by the destination's comparison
function; a zero-value destination adopts the first operand's:

[source,go]
----
a := avl_tree.NewAvlTree[int]() // {1, 2, 3}
b := avl_tree.NewAvlTree[int]() // {2, 3, 4}

var union avl_tree.AvlTree[int] // zero value adopts a's comparison function
union.Union(a, b)               // {1, 2, 3, 4}

var diff avl_tree.AvlTree[int]
diff.Minus(a, b) // {1}
----

== Iteration

Three ways to walk the tree, all in in-order (sorted) sequence:

. `All()` / `Backward()` — range-over-func iterators (Go 1.23+);
`Backward()` iterates in descending order.
. `Front()` — old-style iterator with `Value()`/`Next()`/`Done()`, which
can be paused and resumed.
. `WalkInOrder` / `WalkPreOrder` / `WalkPostOrder` — callback walks.  The
callback receives the position in walk order and the node depth (root
is 0); returning `false` stops the walk.  Caller state is captured in a
closure — statically typed, never boxed into an `interface{}`:

[source,go]
----
   total := 0
   tree.WalkInOrder(func(pos, depth int, data string) bool {
       total += len(data)
       return true // false stops the walk
   })
----

It is not safe to modify the tree while an iterator or walk is in progress.

== Panics

The package panics in exactly three situations — all programmer errors
with no sane fallback:

[options="header"]
|===
| Call | Why 

| `NewAvlTreeFunc(nil)` | nil comparison function, caught at construction time 
| `Insert` on a nil `*AvlTree` | a nil tree cannot store an element 
| `Insert` on a zero-value tree | no comparison function; the message names the constructors 
|===

Everything else tolerates a nil tree and the zero value as an empty tree
(including nil operands to the set operations, which act as the empty
set).

== Differences from pluto/avl_tree

* The `comparable.Comparable` interface constraint is gone: ordering is
either the key type's built-in operators (`NewAvlTree`) or a caller
supplied function (`NewAvlTreeFunc`).  No boxing of elements, no dynamic
dispatch, no type assertions inside `Compare` methods.
* Elements are stored and returned by value.  Find-style operations
(`Search`, `FindMin`, `FindMax`, `Index`) return `(T, bool)` instead of
a nil-able `*T`.
* `Insert` reports whether a new node was added (`true`) or a duplicate
replaced the old value (`false`); the pluto version returns nothing.
* `Len` is available as an alias for `Length`, matching `binary_tree`.
* A nil `*AvlTree` behaves as an empty tree for every operation except
`Insert`; pluto panics with a generic message on most methods called on
a nil tree.
* The only panics are the three listed above, each with a message naming
the fix.
* The `Walk*` callbacks capture state in closures instead of receiving an
`interface{}` `userData` parameter.
* The set operations snapshot their operands before rebuilding the
destination (aliasing a source with the destination is safe) and a
zero-value destination adopts an operand's comparison function.
* No dependency on `pluto/g_lib` or `pluto/stack`: the rotations use the
builtin `max` and the iterator keeps its pending nodes on a plain slice.
