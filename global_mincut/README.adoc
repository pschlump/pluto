= global_mincut — Minimum Cut of an Undirected Weighted Graph

:toc:

== Overview

`global_mincut` finds a *minimum global cut* of an edge-weighted
undirected graph — the bipartition of the vertices with the least total
weight of crossing edges (Sedgewick & Wayne, Algorithms 4th ed., §6.4)
— via the Stoer–Wagner algorithm, as a constructor-style query object
over pluto's link:../dijkstra/[`dijkstra`]
`EdgeWeightedGraph` (the same container link:../mst/[`mst`] consumes —
an intra-pluto composition).

Unlike the max-flow route (n−1 Ford–Fulkerson runs, one per sink),
Stoer–Wagner needs no source pair and no edge ordering: it runs V−1
merge phases, each a maximum-adjacency search whose last vertex yields a
candidate cut; the minimum over phases is the global minimum cut.  Ties
in the search break toward the smallest vertex id, so the reported cut
side is deterministic for a given graph.

The result is an immutable snapshot of the graph at construction time —
later `AddEdge` calls are not reflected — and is safe for concurrent
reads.

== Operations

[cols="1,3,1",options="header"]
|===
| Operation              | Description                                                       | Complexity

| `NewGlobalMincut(g)`   | Compute a minimum cut of g (Stoer–Wagner)                         | O(V³) time, O(V²) space
| `Weight()`             | Total weight of the cut's crossing edges (0 if disconnected)      | O(1)
| `Cut()`                | One side of the cut, sorted vertices, fresh slice (nil if none)   | O(V)
| `InCut(v)`             | Is v on the returned side (false when out of range / no cut)      | O(1)
|===

`Cut()` returns nil only when no bipartition exists — a single-vertex
graph (or a nil result).  Every graph with at least two vertices has a
minimum cut, weight 0 included: a disconnected graph reports weight 0
with one whole component as the side.

== Semantics

* **Parallel edges sum** — two weight-2 edges between the same pair cut
  like one weight-4 edge (capacity semantics, matching max-flow).
* **Self-loops are ignored** — a self-loop never crosses a cut.
* **Weights must be finite and non-negative** — the constructor panics
  naming the first offending edge (NaN compares false against every
  bound, so it is rejected explicitly, as are ±Inf).
* **Determinism** — the maximum-adjacency search breaks ties toward the
  smallest vertex id, so repeated runs over the same graph return the
  same cut (either side of a tied minimum cut is a correct answer; which
  side is reported is fixed).

== Usage

[source,go]
----
import (
    "github.com/pschlump/pluto/dijkstra"
    "github.com/pschlump/pluto/global_mincut"
)

g := dijkstra.NewEdgeWeightedGraph(6)
for _, e := range []dijkstra.Edge{
    {V: 0, W: 1, Weight: 10}, {V: 1, W: 2, Weight: 10}, {V: 2, W: 0, Weight: 10},
    {V: 3, W: 4, Weight: 10}, {V: 4, W: 5, Weight: 10}, {V: 5, W: 3, Weight: 10},
    {V: 2, W: 3, Weight: 1}, // the bridge
} {
    g.AddEdge(e)
}

c := global_mincut.NewGlobalMincut(g)
c.Weight()   // 1  — severing the bridge is cheapest
c.Cut()      // [3 4 5] — one whole triangle
c.InCut(4)   // true
----

Runnable, tested examples live in link:example_test.go[`example_test.go`].

== Panics

[options="header"]
|===
| Call                                          | Why

| `NewGlobalMincut(nil)` / empty graph          | no bipartition exists to compute
| `NewGlobalMincut` on a negative weight        | Stoer–Wagner's cut lemma needs non-negative weights; the panic names the edge
| `NewGlobalMincut` on a NaN / ±Inf weight      | cut weights must be finite; the panic names the edge
|===

Every other operation tolerates nil and zero values: a nil
`*GlobalMincut` reports `Weight` 0, `Cut` nil and `InCut` false — the
same zero answer a single-vertex graph produces.

== Thread safety

Not safe for concurrent use — but there is nothing to share: the
constructor is a pure function of its argument and the result object is
immutable once built, so concurrent *reads* of a `*GlobalMincut` are
safe with no locking (the `suffix_array` / `maxflow` precedent — no
`_ts` twin).

== Benchmark reality

The O(V³) matrix form is one sweep, allocation-light (a V×V float64
matrix): ~300µs at n=60, ~4ms at n=150, ~74ms at n=400 (M4 Max).  The
n−1-max-flows alternative (pluto's `maxflow`) measures 5.7× slower at
n=60 and 3× at n=150 — most of its cost is building n−1 `FlowNetwork`s
— which is why Stoer–Wagner is the implementation here; the max-flow
route survives in the test file as the cross-check oracle.
