= g_lib — Generic Utility Functions
:toc:

== Overview

`g_lib` is a small library of generic utility functions built on Go type
parameters: min/max, absolute value and exponentiation, slice searching
and manipulation, set conversion, map key extraction, and a pointer
helper — plus the `Point2D`/`RectHV` geometry value types (below).
There are no data structures here — just pure functions on slices and
maps — which makes it the one non-structure package in pluto.

Everything is stdlib-only; ordering comes from the standard library's
`cmp.Ordered`, and arithmetic comes from the numeric constraints defined
in this package (see below).

== Functions

[cols="1,2,1",options="header"]
|===
| Function                 | Description                                                    | Complexity

| `Min`, `Max`             | Smaller / larger of two ordered values                         | O(1)
| `MinArray`, `MaxArray`   | Smallest / largest element of a slice (zero value if empty)    | O(n)
| `Abs`                    | Absolute value of a signed numeric value                       | O(1)
| `Pow`                    | `base` raised to `exponent` by repeated multiplication         | O(exponent)
| `IfTrue`                 | Ternary-style selector: `a` if `on`, else `b`                  | O(1)
| `InArray`                | Linear membership test in a slice                              | O(n)
| `LocationInArray`        | Index of first occurrence, or -1                               | O(n)
| `Ptr`                    | Pointer to a copy of a value (the Go 1.26 `new(expr)` form)    | O(1)
| `RemoveAt`               | Copy of slice with item at `pos` removed; input never modified | O(n)
| `Remove`                 | New slice without items `reflect.DeepEqual` to `needle`        | O(n)
| `RemoveComparable`       | New slice without items equal to `element`                     | O(n)
| `Unique`                 | Slice with duplicates removed, first-occurrence order          | O(n)
| `EqualSlice`             | Element-wise slice equality                                    | O(n)
| `FormatSorted`           | Elements formatted then string-sorted into `[a b c]`           | O(n log n)
| `SortSlice`              | In-place ascending sort                                        | O(n log n)
| `ToBoolMap`              | Slice to set (`map[T]bool`)                                    | O(n)
| `KeysForStringMap`       | Keys of a `map[string]T`, unspecified order                    | O(n)
| `SortedKeysForStringMap` | Keys of a `map[string]T`, sorted                               | O(n log n)
| `GetMapKeys`             | Keys of any map, unspecified order                             | O(n)
|===

`Pow` ignores numeric overflow (use a wide enough T), and a negative
exponent returns `T(1)` — the loop runs zero times.  `Abs` of the most
negative value of a signed integer type overflows and stays negative.

== Numeric constraints

The arithmetic functions are parameterized with these constraint
interfaces; they are exported for callers building their own generic
helpers on top.

[cols="1,3,1,1",options="header"]
|===
| Constraint | Type set | Accepts defined types (`~T`) | `uintptr`

| `Numeric` | all integer and floating-point types | yes | no
| `SignedInteger` | all signed integer types | yes | —
| `SignedNumeric` | all signed integer and floating-point types | yes | —
| `Unsigned` | all unsigned integer types + `uintptr` | yes | yes
| `Number` | all integer and floating-point types | *no* | no
|===

`Number` (used by `Pow`) is the odd one out: its type set lists the
predeclared types exactly, so a type *defined* from one of them
(`type celsius float64`) does not satisfy it.  `Numeric` covers the
same types with `~` and accepts defined types.

== Edge-case semantics

* Empty and nil slices: `MinArray`/`MaxArray` return the zero value of
`T`; `InArray` returns false and `LocationInArray` returns -1;
`Remove`/`RemoveComparable`/`Unique` return an empty (nil) slice;
`ToBoolMap` returns an empty non-nil map.
* Empty and nil maps: `KeysForStringMap` returns nil, `GetMapKeys`
returns an empty non-nil slice, `SortedKeysForStringMap` returns nil.
* `RemoveAt` with an out-of-range `pos` returns the input slice
unchanged (not a copy); with a valid `pos` it returns a fresh slice and
never modifies its input.
* `Remove` compares with `reflect.DeepEqual`, so it also works for
element types that are not comparable (slices, maps, functions);
`RemoveComparable` uses `==` and is the faster choice for comparable
elements.
* `FormatSorted` renders an empty or nil slice as `[]`; it sorts only
the formatted strings, never reordering or modifying the input
elements.  It exists so hash-family containers (whose iteration order
is seeded randomly per process) can print run-to-run deterministic
`String()` output without requiring `T` to be ordered.

== Geometry value types

`Point2D` and `RectHV` (link:point2d.go[`point2d.go`]) are the §1.2
planar geometry support types, introduced for pluto's
link:../kd_tree/[kd_tree] and the geometry batch to come — plain
comparable structs, not interfaces, per the house rule.

* `Point2D{X, Y float64}` — `String` ("(x, y)"), `DistanceSquaredTo`,
`DistanceTo`, the orientation predicate `CCW` (+1 ccw / -1 cw / 0
collinear), `Area2` (its raw magnitude), the axis orders `CompareXY`
/ `CompareYX`, and `PolarOrder()` — a comparator closure sorting by
polar angle around the point (algs4 `polarOrder`), the Graham scan's
sort.  Comparable, so it works as a map key (the kd_tree contract).
* `RectHV{Xmin, Ymin, Xmax, Ymax float64}` — `Contains` (boundary
inclusive), `Intersects`, `DistanceSquaredTo` (per-axis clamp).
* The float predicates (`CCW`, `Area2`, `DistanceSquaredTo`) pin
  their products unfused via `math.FMA(x, y, 0)` — the geo package's
  contract — because Go's permitted FMA contraction would otherwise
  make `CCW(a, b, b)` return the multiply's rounding error instead of
  0 (observed on arm64).  Do not rewrite those expressions.
* NaN is tolerated everywhere (no method panics; NaN coordinates never
  order and NaN rectangles contain/intersect nothing — `CCW` reports
  "collinear" on NaN, which is why the geometry package rejects NaN
  input at construction); inverted
  rectangles contain nothing; `kd_tree` uses ±Inf bounds as the whole
  plane.

== Usage

[source,go]
----
import "github.com/pschlump/pluto/g_lib"

m := g_lib.Min(3, 4)                              // 3
pos := g_lib.LocationInArray([]int{1, 42, 7}, 42) // 1
s := g_lib.Unique([]string{"a", "b", "a"})        // ["a", "b"]
set := g_lib.ToBoolMap([]string{"x", "y"})        // map[string]bool{"x":true, "y":true}
p := g_lib.Ptr(42)                                // *int pointing at 42
----

Runnable, tested examples for every function live in
link:example_test.go[`example_test.go`].

== Thread Safety

All functions are safe for concurrent use.  They operate only on their
arguments and keep no shared state.  Functions that return a slice
(`RemoveAt`, `Remove`, `RemoveComparable`, `Unique`) never modify their
input.
