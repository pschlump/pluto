= binomial_queue

A generic *binomial queue* (binomial heap) — the mergeable priority
queue from Sedgwick's *Algorithms in C*, chapter 9.  `DeleteMin` always
removes and returns the minimum element.  A reversed comparison function
(`NewBinomialQueueFunc` with `-Compare(a, b)`) turns it into a max-first
queue.

The structure is a forest of binomial trees, at most one tree of each
degree, kept in strictly increasing order of degree; every tree is
min-heap-ordered (each child sorts at or after its parent).  A degree-k
tree holds exactly 2^k nodes, so a queue of n elements has at most
log₂ n + 1 trees.

The distinguishing operation is `Merge`: one queue absorbs another in
O(log n) — a binary heap (link:../heap[`heap`]) cannot merge faster than
O(n).  `Insert` is a 1-node merge, so it is O(1) amortized (the same
carry argument as incrementing a binary counter).

The element type implements no interface: ordering is either the
element type's built-in `<` / `>` operators (`NewBinomialQueue`) or a
caller supplied function (`NewBinomialQueueFunc`) — no boxing, no
dynamic dispatch, no type assertions.  Elements are stored and returned
*by value* (`T`, not `*T`).

== Operations

[options="header"]
|===
| Operation                    | Description                                                    | Complexity

| `Insert(v)`                  | Add an element (a 1-node merge)                                | O(1) amortized, O(log n) worst
| `Merge(other)`               | Absorb `other` into the receiver, leaving `other` empty        | O(log n + log m)
| `DeleteMin()`                | Remove and return the minimum                                  | O(log n)
| `FindMin()` / `Peek()`       | The minimum, without removing (scan of the tree roots)         | O(log n)
| `IsEmpty` / `Len` / `Length` | Size queries                                                   | O(1)
| `Truncate`                   | Remove all elements                                            | O(1)
| `All` / `Backward`           | Iterate internal forest order — *not sorted*                   | O(n)
| `Dump`                       | Indented per-tree listing, for debugging                       | O(n)
| `Slice` / `String` / `StringFunc` | Materialize/render in internal forest order — *not sorted* | O(n)
| `Equal`                      | Multiset equality via the stored comparison function           | O(n log n)
| `Clone`                      | Deep copy by re-insertion; the sorted drain survives           | O(n) amortized
|===

The element-returning operations (`DeleteMin`, `Peek`, `FindMin`) return
`(T, bool)` — a value copy plus a found flag, never a pointer into the
queue; an empty queue reports `false`.  `DeleteMin` detaches the minimum
root and merges its children (already a valid binomial forest) back in.

`All` yields index/value pairs in internal forest order (pre-order
within each tree), which is *not* sorted; repeatedly calling `DeleteMin`
is the way to consume a queue in sorted order.  `Backward` is the exact
reverse of `All`, with indexes counting down from `Length()-1`, so each
element gets the same index from both iterators.  A single-variable
range yields the index.  The queue must not be modified while an
iterator is running.

== Set-convenience capabilities

Binomial queues get the minimal §4.5 menu only — `Slice`,
`String`/`StringFunc`, `Equal` and `Clone`, in
link:capabilities.go[`capabilities.go`].  No membership batch and no
predicate bulk delete — a priority queue is a multiset with a pop
order, not a set.

`Slice` and `String` materialize in the internal forest order — the
same order `All` yields and the JSON marshal emits — *not* sorted
order; `DeleteMin` is the sorted drain.

[source,go]
----
q.Insert(3)
q.Insert(1)
q.Insert(2)

fmt.Println(q.Slice())  // [2 1 3] — forest order [B0:2, B1:(1 [3])]
fmt.Println(q.String()) // [2 1 3]
----

`Equal` is *multiset* equality: same length and the same sorted value
sequence, so two queues built from the same elements in any insertion
order — or by any *merge history*, which shapes the forest differently
— are equal.  It is non-destructive (neither side is reordered) and
compares through the stored comparison function, *never Go's `==`*, so
a non-comparable element type is fine.  Ties are safe by construction.

`Clone` rebuilds by re-insertion, so the clone's forest shape may
differ from the receiver's — unobservable, since only the multiset and
the sorted drain are content, and both survive.  A zero-value queue
clones to a fresh queue still without a comparison function, but it
remains usable as a `Merge` target (which adopts the operand's
comparison function).

All of them are total functions: none panics on a nil queue or a
zero-value queue, which behave as empty.

== Usage

[source,go]
----
q := binomial_queue.NewBinomialQueue[int]()
for _, v := range []int{42, 7, 13} {
    q.Insert(v)
}
min, _ := q.Peek() // 7
// DeleteMin drains in ascending order.
----

Merge — the reason to reach for a binomial queue over a binary heap:

[source,go]
----
a := binomial_queue.NewBinomialQueue[int]() // producer A's items
b := binomial_queue.NewBinomialQueue[int]() // producer B's items
// ... fill both ...
a.Merge(b) // b is now empty; a holds everything, still min-first
----

A max-first queue or a priority queue over structs — the element type
implements no interface, and the exported `Compare` helper builds the
field ordering:

[source,go]
----
type Task struct {
    Priority int
    Name     string
}

pq := binomial_queue.NewBinomialQueueFunc(func(a, b Task) int {
    return binomial_queue.Compare(a.Priority, b.Priority)
})
pq.Insert(Task{3, "write"})
pq.Insert(Task{1, "review"})
// DeleteMin yields 1:review first.
----

== Panics

The package panics in exactly three situations — all programmer errors
with no sane fallback:

[options="header"]
|===
| Call | Why

| `NewBinomialQueueFunc(nil)` | nil comparison function, caught at construction time
| `Insert` on a nil queue | a nil queue cannot store an element
| `Insert` on a zero-value queue | no comparison function; the message names the constructors
| `Merge` on a nil receiver with a non-empty other | the elements have nowhere to go
|===

Everything else tolerates a nil queue and the zero value as an empty
queue and reports not-found / no-op: `DeleteMin`, `Peek`, `FindMin`,
`Len`, `Length`, `IsEmpty`, `Truncate`, `Dump`, `All`, `Backward`,
every set-convenience capability, and a `Merge` whose other side is
empty or nil.  Merging into a zero-value receiver adopts the other
queue's comparison function; merging a queue into itself is a no-op.

== Concurrency

A `BinomialQueue` is not safe for concurrent use.  Guard it with your
own mutex if it is shared between goroutines.
