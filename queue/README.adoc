= queue

A generic *FIFO queue* built on a slice — the simplest container in
pluto.  The element type needs *no constraints at all*: there is no
ordering and no equality to supply, and the zero value of `Queue` is an
empty queue ready to use without a constructor.

Elements are stored and returned *by value* — `Dequeue` and `Peek`
return `(T, error)` instead of a pointer — so a dequeued or peeked
element never aliases the queue's internals.

Not safe for concurrent use (a mutex-guarded twin has the same
interface).

== Operations

[options="header"]
|===
| Operation                    | Description                          | Complexity

| `Push` / `Enqueue`           | Insert at the tail                   | O(1) amortized
| `Pop`                        | Remove the head                      | O(1)
| `Dequeue`                    | Remove and return the head           | O(1)
| `Peek`                       | Look at the head without removing    | O(1)
| `IsEmpty` / `Len` / `Length` | Size queries                         | O(1)
| `Truncate`                   | Remove all elements                  | O(1)
| `All` / `Backward`           | Range-over-func iterators with index | O(n)
| `Slice`                      | Fresh `[]T`, FIFO order (head first) | O(n)
| `String` / `StringFunc`      | Render the elements: `[a b c]`       | O(n)
| `Equal`                      | Same sequence (ORDER-SENSITIVE)      | O(n)
| `Clone`                      | Deep copy                            | O(n)
|===

`Len` is an alias for `Length`, matching the other pluto packages.

== Set-convenience capabilities

Sequences get the minimal menu only — `Slice`, `String`/`StringFunc`,
`Equal` and `Clone`, in link:capabilities.go[`capabilities.go`].
Sequences are not sets, so there is deliberately no `Contains`, no batch
insert/delete and no predicate bulk delete: an O(n) membership scan over
a sequence would be a footgun.

[source,go]
----
q.Enqueue(1)
q.Enqueue(2)

fmt.Println(q.String())   // [1 2]
fmt.Println(q.Slice())    // [1 2]
dup := q.Clone()
fmt.Println(q.Equal(dup)) // true
----

`Equal` is the one *order-sensitive* `Equal` in pluto — `[1 2]` is not
equal to `[2 1]`; every set-shaped package compares membership instead.
It compares elements pairwise with Go's `==` through interface
conversion, so the element type must be comparable: a non-comparable
element type (a slice, map or function) panics with Go's runtime
comparison panic, but only when two elements are actually compared —
queues of different lengths, and nil or empty queues, are answered
without touching any element.

All four are total functions: none of them panics on a nil queue, which
behaves as an empty queue.

== Errors

The empty queue is reported with an error (compare with `errors.Is`):

[options="header"]
|===
| Error           | Meaning

| `ErrEmptyQueue` | `Pop`/`Dequeue`/`Peek` on an empty queue
|===

== Usage

[source,go]
----
var q queue.Queue[int] // no constructor needed

q.Enqueue(1)
q.Enqueue(2)

head, _ := q.Dequeue() // 1 — first in, first out
next, _ := q.Peek()    // 2 — still queued
----

Iteration, head (next out) to tail (last in) and back:

[source,go]
----
for i, v := range q.All() {
    ...
}
for i, v := range q.Backward() {
    ...
}
----

The queue must not be modified while an iterator is running.

== Panics

The package has exactly *one* panic, a programmer error with no sane
fallback:

[options="header"]
|===
| Call                            | Why

| `Push`/`Enqueue` on a nil queue | a nil queue cannot store an element
|===

Everything else — including the zero value, which is fully usable because
there is no comparison or equality function to configure — tolerates a
nil queue as an empty queue.  The capability methods add no panics of
their own; the only caveat is `Equal`, which inherits Go's runtime
comparison panic when the element type is non-comparable and two
elements are actually compared (see above).

== Memory behavior

Pops advance the slice window (`data = data[1:]`), zeroing each vacated
slot so the backing array does not keep dequeued elements alive; when the
queue drains completely the backing array is released entirely.  A
long-lived queue that grows and drains repeatedly will periodically
reallocate as the window walks off the front of the backing array — for
stable O(1) memory across arbitrary push/pop patterns, use the
doubly-linked-list queue in link:../dll/[`dll`] (`Enqueue`/`Pop`).
