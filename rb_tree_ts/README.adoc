= rb_tree_ts — Ordered Collection (Thread-Safe Red-Black Tree)
:toc:

Package `rb_tree_ts` implements an ordered collection of generic items as a
link:https://en.wikipedia.org/wiki/Red%E2%80%93black_tree[red-black]
self-balancing binary search tree that is safe for concurrent use.  All
operations are guarded by an internal `sync.RWMutex`.  Items must implement
`github.com/pschlump/pluto/comparable.Comparable` (a single `Compare`
method).

This is the thread-safe version of `rb_tree`; both packages expose the
identical API.

== Complexity

All ordered operations are `O(log n)` in the *worst case* — the red-black
balancing guarantees are deterministic, not expected-case.

[cols="2,1,2",options="header"]
|===
| Operation                     | Worst case | Notes

| `Insert`                      | O(log n)   | duplicate keys replace stored item
| `Search`                      | O(log n)   | returns `nil` when not found
| `Delete`                      | O(log n)   | returns `false` when not found
| `FindMin`/`FindMax`           | O(log n)   |
| `DeleteAtHead`/`DeleteAtTail` | O(log n)   | remove smallest/largest
| `IsEmpty`/`Length`            | O(1)       |
| `Truncate`                    | O(1)       | drops the whole tree
| `Depth`                       | O(n)       | walks the whole tree
| `All`/`Backward`              | O(n)       | iterate over a snapshot
|===

== Usage

Identical to `rb_tree`; import `github.com/pschlump/pluto/rb_tree_ts`
instead:

[source,go]
----
var tree rb_tree_ts.RbTree[Item]

tree.Insert(Item(5))
if p := tree.Search(Item(5)); p != nil {
	fmt.Println("found", *p)
}
for v := range tree.All() {
	fmt.Println(v)
}
----

== Thread Safety

`RbTree` *is* safe for concurrent use.  Reads (`Search`, `FindMin`,
`FindMax`, `IsEmpty`, `Length`, `Depth`, and the iterators) take the read
lock; mutations take the write lock.

`Search`, `FindMin` and `FindMax` return a *copy* of the stored item, so
mutating the returned value cannot corrupt the tree.  The `All` and
`Backward` iterators operate on a consistent snapshot taken under the read
lock when iteration starts; the lock is never held while the loop body runs,
and concurrent modifications are not reflected in the iteration.
