= skip_list_ts

A generic *skip list* that is *safe for concurrent use* — the
thread-safe twin of link:../skip_list/[charon/skip_list].  Every operation is
guarded by a `sync.RWMutex`: readers run in parallel with each other,
writers are exclusive.

Like `skip_list`, it is a probabilistic ordered collection — multiple
levels of linked lists where each higher level acts as an "express lane"
— with Insert, Search and Delete at *O(log₂ n) expected*, and no
degradation on sorted input.  And like every charon package it is a
rework of
link:https://github.com/pschlump/pluto/tree/main/skip_list_ts[pluto/skip_list_ts]
that replaces the `comparable.Comparable` interface constraint with pure
Go type parameters, so element data is never boxed into an interface and
never unboxed with a type assertion.

* Elements are stored and returned *by value* (`T`, not `*T`); find-style
operations return `(T, bool)`.
* Lists of ordered key types (integers, floats, strings) are ordered by the
built-in `<` / `>` operators: `skip_list_ts.NewSkipList[int]()`.
* Lists of any other type — including structs ordered by a single field —
take a plain comparison function, with no interface to implement.

The public API is identical to `skip_list` (plus the locking behavior
below), so switching between the two is a package-name change.

Runnable, tested copies of the examples live in
link:example_test.go[`example_test.go`] — they run under `go test` and appear
on pkg.go.dev.  The link:../skip_list/[skip_list README] documents the full
API usage; it applies unchanged.

== Locking behavior

* *Reads* (`Search`, `FindMin`, `FindMax`, `Len`, `Length`, `IsEmpty`)
take the read lock and release it before returning — they can run in
parallel with each other.
* *Writes* (`Insert`, `Delete`, `DeleteAtHead`, `DeleteAtTail`,
`Truncate`) take the write lock.
* *`All` and `Backward` operate on a snapshot* of the list taken when
they are called (under the read lock, released immediately after).  It
is safe to mutate the list while iterating — including from inside the
loop — and an iterator never observes modifications made after it was
created.  The snapshot costs one O(n) copy.
* *`Dump` holds the read lock for the whole dump*, so the writer must
not call methods on the same list.

[source,go]
----
for v := range list.All() {
    list.Delete(v) // safe: All iterates a snapshot
}
----

== Panics

Identical to `skip_list` — the package panics in exactly three situations,
all programmer errors with no sane fallback:

[options="header"]
|===
| Call                          | Why

| `NewSkipListFunc(nil)`        | nil comparison function, caught at construction time
| `Insert` on a nil `*SkipList` | a nil list cannot store an element
| `Insert` on a zero-value list | no comparison function; the message names the constructors
|===

Everything else tolerates a nil list and the zero value as an empty list
(the zero value of `sync.RWMutex` is a working lock).

== Usage

[source,go]
----
package main

import (
    "fmt"
    "sync"

    "github.com/pschlump/charon/skip_list_ts"
)

func main() {
    list := skip_list_ts.NewSkipList[int]()

    // Writers from many goroutines share one list.
    var wg sync.WaitGroup
    for w := 0; w < 8; w++ {
        wg.Add(1)
        go func(w int) {
            defer wg.Done()
            for i := 0; i < 100; i++ {
                list.Insert(w*1000 + i)
            }
        }(w)
    }
    wg.Wait()
    fmt.Println(list.Len()) // 800

    // Deleting from inside an All loop is safe: it iterates a snapshot.
    for v := range list.All() {
        list.Delete(v)
    }
    fmt.Println(list.IsEmpty()) // true
}
----

== Differences from pluto/skip_list_ts

* The `comparable.Comparable` interface constraint is gone: ordering is
either the key type's built-in operators (`NewSkipList`) or a caller
supplied function (`NewSkipListFunc`).  No boxing of elements, no
dynamic dispatch, no type assertions inside `Compare` methods.
* The data is stored by value in each node (pluto stored a `*T` pointing
at the inserted item).  `Search`, `FindMin` and `FindMax` return
`(T, bool)` instead of a nil-able `*T`; snapshots are `[]T`, not `[]*T`.
* `Insert` reports whether a new node was added (`true`) or a duplicate
replaced the old value (`false`); the pluto version returns nothing.
* `Len` is available as an alias for `Length`, matching the other charon
packages.
* A nil `*SkipList` behaves as an empty list for every operation except
`Insert`; pluto panics on `Insert`, `Delete`, `DeleteAtHead` and
`DeleteAtTail` called on a nil list.
* The only panics are the three listed above, each with a message naming
the fix.
* The snapshot for `All`/`Backward` is taken when they are called, not
when the range loop starts, so an iterator never observes modifications
made after its creation.
