= dll

A generic doubly linked list with head and tail pointers — usable
directly as a *stack* (`Push`/`Pop`/`Peek` at the head) and as a
*queue* (`Enqueue` at the tail, `Pop` from the head), with positional
access from either end and O(1) removal of previously found elements.

* Elements are stored and returned *by value* (`T`, not `*T`).
* Lists of types comparable with `==` (all scalars, strings, pointers,
arrays, and structs of comparable fields) need no equality function:
`dll.NewDll[int]()`.
* Any other type — or equality by a single field — takes a plain equality
function, with no interface to implement:
`dll.NewDllFunc(func(a, b Item) bool { return a.ID == b.ID })`.

The equality function is consulted *only* by `Search`,
`ReverseSearch`, and the `Delete` calls built on them.  The stack, queue
and positional operations never compare elements.  Search probes are
passed by value, so a probe only needs the fields the equality function
reads.

Runnable, tested copies of the examples live in
link:example_test.go[`example_test.go`] — they run under `go test` and appear
on pkg.go.dev.

== Operations

[options="header"]
|===
| Operation                                | Description                                | Complexity

| `Push` / `InsertBeforeHead`              | Insert at the head                         | O(1)
| `Enqueue` / `AppendAtTail`               | Insert at the tail                         | O(1)
| `Pop` / `DeleteAtHead`                   | Remove and return the head                 | O(1)
| `PopTail` / `DeleteAtTail`               | Remove and return the tail                 | O(1)
| `Peek` / `PeekTail`                      | Look at the head / tail without removing   | O(1)
| `Search` / `ReverseSearch`               | Find an element, head→tail or tail→head    | O(n)
| `Delete` / `DeleteSearch`                | Delete the first matching element          | O(n)
| `DeleteFound`                            | Delete a previously found element          | O(1)
| `Index` / `IndexFromTail`                | Nth element from the head / tail           | O(n), n/2
| `Walk` / `ReverseWalk`                   | Callback traversal, stoppable              | O(n)
| `All` / `Backward` / `IterateOver`       | Range-over-func iterators with index       | O(n)
| `Front`/`Rear`/`Current` + `Next`/`Prev` | Legacy bidirectional iterator with `Pos()` | O(n) total
| `Trim` / `TrimTail`                      | Keep first / last n elements               | O(n)
| `Concat`                                 | Append a copy of another list              | O(len src)
| `Reverse` / `ReverseList`                | Reverse in place, O(1) extra storage       | O(n)
| `Truncate`                               | Remove all elements                        | O(1)
| `IsEmpty` / `Len` / `Length`             | Size queries                               | O(1)
| `Dump`                                   | One line per element, for debugging        | O(n)
|===

`DllIter` (from `Front`, `Rear`, or `Current`) can be walked with `Next`
or `Prev` and reports its position with `Pos()`; `Value` returns
`(T, bool)`.

== Errors

Empty-list, not-found and out-of-range conditions are reported with
errors (compare with `errors.Is`), not panics:

[options="header"]
|===
| Error | Meaning 

| `ErrEmptyDll` | pop/peek/trim on an empty list 
| `ErrNotFound` | `Delete`/`DeleteSearch`/`DeleteFound(nil)` 
| `ErrOutOfRange` | `Index`/`IndexFromTail` with a bad subscript 
| `ErrInternalDll` | internal inconsistency (should never happen) 
|===

== Usage

Stack:

[source,go]
----
stack := dll.NewDll[string]()
stack.Push("first")
stack.Push("second")
top, _ := stack.Peek()   // second
v, _ := stack.Pop()      // second
----

Queue:

[source,go]
----
queue := dll.NewDll[int]()
queue.Enqueue(1)
queue.Enqueue(2)
head, _ := queue.Pop()   // 1 — first in, first out
----

Search and O(1) delete of a found element:

[source,go]
----
el, pos := list.Search(probe)  // element + position, or nil/-1
if el != nil {
    list.DeleteFound(el)
}
----

`DllElement.Data` is an unexported `T`; use `GetData()`/`SetData()` on
the handle.

Iteration with the index, both directions:

[source,go]
----
for i, v := range list.All() {
    ...
}
for i, v := range list.Backward() {
    ...
}
----

The `Walk`/`ReverseWalk` callbacks capture caller state in a closure
(statically typed, never boxed).  Note the dll convention: returning
*true stops the walk* — the opposite of the pluto tree packages — and
the walk returns the element and position where it stopped.

== Panics

The package panics in exactly three situations — all programmer errors
with no sane fallback:

[options="header"]
|===
| Call | Why 

| `NewDllFunc(nil)` | nil equality function, caught at construction time 
| Insert-family on a nil `*Dll` | a nil list cannot store an element 
| Insert-family on a zero-value list | no equality function; the message names the constructors 
|===

The insert family is `InsertBeforeHead`, `Push`, `AppendAtTail`,
`Enqueue`, and `Concat` (which appends).  Everything else tolerates a nil
list and the zero value as an empty list.
