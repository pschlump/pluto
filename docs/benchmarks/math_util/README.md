# Phase 8 math benchmark record

Recorded 2026-11-22 on Apple M4 Max, darwin/arm64, Go 1.27.0, OpenJDK 11.0.28,
Guava commit `36e3995499d6c3b74b1207d362fa9e19915d2589`. Go ran three 1-second
measurements; JMH 1.37 ran two 1-second warmups and three 1-second measurements,
one fork/thread. Inputs are fixed non-trivial signed 64-bit boundaries; the
prime is `2^63-25`.

| Workload | Pluto Go | Guava JMH |
|---|---:|---:|
| Half-even divide | 3.984–4.015 ns; 0 allocs | 782.434M ops/s ± 76.631M |
| Half-even log10 | 83.47–84.13 ns; 160 B, 5 allocs | 426.631M ops/s ± 15.926M |
| Half-even sqrt | 2.402–2.467 ns; 0 allocs | 783.048M ops/s ± 28.969M |
| Deterministic primality | 43.63–44.12 µs; 0 allocs | 8,749.352 ops/s ± 581.679 |
| Binomial(30,15) | 258.7–259.5 ns; 56 B, 2 allocs | 782.063M ops/s ± 88.575M |

The exact-midpoint log10 implementation deliberately allocates big-integer
storage. Guava uses algorithm-specific tables and the JVM may optimize fixed
inputs differently; these are matched operation records, not general speed
claims or ratios.

Raw files are `go-matched.txt`, `jmh-matched.json`, and `normalized.json`.
`math_util/testdata/guava_math.json` is generated by `MathOracle` from the pinned
source and covers checked/saturating arithmetic, conversions, all rounding modes,
number theory, and overflow traces.
