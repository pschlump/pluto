# rb_tree notes

`RbTree[T any]` is a leaner API than the other trees: no `Index`, `Reverse`, `Walk*`, `Front`, or set operations — just insert/search/delete/min/max/head-tail removal, `Dump` (color-aware format: `RbTree (empty)` or a header plus `data(R|B)` lines), and `All`/`Backward`.  Nodes carry parent pointers, so the iterators are successor/predecessor walks with O(1) extra space (`successor`/`predecessor` in iter.go).  Insert/delete are CLRS-style: red new node + `insertFixup`, `transplant` + `deleteFixup(x, xParent)` (the parent is passed separately because x may be nil).  `DeleteAtHead`/`DeleteAtTail` call `deleteNode(minNode/maxNode(root))` directly — one descent, no re-search through `Delete`.  `checkInvariants` in rb_tree_test.go verifies all five red-black properties plus parent-pointer integrity — call it after any structural change.

The phase-2 set-convenience capabilities live in `capabilities.go`: `Contains`/`ContainsSlice`/`ContainsAny`, `InsertSlice`/`InsertIter`/`DeleteSlice`/`DeleteFunc`, `Slice`/`String`/`StringFunc`/`Equal`/`Clone`. The shared `insertContractCheck(caller)` + `insertAll` pair carries the insert panic contract to the batch inserters (panic only when a batch would store; empty batch tolerated) — messages mirror Insert's own ("rb_tree: %s called on a nil tree"). `Slice` collects `All()` (the O(1)-space successor walk) — in-order *is* ascending, no sorting (unlike the hash families' sorted-format rule). `Equal` is Len + one-way Search over the slice. `DeleteFunc` is collect-then-delete. `Clone` is the recursive structural copy including `red` and rebuilt `parent` links (children copied with the duplicate as their parent). Batch mutators return "receiver changed"; read side total over nil/zero-value. The twin `rb_tree_ts/capabilities.go` mirrors method-for-method: `Slice` = the twin's `toSlice` snapshot under the read lock, batch mutators hold the write lock once (atomic), `DeleteFunc` predicate runs unlocked over the snapshot, `Equal` never holds two locks (snapshot one side, probe the other). `capabilities_test.go` mirrors the plain suite plus the concurrency block; the mass-delete and randomized-model tests call `checkInvariants` (via `capKey` zero-padded keys so the typed checker applies).

`rb_tree_ts` adds the `lock sync.RWMutex`; its unexported helpers (rotations, fixups, `findNode`, `deleteNode`, `nodeDepth`) are the lock-free internals that the locked public methods call.  Its snapshot (`toSlice`) walks the parent pointers under the read lock.  Never call one locked public method from inside another (see `Dump`, which uses the lock-free `nodeDepth` instead of calling `Depth`).
