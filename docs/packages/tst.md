# tst notes

`Tst[T any]` is Sedgwick's §5.5 TST — the memory-efficient sibling of `trie`: one node per byte (`c byte; left, mid, right`), three pointers, no 256-way arrays. Identical API surface to `trie` with one contract difference: the **empty key is rejected** (`Insert("")` returns false, Search not-found — algs4 throws; pluto reports). `Delete` clears the value and prunes childless value-less branches (algs4's TST has no delete); a full drain restores `root == nil`. Key reconstruction must use `string([]byte{x.c})` — `string(x.c)` converts the byte to a rune and corrupts non-ASCII keys (the UTF-8 test guards this). Same constructor-free contract as `trie` (zero value usable, single nil-`Insert` panic).

The phase-3 set-convenience capabilities live in `capabilities.go`, mirroring `trie`'s method for method: `Keys` (literally `KeysWithPrefix("")`), `Values` (value side of `All`, index-aligned with `Keys`), `String`/`StringFunc` (keys only, bracket-space format, in-order walk = ascending — no sorting), `Equal` (**keys only** — same no-boxing rule; cross-family note: tst rejects the empty key that trie stores at the root, so trie-vs-tst Equal is meaningful only for non-empty key sets), `Clone` (recursive node-by-node deep copy of `c`/links/value/`hasValue`), `ContainsSlice`/`ContainsAny`, `DeleteSlice`. The empty key keeps its rejection through the new methods (never contained, never deleted). No batch insert; `Contains` already existed. All total functions — none panics.

`tst_ts` is the twin, same pattern as `trie_ts` (snapshot iterators, real `Lock`/`Unlock` + `Nl*`, race tests `TestTstConcurrent`/`TestConcurrentCompound` plus the capabilities concurrency block; main source file keeps the plain package's name, `tst_ts/tst.go`, per house convention). The twin mirrors the capability menu with the twin lock discipline: snapshot reads, compute-after-snapshot `String`/`StringFunc`/`Equal` (format callback runs unlocked; `Equal` never holds two locks), one-lock batches with atomic `DeleteSlice`.
