# avl_tree notes

`AvlTree[T any]` mirrors the binary_tree contract but every node caches its subtree height (`Depth` is O(1)), and `rebalanceNode`/`rotateLeft`/`rotateRight` restore the AVL invariant on the way back up from each insert/delete (delete's two-children case unlinks the in-order successor via `removeMin`). Unlike binary_tree: `Insert` returns bool (added vs duplicate-replaced), there is no `DeleteMatch`/`WalkFunc`, `Len` aliases `Length`, and there are set operations — `Copy`/`Union`/`Minus`/`Intersect`/`SymmetricDifference` snapshot their operands before rebuilding the destination (so a source may alias the destination) and a zero-value destination adopts an operand's comparison function (`SymmetricDifference` is the merge-walk over the two sorted operand slices, skipping elements present in both; commutes, and equals `Minus(Union, Intersect)`). `Floor(key)`/`Ceil(key)` are the point-query companions of `FindMin`/`FindMax` — a descent that remembers the last candidate on the appropriate side, returning `(T, bool)` like skip_list's. `validateAVLNode` in avl_more_test.go checks the BST order, AVL balance, and cached-height invariants — call it after any structural change.

The phase-2 set-convenience capabilities live in `capabilities.go`: `Contains`/`ContainsSlice`/`ContainsAny`, `InsertSlice`/`InsertIter`/`DeleteSlice`/`DeleteFunc`, `Slice`/`String`/`StringFunc`/`Equal`/`Clone`. The shared `insertContractCheck(caller)` + `insertAll` pair carries the insert panic contract to the batch inserters (panic only when a batch would store; empty batch tolerated). `Slice` is the iterative-stack in-order walk — unlike the hash families there is no sorted-format rule: in-order *is* ascending, so `String`/`StringFunc` need no sorting and `Equal` is Len + one-way Search over the slice. `DeleteFunc` is collect-then-delete (snapshot first, delete after). `Clone` is the recursive structural copy including each node's cached `height` — the returning form; destination-form `Copy(yy)` is unchanged. Batch mutators return "receiver changed". Read side total over nil/zero-value as everywhere. The twin `avl_tree_ts/capabilities.go` mirrors method-for-method: `Slice` = `snapshotInOrder`-style snapshot under the read lock, batch inserters hold the write lock once for the whole batch (atomic for pollers), `DeleteFunc` runs the predicate unlocked over the snapshot, `Equal` never holds two locks (snapshot one side, probe the other), `SymmetricDifference` snapshots both operands (with comparators) then merges under the write lock, `Floor`/`Ceil` under the read lock. `capabilities_test.go` mirrors the plain suite plus the concurrency block, and the avl-only `TestCapabilitiesSymmetricDifferenceModel` (seed 7: reference vs map model, commutativity, `Minus(Union, Intersect)` equivalence, alias safety) and `TestCapabilitiesFloorCeil` (linear-scan oracle over `Slice`).

`avl_tree_ts` adds the `lock sync.RWMutex` and `nl*` lock-free internals to the same structure; its `snapshot()` returns both the in-order data and the tree's comparison function read under the read lock, which is how the set operations adopt a comparator without racing with concurrent adoption on the operand.
