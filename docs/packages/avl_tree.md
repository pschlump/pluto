# avl_tree notes

`AvlTree[T any]` mirrors the binary_tree contract but every node caches its subtree height (`Depth` is O(1)), and `rebalanceNode`/`rotateLeft`/`rotateRight` restore the AVL invariant on the way back up from each insert/delete (delete's two-children case unlinks the in-order successor via `removeMin`). Unlike binary_tree: `Insert` returns bool (added vs duplicate-replaced), there is no `DeleteMatch`/`WalkFunc`, `Len` aliases `Length`, and there are set operations — `Copy`/`Union`/`Minus`/`Intersect`/`SymmetricDifference` snapshot their operands before rebuilding the destination (so a source may alias the destination; see *Set operations: linear merge + balanced build* below for the algorithm) and a zero-value destination adopts an operand's comparison function (`SymmetricDifference` is the merge-walk over the two sorted operand slices, skipping elements present in both; commutes, and equals `Minus(Union, Intersect)`). `Floor(key)`/`Ceil(key)` are the point-query companions of `FindMin`/`FindMax` — a descent that remembers the last candidate on the appropriate side, returning `(T, bool)` like skip_list's. `validateAVLNode` in avl_more_test.go checks the BST order, AVL balance, and cached-height invariants — call it after any structural change.

The phase-2 set-convenience capabilities live in `capabilities.go`: `Contains`/`ContainsSlice`/`ContainsAny`, `InsertSlice`/`InsertIter`/`DeleteSlice`/`DeleteFunc`, `Slice`/`String`/`StringFunc`/`Equal`/`Clone`. The shared `insertContractCheck(caller)` + `insertAll` pair carries the insert panic contract to the batch inserters (panic only when a batch would store; empty batch tolerated). `Slice` is the iterative-stack in-order walk — unlike the hash families there is no sorted-format rule: in-order *is* ascending, so `String`/`StringFunc` need no sorting and `Equal` is Len + one-way Search over the slice. `DeleteFunc` is collect-then-delete (snapshot first, delete after). `Clone` is the recursive structural copy including each node's cached `height` — the returning form; destination-form `Copy(yy)` is unchanged. Batch mutators return "receiver changed". Read side total over nil/zero-value as everywhere. The twin `avl_tree_ts/capabilities.go` mirrors method-for-method: `Slice` = `snapshotInOrder`-style snapshot under the read lock, batch inserters hold the write lock once for the whole batch (atomic for pollers), `DeleteFunc` runs the predicate unlocked over the snapshot, `Equal` never holds two locks (snapshot one side, probe the other), `SymmetricDifference` snapshots both operands (with comparators) then merges under the write lock, `Floor`/`Ceil` under the read lock. `capabilities_test.go` mirrors the plain suite plus the concurrency block, and the avl-only `TestCapabilitiesSymmetricDifferenceModel` (seed 7: reference vs map model, commutativity, `Minus(Union, Intersect)` equivalence, alias safety) and `TestCapabilitiesFloorCeil` (linear-scan oracle over `Slice`).

`avl_tree_ts` adds the `lock sync.RWMutex` and `nl*` lock-free internals to the same structure; its `snapshot()` returns both the in-order data and the tree's comparison function read under the read lock, which is how the set operations adopt a comparator without racing with concurrent adoption on the operand.



## Phase 3 positioned ranges

`Lower` and `Higher` add strict O(log n) navigation. `RangeOf` performs a
positioned descent followed by an in-order stack walk in O(log n + results), with
open/closed/unbounded bounds and early termination. The `_ts` implementation
collects only matching values under the read lock before iteration.

## Hot paths: allocation-free replace, iterative descents, Upsert/Remove

A performance pass (the `table` package had bypassed avl_tree with a private tree) fixed four costs, in both packages:

- **Allocate only at a nil link.** `upsert`/`nlUpsert` (behind `Insert` and the new `Upsert`) allocate the node only when the descent reaches the nil link where it belongs. A replace (`Insert` or `Upsert` of an equal element) writes `cur.data` in place and allocates nothing — the old code built the node before searching, so every replace cost one 32-byte allocation. `TestAllocations` pins 0 allocs/op for replace.
- **Iterative descents with a fixed path.** Insert and delete are loops that record the `**AvlTreeElement` links they pass in a `[maxAvlHeight]` array (`maxAvlHeight = 92`: a minimal AVL tree of height h has F(h+2)−1 nodes and F(94) > 2^64, so no tree that fits in memory is taller than 91). `retrace` then rebalances bottom-up and **stops at the first subtree whose height came out unchanged** — everything above it has unchanged child heights, so the remaining `rebalanceNode` calls would be no-ops; shapes are identical to the old recursive form. The old recursive closures did not actually heap-allocate (escape analysis kept them on the stack); the gain there is fewer indirect calls plus the early stop.
- **The delete splice trap.** In the two-children case the successor's descent extends the same path, and the entry recorded just below the target is `&target.right` — a field of the node being unlinked. After the splice it must be rewritten to `&m.right` (the successor's field) or the retrace rebalances a detached node. `TestAvlSequentialShapes` (repeatedly removing the root) exercises it.
- **No recursive closures in hot paths.** `All`/`Backward` are one-line closures calling the `ascend`/`descend` methods, which keep pending nodes in a fixed `[maxAvlHeight]` stack. `All` stays inlinable, `yield` does not escape, and a full or early-stopped `for range tree.All()` allocates nothing (was 2 allocs). What matters is that `All` stays inlinable at the range site so its closure and `yield` do not escape — measured: putting the same fixed-stack loop directly inside the closure literal also gives 0 allocs (Go 1.27), so the method split is for sharing (`Index` reuses `ascend`), not a requirement; a recursive closure `walk` inside it is what allocated (2 allocs/range). The `Walk*` functions (`walkInOrder`/`walkPreOrder`/`walkPostOrder` with `walkFrame{n, depth}` stacks; post-order's depth is the stack height after the pop), `Index` (early-stopping in-order walk), `Reverse`, `RangeOf`, `toSlice`/`Slice`/the twin's `snapshot` (`appendInOrder`/`nlAppendInOrder` into a pre-sized slice) use the same fixed stacks. `Clone` uses the plain recursive generic function `cloneNode`. Only the debugging `Dump` keeps a recursive closure.
- **Upsert / Remove.** `Upsert(item T) (old T, replaced bool)` and `Remove(find T) (removed T, found bool)` are the one-descent forms of Search-then-Insert and Search-then-Delete, in both packages with identical signatures. `Upsert` follows Insert's panic contract (nil tree, zero-value tree, with messages naming `Upsert` and the constructors); `Remove` follows Delete's tolerance (nil/zero value → not-found). In the twin both take the write lock once, which makes them the atomic replacements of the racy two-call patterns. `Insert`/`Delete` are now thin wrappers over `upsert`/`remove` (`nlUpsert`/`nlRemove` in the twin).

Tests: `upsert_test.go` in each package — a fixed-seed (42) model test interleaving Insert/Upsert/Delete/Remove/DeleteAtHead/DeleteAtTail with `validateAVLNode` after every op (the twin runs the same ops against the plain package for parity), all/backward/walk order plus early stop at every position against recursive reference walks, Index at every position, allocation pins, and a concurrent Upsert/Remove race test in the twin. Benchmarks live in `perf_bench_test.go` (`BenchmarkPerf*`); `BenchmarkPerfUpsert`/`BenchmarkPerfRemove` sit in `upsert_test.go` because the older code has no such methods to A/B against.

## Set operations: linear merge + balanced build

`Copy`/`Union`/`Minus`/`Intersect`/`SymmetricDifference` (both packages; helpers in `setop.go`) used to rebuild the destination with one `Insert` per element — O((n+m) log(n+m)), one allocation per element, plus rotations. Both snapshots are already in order, so now:

1. **Snapshot** the operands exactly as before (`toSlice`; the twin's `snapshot()` under each operand's own read lock, then the destination's write lock — lock discipline unchanged), empty the destination, adopt a comparator exactly as before.
2. **Order check.** The snapshots are ascending under the *operands'* comparators; the result must be ordered by the *destination's*. Those normally agree, but not always: a destination with its own different comparator, a `Reverse()`d operand (its in-order sequence is descending), or an operand ordered by a finer comparator (adjacent elements equal under the destination's). Function values cannot be compared, so `strictlyAscending` checks each snapshot (n−1 comparisons). A snapshot that is not *strictly* ascending (non-strict lets the finer-comparator duplicates through — mutation-tested) sends the operation to `setOpInsert`, the old insert-per-element code verbatim, so results are identical to the old implementation in every case. SymmetricDifference checks the k-element merge OUTPUT instead of the two inputs: the old algorithm was this same merge loop inserting each emitted element for any input order, so the emitted sequence is identical either way — strictly ascending output means the insert-built tree holds exactly those elements; otherwise that sequence is inserted one by one. This keeps the identical-operands case (k = 0) from paying 2n comparisons (an A/B first showed it 26–45% slower than the old code there).
3. **Merge** (O(n+m)). Equal elements: **Union keeps zz's** (the old code inserted yy then zz, and a duplicate insert replaces), **Intersect keeps yy's** (the old code inserted yy's element when zz contained it), Minus keeps yy's, SymmetricDifference drops both, Copy keeps yy's. `TestSetOpEqualElementKept` pins these with the `N` satellite field and passed against the old code before the change. Two shapes, chosen by A/B measurement: Minus/Intersect use `filterInPlace`, compacting the result into the private yy snapshot (the write index never passes the read index) and then `buildFrom` copies it into an exact slab; Union/SymmetricDifference, whose result can be longer than either snapshot, use `mergeInto` twice — a counting pass (`dst == nil`), then one exact slab, then a pass writing straight into the slab's data fields (an extra comparison pass instead of an n+m scratch slice: same time, ~1/6 fewer bytes; doing the same count-then-write for Minus/Intersect cost them 3–16% and was rejected). Copy snapshots yy straight into the result's slab (`nodeSnapshot`; in the twin under yy's read lock), checks it in place and links it — the snapshot *is* the new tree's storage (1 allocation instead of 2, 14–26% faster).
4. **Build** (`linkBalanced`, O(n)). The slab's data fields are already in order; the middle element of every index range is that range's root (a plain recursive generic function over sub-slices, depth = height — not a closure), each node's height = max(children)+1. Sibling sizes differ by at most one, so the result is a valid AVL tree of minimum height bits.Len(k), no rotations.

**Memory tradeoff (the table/tree_index.go choice).** The slab is one allocation for the whole result: a node later unlinked by `Delete`/`Remove` stays allocated until every node of its slab is unreachable (or the tree is truncated/rebuilt) — worst case the result's size at build time × node size. To keep that retained memory inert, `remove`/`nlRemove` now **zero the unlinked node** (`*target = AvlTreeElement[T]{}`), so a slab never keeps a deleted element's referents alive; `TestSetOpSlabDeleteReleasesElement` checks it with a `weak.Pointer`. Nodes inserted later are allocated individually as always. The old `Front` iterator already documents that mutation invalidates it, so zeroing is not observable through the API.

**Shape.** Results are now perfectly balanced instead of insert-built. No test or doc pinned a set-operation result's shape (`Depth` is still O(1) from cached heights, now minimal); nothing needed adjusting.

**Tests** (`setop_test.go`): the old implementations kept as an oracle; fixed-seed differential over sizes 0..200 plus 1000/4097/20000 at three overlap levels, comparing elements *with satellite data*, `validateAVLNode`, Len, depth == bits.Len(Len), then interleaved Insert/Delete against the oracle and a validated drain; aliasing (`tt.Op(tt, o)`, `tt.Op(o, tt)`, `tt.Op(tt, tt)`); every nil/zero/empty/full combination of destination and operands with adoption; the three foreign-order cases; panic-free contract; minimum-height shape. The twin: the same pin, parity with the plain package (elements, Len, Depth), aliasing/operand matrix, and a `-race` test with concurrent writers to the operands and destinations used as each other's operands. Benchmarks: `setop_bench_test.go` (`BenchmarkSetOp`: each op × n ∈ {64, 100k} × overlap ∈ {0, 50, 100}%).
