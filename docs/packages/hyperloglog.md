# hyperloglog notes

`hyperloglog.Hll` is the Redis PFADD/PFCOUNT/PFMERGE sketch (request `note/04-hyperloglog.md`): 2^14 = 16384 six-bit registers densely packed in a `[12288]byte` (the Redis dense layout — register i occupies bits [6i, 6i+6), LSB-first, 4 registers per 3 bytes). **Non-generic** (elements are `[]byte`, hashed and forgotten — the union_find/suffix_array precedent) and **constructor-free** (the hash is fixed, so nothing to store; `NewHll` is note-parity convenience). Panics: exactly 2 — `Add` on nil, `Merge` into nil that would fold a non-empty operand (merging only empty operands is tolerated); corrupt serialized data is errors (`ErrBadLength`, `ErrBadRegister`, via errors.Is) — a 6-bit packing holds 0–63 but `HllFromBytes` rejects ranks above `rankMax` = 51, the most any 64-bit hash at p=14 can produce.

Three contracts to preserve:

- **The hash is frozen.** xxHash64, seed 0, implemented inline (`hash.go`) — NOT Redis's MurmurHash64A (optional per the note). The serialized form is versionless exactly because hash/precision/packing are constants; changing any breaks every persisted Hll. `TestXxh64Vectors` pins the hash against the xxHash reference suite's published sanity vectors (xsum_sanity_check.c), including a seed≠0 variant via `xxh64Seed`.
- **The estimator is LinearCounting + Ertl.** `estimate.go`: LC while zeros > 0 and estimate ≤ 2.5m; above it Ertl's σ/τ corrected estimator (arXiv:1702.01284) — what current Redis ships; attribution comment kept. Chosen over HLL++ tables (no tables, no boundary jumps) and the LogLogBeta polynomial (Redis's own successor); σ converges to LC at low load (they agree digit-for-digit — probed). The register accessors must match the histogram's 3-byte group decode — `TestRegisterPacking` cross-checks them, and the fb > 2 spill condition is what keeps register 16383 in bounds (the last register ends exactly on the array end; the C macro reads one past into the sds terminator, which Go cannot do — don't "simplify" the boundary).
- **The count cache is atomic so the twin can share it.** `cached atomic.Uint64` + `valid atomic.Bool` in the plain struct: Add/Merge/Reset invalidate after their register writes (order matters), Count populates under `valid` — so `hyperloglog_ts.Count` can take its **read** lock while remaining race-free. Never copy an Hll value (copylocks); always `*Hll`. `Clone`/`MergeMax`/`Invalidate` are the exported surface the twin composes (point-in-time snapshot / lock-free union core / cache drop) — plain `Merge` is built on `MergeMax` too.

Accuracy reality (documented in README/tests): below ~2.5m the noise is the register-collision floor — sd ≈ n/√(2m) ≈ **0.55% relative regardless of n** (the multinomial constraint cancels the naive occupancy variance; do not "fix" the sweep when it looks too good) — and the only bias is the collision count n²/2m (−0.3% at n=100, fundamental). Above it, 1.04/√m ≈ 0.81%. `TestCardinalitySweep` gates the note's criteria: mean |err| < 1.5% at 1k–10M (observed 0.4–0.7%), < 0.5% below ~1000; the 10M point skips under `-short`. `TestMergeSplitExact` asserts merge-of-partition is **bit-identical** to all-in-one (max over a partition = global max — exact, not tolerance). Benchmarks: Add ~127M ops/s for 8-byte keys (note's target ≥10M), uncached Count ~11µs, cached ~1ns, Merge ~16µs.

`hyperloglog_ts` embeds the plain sketch **by pointer** (value embedding trips copylocks on the atomics), zero value still usable — inner appears on first write, reads ride the plain nil tolerance, `Bytes` on a never-written zero value returns the all-zero form for contract consistency. Its `Merge` clones each operand under the operand's own read lock (released) before the destination write lock — the avl_tree_ts set-op pattern (no nested locks; opposite-way merges deadlock-free; aliasing operands no-op; a concurrently-mutated operand merges as its snapshot). `Nl*` set: `NlAdd`/`NlCount`/`NlIsEmpty`/`NlReset`/`NlBytes`/`NlMerge` (`NlMerge` takes no operand locks — operands must be quiet). Race coverage: `TestConcurrentAddCount` (read-lock Count vs write Adds — the atomic-cache pairing), `TestConcurrentMerge` (all-direction merges + concurrent writers), `TestLockNlCompound`, `TestConcurrentReset`.
