# queue notes

`Queue[T any]` is the constraint-free container: no ordering, no equality, no constructors — the zero value is fully usable (including `Push`), so the only panic is `Push`/`Enqueue` on a nil queue.  Slice-backed with a moving window: `popHead` zeroes the vacated slot, advances `data = data[1:]`, and nils the slice on full drain (tested by `TestPopReleasesBackingArray`); long grow/drain cycles reallocate — point callers needing stable O(1) memory at `queue_dll` (or `dll`'s `Enqueue`/`Pop`).  `Dequeue`/`Peek` return `(T, error)`.  Error API: `ErrEmptyQueue`.

`queue_ts` adds the `lock sync.RWMutex` and `noLock*` internals; its `All`/`Backward` copy the slice under the read lock when called.

**Phase-4 capabilities** (`capabilities.go`, plan §4.4 minimal sequence menu): `Slice` (FIFO, head first = `All`'s order; nil→nil, empty→empty-non-nil, always a copy), `String`/`StringFunc` (`[a b c]` bracket-join, `fmt.Sprint` per element, nil format → `[]`), `Equal` and `Clone`.  `Equal` is the **order-sensitive** Equal — the one pluto family where `[a b] ≠ [b a]` (set-shaped packages compare membership).  In this constraint-free package it compares elements with Go's `==` via interface conversion (`any(a) != any(b)`) — the approved phase-4 decision; a non-comparable element type panics with the runtime comparison panic **only when two elements are actually compared** (the length check runs first, so different lengths and nil/empty never touch an element).  No `Contains`/batch insert/predicate delete — deliberately: O(n) membership over a sequence is a footgun.  The `queue_ts` twin mirrors the menu: `Slice` snapshots under the read lock, `Clone` takes the write lock, `Equal` snapshots each side **sequentially** (one lock at a time — comparing two queues from concurrent goroutines cannot deadlock), `StringFunc`'s format callback runs outside the lock.  Tests: `capabilities_test.go` (800-step randomized model vs `[]int`, PCG seed (1,42), full surface checked every 37 steps, rotation-must-not-be-equal finish) and `capabilities_example_test.go`; the twin adds `TestCapabilitiesConcurrent` (8-goroutine hammer) + `TestCapabilitiesEqualNoDeadlock`.
