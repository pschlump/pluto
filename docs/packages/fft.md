# fft notes

`fft` is Sedgewick §9's `FFT.java` as stateless functions over `[]complex128` — the `geo` pure-function precedent, no state, no constructor, no `_ts` twin (concurrent use is free). `FFT` is the recursive radix-2 Cooley–Tukey core (`fftRec`): split even/odd indices, transform each half, combine with twiddle factors `w_n^k = e^{-2πik/n}` computed per k from cos/sin (the reference's per-k `Math.cos/sin`, not a recurrence — slower per point, bit-faithful to the reference). `fftRec` keeps the reference's single-scratch-buffer trick — the even half's slice is REFILLED with the odd half after the even transform returns — which is safe here because the n==1 base case returns a fresh one-element slice, so no caller holds the reused buffer (if the base case ever returned `x` itself, the trick would corrupt the even result). `IFFT` is the reference construction conjugate → forward FFT → conjugate → scale 1/n, sharing the single forward core. Length contract: `FFT`/`IFFT`/`CConvolve` require a power-of-2 length and panic naming the FUNCTION and the length (per-function messages — the algs4 IllegalArgumentException contract, house message style); nil/empty input returns nil (tolerated, never panics); inputs are never mutated (every entry copies before recursing).

`Convolve` deliberately deviates from the reference and the deviation is a documented contract: algs4's `convolve` demands two EQUAL power-of-2 lengths, always pads to exactly 2×, and returns the padded length with trailing zeros — correct only when the caller pre-arranges lengths (its own test uses equal 2^k arrays). pluto's `Convolve` takes any two lengths, pads both to the smallest power of 2 ≥ `n1+n2-1` (at that padding circular convolution cannot wrap — the wrap terms need k ≥ pad−(n2−1) and there are no nonzero a[k] up there), and returns the TRIMMED `n1+n2-1` slice — the polynomial product always (identity: `Convolve(x, [1]) == x`). The padding loop `for pad < n1+n2-1 { pad *= 2 }` starting from 1 yields pad ≥ L, exactly the no-wrap condition; a `pad <= ...` would loop forever at exact powers of two, and 2·max is over-padding.

Oracles: the definitional O(n²) DFT (`dftNaive`, `X[k] = Σ x[t] e^{-2πikt/n}`) over 200 fixed-seed random integer signals (integers keep |FFT−DFT| ~1e-12; tolerance 1e-9); IFFT round-trip `IFFT(FFT(x)) == x` (the reference's own main test); naive circular and linear convolution sums; structural known answers (identity at n=1, constant → [nc,0,…], impulse → all ones, pure tone at bin k0 → n at k0 and 0 elsewhere). TRAP in the linear-convolution oracle: the inner loop's lower bound must be `max(0, t−n2+1)` — writing the bound as a `for`-clause conjunction (`k <= t0 && k < n1 && t0-k < n2`) makes Go evaluate the k=0 case first and ABORT the whole loop whenever `t0 ≥ n2`, silently producing a zero tail that indicts the (correct) implementation. Benchmarks are measured before documented (the item-17 lesson): FFT 67µs @1024 / 1.43ms @16384; naive DFT at n=256 costs 486µs — the n log n vs n² gap in one comparison; the recursion's ~2.25 allocs/point (2302 at n=1024) is the faithful algs4 shape (every level allocates its halves and output).
