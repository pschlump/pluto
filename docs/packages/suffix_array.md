# suffix_array notes

`SuffixArray` is Sedgwick's §6.3 suffix array — the second non-generic structure (over `string`, like `union_find` over indices). `NewSuffixArray(s)` builds by **prefix doubling** (sort indices by `(rank[i], rank[i+k])` pairs, doubling k — O(n log² n) with `sort.Slice`) and the LCP table by **Kasai's algorithm** O(n); the struct keeps `text`, `suffixes` (sorted order), `lcp` (lcp[0] == 0 by definition), and `rank` (inverse permutation). All queries are O(1) positional with out-of-range reporting `(0, false)` — the package has **no panics at all**, and nil receivers report 0/false/"". `LongestRepeatedSubstring` folds in the algs4 LRS client (max over lcp, ties first in sorted order), and `LCS(s, t)` in `lcs.go` folds in the algs4 `LongestCommonSubstring` client: one suffix array over `s + sep + t` where `sep` is the first byte absent from both inputs (a suffix of s must not share a prefix running across the join — hence the separator), then the max LCP over ADJACENT sorted suffixes starting in opposite halves (the longest common substring always ends up adjacent in sorted order); ties first in sorted order, `("", true)` for a genuine empty answer, `("", false)` only in the pathological all-256-bytes-in-use case. **Immutable after construction → no `suffix_array_ts` twin** (the `queue_dll` documented-exception precedent); concurrent reads are safe, covered by `TestConcurrentReads` under `-race`. `thorough_test.go` cross-checks against a `naiveSuffixArray` reference (sort all suffixes with `strings.Compare`, brute-force LCP) at fixed seed 42 over a 3-letter alphabet (long repeats = worst case); `checkInvariants` verifies the permutation, sorted order, brute-force LCP, and Rank/Index mutual inversion.
