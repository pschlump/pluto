# bloom notes

`bloom.Bloom` is the classic Bloom filter (Bloom 1970) — the pluto-standard port of the author's 2016 `bloom-filter` library (`../bloom-filter`): a fixed-shape bit array (`[]uint64`, m bits, k probes per element) approximating set membership with one-sided error. **Non-generic** (`[]byte` elements hashed and forgotten — the hyperloglog/union_find/suffix_array precedent) and **shape-required**: unlike constructor-free hyperloglog, the zero value is readable (MayContain false, counters 0, Bytes nil) but NOT writable — `Add`/`TestAndSet` on nil or zero-value panic naming the constructors (the lru capacity precedent: no shape, no sane answer). Constructors: `NewBloom(n, p)` computes the classic optima m = ceil(−n·ln p/(ln 2)²) (maxBits = 2^32 cap — the two 32-bit hashes cannot address more), k = round(ln 2·m/n) clamped to [1, maxHashes=64]; `NewBloomBits(m, k)` takes the shape directly (m prime-friendly — arbitrary, not power-of-two; the 2016 library's documented preference).

Three contracts to preserve:

- **The hash pair is frozen and fixed to the C originals.** h1 = MurmurHash2 (Austin Appleby's reference, seed 552211 = the 2016 constant), h2 = SuperFastHash (Paul Hsieh, published form with the `<<25` avalanche and **signed-char tail bytes** — sign-extended in Go via `uint32(int32(int8(b)))`). The 2016 Go port had a silent bug: `uint32(data[1] << 8)` shifts *inside the byte type*, so every odd byte read as zero (both hashes crippled; its test vectors pinned the broken values — do NOT reuse them). The fixed ports are pinned by `vectors_test.go` — 37 frozen vectors generated by **compiling the two C sources with clang** (the geo oracle pattern; the full 269-vector corpus was checked at generation) — plus a cross-check against structurally different second ports (`refMurmur2`/`refSuperFastHash`) over 20k random inputs. Probes are **Kirsch–Mitzenmacher** (h1 + i·h2) mod m with a degenerate-step guard (h2 ≡ 0 mod m → step 1; always triggered by the empty element, whose SuperFastHash is 0 — `TestProbesInRange` asserts the consecutive-walk). Add/MayContain derive identical positions → **false negatives are structurally impossible**.
- **Exact return-value laws** (gated in `TestRandomizedModel`, seed 42): `Add` returns exactly the inverse of the pre-call `MayContain` (duplicate Add always false; fresh Add false only on a false-positive pre-state); `TestAndSet` returns the pre-add answer (the 2016 semantics); `Added()` counts every Add/TestAndSet call exactly (duplicates included — a filter cannot tell); `set`/`Count`/`Saturation` are O(1) via the incrementally maintained set-bit counter (Count = ML estimate −(m/k)·ln(1−X/m), reporting m at full saturation — documented stand-in). Merge is the bitwise OR with strict shape match (both m and k; nil/empty operands and self-merges skipped; `added` sums — self-merge must NOT double it); merging a partition is **bit-identical** to all-in-one (`TestMergeSplitExact`).
- **The serialized form is versionless but shape-carrying**: 24-byte header (m, k, added — 8 bytes each LE) + bit words. Errors via errors.Is: `ErrBadLength` (length/shape mismatch, m out of range), `ErrBadHashes` (k outside [1,64]), `ErrBadBits` (a set bit at or above m — the padding no Add can touch; the ErrBadRegister analog). Changing either hash or hashSeed breaks every persisted filter.

Accuracy reality (documented + gated): false positives ≈ (1−e^(−kn/m))^k, measured 0.5×–1.6× of p at design load across (1k,10%)…(100k,1%); saturation ≈ 0.5 at design load (optimal k). Benchmarks: Add ≈ 24 ns/op zero-alloc for 16-byte elements (probe buffer stack-allocated — keep it that way), MayContain 23/34 ns hit/miss, each hash ≈ 3.4 ns.

`bloom_ts` wraps `*bloom.Bloom` behind one RWMutex (the lfu_ts/lru_ts composition pattern; **not** lazy-`ensure()` like constructor-free hyperloglog_ts — the zero value cannot fabricate a shape). Nil guards before lock acquisition; write panics carry `bloom_ts:` prefixes naming the constructors; a Merge shape mismatch panics with the plain core's message. `Merge` snapshots each operand (Clone under the operand's own read lock, released) before the destination's write lock — the hyperloglog_ts pattern (no nested locks, opposite-way merges deadlock-free, aliasing operands skipped). Real `Lock`/`Unlock` + `Nl*` mirror (`NlAdd`/`NlMayContain`/`NlTestAndSet`/`NlCount`/`NlAdded`/`NlSaturation`/`NlIsEmpty`/`NlReset`/`NlBytes`/`NlMerge` — write-form Nl methods carry the zero-value panic); the canonical compound is batch insert-if-absent under one `NlSaturation` view. Race trio in thorough_test.go: `TestConcurrent` (exact `Added` total + no false negatives after the storm), `TestConcurrentMerge`, `TestConcurrentCompound`. Plain bloom keeps no-op `Lock`/`Unlock`.
