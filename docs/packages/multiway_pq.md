# multiway_pq notes

`multiway_pq.DHeap[T any]` is the d-ary min-heap (backlog §3.10; algs4 §9 `MultiwayMinPQ`) — `heap`'s ENTIRE surface ported to d-ary addressing, file-for-file: `multiway_pq.go` (all methods), `iter.go` (`All`), `json.go` (`MarshalJSON`/`UnmarshalJSON` — same contracts, but unmarshal rebuilds via `AppendHeap` + the bottom-up Heapify sweep in O(n) instead of heap's one-by-one Push O(n log n)). Struct gains `d int`; `D()` exposes it (returns 2 for nil/zero-value — the tolerated fallback). Addressing: children `d*i+1 .. d*i+d`, parent `(j-1)/d`; `up` one compare per level (O(log_d n)), `down` finds the SMALLEST of the d children per level (O(d·log_d n)), `Heapify` rebuild loop runs `i = (Len()-2)/D()` down to 0 (the binary `Len()/2-1` generalized — for d≥3 `(0-2)/d` truncates to 0, a harmless Heapify(0,0) on an empty heap). Constructors `NewDHeap[T cmp.Ordered](d)` / `NewDHeapFunc(d, fx)`; panic contract = heap's 3 **plus `d < 2`** = exactly 4 (`multiway_pq:`-prefixed). Memory behavior identical (zero the slot, nil the slice on full drain). No-op `Lock`/`Unlock` kept — a `d_heap_ts` twin is backlog-listed possible later work; shared callers use `heap_ts` today.

**The mirror-oracle corollary** (fib_heap's tie-poisoning lesson, inverted): two heaps over the same multiset must pop the same minimum VALUE even when the minimum is tied — so `TestDHeapRandomizedModel` (PCG 42,7, 4000 steps, parameterized over d ∈ {2,3,4,8,16}) mirrors every Push/Pop/Peek against pluto `heap` **value-for-value** AND against a map multiset model, tracking Delete/Fix through the mirror's `Search`. Values-only comparison is tie-SAFE here (unlike the indexed mirror in fib_heap, where equal minima let two structures pop different INDICES).

**Benchmarks must target worst-case sift paths**: a uniformly random heap slot is a leaf on average (O(1) depth — n·(d-1)/d of nodes are leaves), so a naive `Fix(i%n, smaller)` benchmark measures ~nothing. `BenchmarkFixDecrease` fixes LEAF slots (`i%(n/2)+n/2`, full log_d n rise) and `BenchmarkFixIncrease` fixes the root (full sink) — the first version cycled idx from 0 and came out flat across d, which is how the flaw was caught. Measured (M4 Max, README): decrease-key 12.8→7.7 ns (d=2→16, the log₂→log₁₆ path; d=2 tracks pluto heap's 12.9 validating the port), Pop 71.9→124.3 ns (the d-1 compares per level), bulk build 20.5→10.8 µs (n/d Heapify calls instead of n/2 — bulk build gets FASTER with d). Even at 2²⁰ elements the decrease stays ~flat across sizes: an up-sift touches one cache line per level (M4 Max's 16 MB L2 makes 8 MB resident anyway; probed at 2²³ = 64 MB, still ~14 ns — the leaf walk prefetches perfectly). Practical guidance in README: d=4 the default sweet spot, d=8–16 for decrease-dominated workloads. The Multiway.java k-way merge is a checked EXAMPLE (`Example_mergeKSortedSlices`, satellite `{v, from}` struct) — a `MergeK` helper is Tier-2 item 23's scope, not here.


**Phase-5 capabilities** (`capabilities.go`, plan §4.5 heaps/PQ menu): `Slice`, `String`/`StringFunc`, `Equal`, `Clone` — the exact `heap` exemplar menu (this package is heap's API twin), no membership batches and no predicate delete.  `Slice`/`String` use the **internal breadth-first backing order** (`All`'s order, JSON order) — NOT sorted (`Pop` is the sorted drain); 3,1,2 pushes yield `[1 3 2]` at any d.  `Equal` is **multiset equality** (length check → `slices.SortFunc` copies with the stored comparator → pairwise `cmp==0`), non-destructive, ties safe, through the comparator **never Go's `==`** (non-comparable element types fine) — and deliberately **d-blind**: a d=2 and a d=8 heap over the same multiset are equal (d shapes the tree, not the content; tested).  `Clone` copies the backing array — preserves the heap property exactly, so the exact layout, the pop sequence AND `d` survive (layout asserted via `slices.Equal` of the two Slices, `D()` checked).  All total functions (nil/zero-value → empty; `Clone` of a zero-value → fresh zero-value-shaped, still no `cmp`, like the receiver).  Tests: `capabilities_test.go` (multiset Equal incl. arrangement-difference proof, `[1 1 2]` vs `[1 2 2]`, tie-heavy, cross-d equality, reversed comparator, non-destructive, `checkHeapInvariant` after structural changes, 800-step PCG(1,42) model vs `[]int` with a **Search+Delete arbitrary-member** case beyond heap's mix, every 37 steps full-surface `checkCapModel`, shuffled-rebuild finish) and `capabilities_example_test.go` (5 examples).
