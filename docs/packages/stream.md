# stream notes

`stream.Stream` is the Redis stream (XADD/XRANGE/XREAD/XGROUP lineage, request `note/02-stream.md`, built for the Ultima stream command family): an append-oriented log of `Entry{ID, Fields [][2]string}` (ordered pairs, **duplicates allowed**, copied on Add) keyed by `ID{Ms, Seq uint64}`. **Constructor-free like the tries** — ordering is inherent in the ID type (`CompareID`), zero value ready to use, exactly two panics (`Add` and `CreateGroup` on a nil stream, messages naming the method); data rules are errors (`ErrInvalidID`, `ErrIDTooSmall`, `ErrIDExhausted`, `ErrGroupExists`, via errors.Is). Entry IDs **strictly increase**: `Add` resolves `Seq == AutoSeq` (== `math.MaxUint64`, the Redis sentinel) to last.Seq+1 on the same ms / 0 on a later ms, then requires > last — so `0-0` is never a valid entry (the MinID range sentinel), `0-1` is the legal first entry, and `MaxID` prints as `ms-*` (its Seq *is* the sentinel; an explicit MaxUint64 seq cannot be added). `ParseID` takes "ms-seq"/"ms"/"ms-\*"; `$` maps to `LastID()` and `>` to ReadGroup's after == MinID (caller-side, documented). `LastID` survives Delete/trim; `SetLastID` is unconditional XSETID support (Redis rejects decreases — caller pre-checks; the storage stays sorted regardless). `Range(start, end, count)`/`RevRange(end, start, count)` have **inclusive bounds** (RevRange's parameter order mirrors XREVRANGE — a documented trap), count ≤ 0 = no limit, and walk the **live** storage on the plain package.

Layout (documented in the README): entries live in a `skip_list.SkipList[Entry]` ordered by ID (the fifth intra-pluto composition; O(log n) add/seek, O(log n + m) ranges, span-backed `DeleteByRank`/`DeleteRange` give O(log n + k) `TrimMaxLen`/`TrimMinID`) — no listpack block packing, per the note's favor-simplicity guidance. Each group holds lastDelivered, a consumer name set, and **one group-wide PEL** — a `skip_list[pelEntry]` ordered by ID carrying consumer/delivery time/delivery count — because every PEL query in the command family is range-shaped; XAUTOCLAIM's min-idle filter runs during the ID-ordered scan capped at `autoClaimAttempts` (10) × count examined entries (Redis's attempt limit; count ≤ 0 = uncapped), not through a time index.

Group semantics to preserve: `ReadGroup` with after == MinID is the `>` form (floor = group's last-delivered, advances it, never re-delivers live-pending entries); any other `after` is a **replay** (floor = after, does NOT advance last-delivered; a literal replay-from-0-0 is `GroupSetID` + `>`). Consumers are auto-created by ReadGroup/Claim/AutoClaim. `Claim` gates on minIdle, bumps delivery count, and **silently drops** pending IDs whose entries are gone; `AutoClaim` reports them in `deletedIDs` (Redis 7) and returns `nextStart` = successor of the last examined ID (MinID when exhausted). **Delete and the trims never touch PELs** (Redis behavior — abandoned work over trimmed data stays discoverable); `Ack` clears it. `GroupNames`/`GroupLastID`/`GroupConsumers`/`Pending` are the XINFO surface; missing groups report empties (NOGROUP is the caller's layer). Iteration-mutation rule: the plain package's iterators walk live skip-list nodes — internal PEL mutations are always deferred to after the walk (see `AutoClaim`, `GroupDeleteConsumer`); never mutate a PEL/entry list mid-`Range`.

`stream_ts` guards a plain `stream.Stream` **value** behind one RWMutex (the `hash_tab_bt_ts` composition pattern — no locks inside the borrowed structure) and **aliases** `ID`/`Entry`/`PendingEntry` plus the errors/sentinels/`ParseID`/`CompareID`, so twin-switching is an import change. Snapshot `Range`/`RevRange` (eager, collected under the read lock), real `Lock`/`Unlock` + the full `Nl*` mirror (`NlAdd`…`NlAutoClaim`, plus `NlRangeSnapshot`/`NlRevRangeSnapshot`; iterators get no `Nl*` forms), nil guards **before** lock acquisition. Concurrent appends must use the **AutoSeq form** — the next-seq resolution runs under the lock (how a Redis server assigns XADD IDs); explicit concurrent IDs cannot satisfy the total order (the stream's contract, documented in the race test). Plain `stream` keeps no-op `Lock`/`Unlock` for compile parity. `checkInvariants` in thorough_test.go (entries strictly ascending, max entry ≤ last, PEL ascending/owned/counts ≥ 1, `Pending` agreement) — call it after structural changes; `TestStreamRandomizedModel` (`rand.NewPCG(42, 7)`, 4000 steps) cross-checks every return value and the full post-state against a map/slice model each step (minIdle only ever 0 or 1h so idle comparisons stay deterministic); benchmarks cover 1M adds, ranges over 1M entries, and AutoClaim over 100k pending.
