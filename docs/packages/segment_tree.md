# segment_tree notes

`SegmentTree[T any]` is the array-backed segment tree (Sedgwick "Beyond" §SegmentTree): `tree []T` of size 2·nextPow2(n) with identity-padded leaves, iterative O(log n) `Query(lo, hi)` (inclusive) / `Update(i, v)` (point assign), O(1) `Value` (leaf read — `size` is a struct field for this). Dual constructors per the ordering convention: `NewSegmentTree[T g_lib.Numeric](data)` = range sum; `NewSegmentTreeFunc[T any](data, combine func(a,b T) T, identity T)` = any associative op (min/max/gcd) — the stored `combine`+`identity` are the whole difference. Panic contract: empty data (each constructor names itself — `NewSegmentTree` checks before delegating) and nil `combine`; `Update` on a nil tree panics; out-of-range reports `false`, reads tolerate nil. No-op `Lock`/`Unlock` in the plain package. `segment_tree_ts` adds the RWMutex plus `NlLen`/`NlQuery`/`NlValue`/`NlUpdate`. `thorough_test.go` cross-checks sum/min/max trees over shared data against brute-force loops at seed 42; `checkInvariants` verifies the internal array against the leaves.
