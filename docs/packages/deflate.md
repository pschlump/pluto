# deflate notes

`deflate` is RFC 1951 DEFLATE over byte slices: `Compress(data []byte) []byte` / `Expand(data []byte) ([]byte, int)` — the int is bytes of input consumed (padding byte included, trailing input excluded) so the gzip/zlib wrappers can locate their trailers; `(nil, 0)` is malformed. It is the codec of gzip/zlib/zip (method 8) and `.tar.gz`; pluto `lzw` is a different, algs4 format.

Structure: `bits.go` (LSB-first bitWriter/bitReader — DEFLATE packs all fields LSB-first but emits Huffman codes MSB-first, so encoder-side codes are pre-reversed via `reverseBits` and written through the same LSB writer; the bitReader has two modes, see streaming below); `huff.go` (canonical machinery: `buildLengths` via pluto/heap with ties by node index for determinism, freq-halving loop when the optimal tree exceeds 15/7 bits, `canonicalCodes`, decoder-side `decTree`); `tables.go` (RFC §3.2.5 length/distance bases+extras, the §3.2.7 CL permutation, fixed trees); `deflate.go` (encoder); `inflate.go` (decoder); `stream.go` (streaming Reader/Writer).

Encoder: hash-chain matcher (3-byte Knuth-multiply hash into 2^15 chains, `maxChain` 128, walk bounded by the 32K window) with one-step lazy matching; matches 3..258, overlapping allowed (`matchLen` compares straight into the input). Tokens flush as blocks per 16384 symbols; `flushBlock` prices stored (with exact byte-alignment pad), fixed, and dynamic by exact bit count and emits the cheapest. Traps burned in during development, keep the tests:

- **The dynamic header transmits code-length VALUES (3 bits each), not the Huffman codes of those lengths.** Writing `clCodes[clOrder[i]].bits` there produced streams stdlib rejects with "corrupt input" — the bug appeared only for inputs whose CL tree was nontrivial (long runs), passing the small tests first. `TestRoundTrip/run-a` and the seed-42 sweep hold this.
- **`decTree.syms` must be grouped by (length, symbol), not symbol order** — canonical decode indexes `syms[index + code - first]` where index accumulates per length. Sym-order construction decoded *wrong symbols silently* (the first version of this bug decoded empty output for everything).
- **The fixed distance tree is legitimately incomplete** (codes 30-31 exist but never occur, §3.2.6) — stream validation would reject it, so fixed trees are built by `buildFixedTree` without validation. Dynamic trees keep zlib's exact rules: literal and CL trees must be complete; a distance tree may be incomplete only as a single 1-bit code (the encoder writes that shape when 0 or 1 distances are used — `distLengths[0]=1` on `distAllZero`).
- **The chain head can be the encoder's own current/next position** (insert happens before match, and lazy inserts i+1): `findMatch` skips `j >= i` first or it emits distance 0 — a self-match.
- A literal tree with a single used symbol can't be dynamic (incomplete) — fall back to fixed/stored (`litUsed >= 2` gate).
- `lengthCodeOf(257)` → code 284 with 5 extra bits, `lengthCodeOf(258)` → 285; the encoder's `lengthCodeOf` walks bases downward and lands right, don't "simplify" it to a shifted mask.

Decoder: puff-style per-length canonical walk (≤15 bit reads/symbol). Rejects: BTYPE 11, LEN/NLEN mismatch, truncated stored data, HLIT>286 / HDIST>30, incomplete/oversubscribed trees, CL repeat with no previous or past the end, literal symbols 286/287, distance symbols 30/31, distance > output length, unmatched bit patterns, a literal tree with no code for symbol 256 (a block that can't end), input exhausted anywhere. All report `(nil, 0)`; nothing panics (bit-flip fuzz asserts this).

Tests: `deflate_test.go` corpus (empty/tiny/runs/overlap/all-bytes/text/random/far-match-at-32768/Fibonacci-skewed frequencies — the skew forces the freq-halving length limiter — sizes 65534-65537, mixed 300K) with round trips + **stdlib interop both directions** (`TestStdlibReadsOurs`, `TestWeReadStdlib` at all five stdlib levels), hand-built crafted vectors (valid stored `01 01 00 FE FF 41` → "A"; malformed: reserved BTYPE, LEN/NLEN mismatch, oversubscribed CL tree `05 00 F8 1F`, match into empty history `05 02`, fixed symbol 286 `1D 03`), truncation sweep (every proper prefix of our single-final-block streams → nil), trailing-input consumed-count; `thorough_test.go` seed-42 400-step property test across 5 input shapes with bidirectional stdlib cross-checks every 8th step, sizes 0..1200 sweep, bit-flip no-panic sweeps. `Compress(nil)` == `03 00` golden. `stream_test.go` mirrors the suite for the streaming types (below).

Benchmarks (M4 Max, 256 KiB mixed corpus): Compress ~2615 µs (~100 MB/s, vs stdlib level 6 ~428 MB/s — a quarter of stdlib speed, comparable ratio); Expand ~1124 µs (~236 MB/s, vs stdlib ~372 MB/s). The decoder's bit-at-a-time canonical walk is the deliberate simplicity; a table-driven decoder is the obvious future speedup if it ever matters.

## Streaming (`stream.go`)

`NewWriter(dst)` / `NewReader(src)` wrap the same codec as io.Writer/io.Reader: one raw DEFLATE stream, memory bounded regardless of length (Reader: 32 KiB history + bounded input stage; Writer: 64 KiB window + bounded output). `Reader.Close` reports the sticky error; `Reader.Buffered()` returns staged-but-unconsumed source bytes past the final block — gzip/zlib framing takes its trailer from there. Errors: corruption wraps `ErrMalformed`, truncation is `io.ErrUnexpectedEOF`, both sticky. `Compress(nil)` == `03 00` golden holds for the Writer too.

Sharing the decode path cost a 2× Expand regression twice; the shape that finally works:

- **bitReader has two modes.** Whole-buffer (Expand): `buf` is the caller's slice, end-of-slice is end-of-input. Streaming: a `src io.Reader` is attached and `fill()` stages 32 KiB chunks (compaction keeps the stage bounded; (0,nil) reads retried 100× then `io.ErrNoProgress`). An interface or generic for the bit source had been tried first — per-symbol dynamic dispatch through `decode` halved Expand (236→98 MB/s).
- **`decTree.decode` writes the byte-load/bit-extract inline** (the body of `readBit`) rather than calling it. `readBit` must call the non-inlinable `fill`, which makes `readBit` itself non-inlinable, and a call per bit in decode's walk is exactly the 2× again. decode is too big to inline into anyone, so the `fill()` call inside it is free. `readBits` (extra bits, ~once per match) still calls `readBit` — measured, not hot.
- **`expandBlock(r, out, lit, dist, limit)` pauses at an output limit** and resumes with the same trees and buffer (`1<<62` = run to end of block). The Reader's output is a cursor over one buffer: `out[:delivered]` is history already handed to the caller, `out[delivered:]` pending; `trim()` keeps at most 32 KiB of history because match distances index the whole buffer. **Dropping delivered bytes entirely was the second regression** — matches reaching into delivered output (`d > len(out)`) then rejected legal streams; bytes must be retained one window past delivery, never re-delivered.
- **Stored blocks** bypass the accumulator: after `align()` the 16-bit LEN/NLEN reads consume exactly two staged bytes each, so `pos` lands on the raw data and stStoredCopy copies straight from the stage.
- **Truncation vs corruption:** a bit read failing for want of input sets `readFailed`; `starved()` maps that to `io.ErrUnexpectedEOF` (or the underlying read error) and everything else to `ErrMalformed`.
- Writer: sliding 64 KiB window, absolute int64 hash-chain positions (`head`/`prev` indexed `pos & windowMask`), same lazy matching and 16384-token blocks as `Compress`; `flushBlock`/`writeTokens` are reused verbatim. `drain()` emits only whole bytes so consecutive blocks share bit boundaries exactly as whole-buffer output does. `Flush` ends a non-final block (decodable early), `Close` the final one.

Streaming traps: `io.Pipe` is synchronous — a Flush test needs the reader goroutine running before the writer's pipe writes can return, and a bytes.Reader snapshots its input so later writes are invisible to an already-created reader (use a pipe). Testing truncation on streaming output is O(n²) per prefix — sample with a stride.

No `_ts` twin (stateless, `lzw` precedent). No panics. Concurrency-safe by construction.
