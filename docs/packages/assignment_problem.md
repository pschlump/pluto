# assignment_problem notes

`assignment_problem` is Sedgwick's §6.5 `AssignmentProblem` (backlog Tier-2 item 14; the roadmap line said §6.4, but the algs4 file's own javadoc points at Section 6.5) — one constructor-style immutable query object solving the n×n min-weight perfect matching by **successive shortest paths**: empty matching, n rounds of Dijkstra over reduced costs on the residual alternating-path graph, flip one shortest augmenting path per round, shift duals by the computed distances.

**Structure.** `AssignmentProblem` keeps the caller's matrix copied, `minW = min(0, every weight)` (algs4's shift making every internal cost non-negative — negative weights are legal input despite algs4's javadoc claiming otherwise; the code does the same shifting), duals `px/py`, match arrays `xy/yx`, and per-round Dijkstra scratch allocated once in `prepare` (`distRow/distCol/settledRow/settledCol/prevRow`) — `augment` allocates nothing. `NewAssignmentProblem = prepare + n× augment`; the split exists so `TestRoundByRoundDualInvariants` can check the dual invariants between rounds (the white-box counterpart of algs4's constructor asserts).

**The public duals are TRANSLATED, not algs4's.** algs4's `dualRow`/`dualCol` return `px`/`py` — duals of the minW-shifted instance, under the pairing (−px_i) + py_j ≤ w_ij − minW. pluto's `DualRow(i) = minW − px[i]` and `DualCol(j) = py[j]` shift the row side back so the LP-duality certificate holds verbatim on the CALLER's matrix: `DualRow(i)+DualCol(j) ≤ w[i][j]`, equality on matched pairs, dual sum == Weight(). Get the translation on the wrong side (py − minW on columns, say) and the sum identity silently breaks (Σduals = Weight − 2·n·minW or similar) — the certificate test catches it immediately.

**Run the Dijkstra to completion.** The dual update adds distTo of EVERY row and column (algs4's DijkstraSP computes the full tree; the sink is a dead-end vertex). An "optimization" that breaks the scan when the sink comes within reach leaves unsettled vertices with tentative (too-large) distances; shifting those can push reduced costs NEGATIVE and break dual feasibility — and the settle-order trap is subtle: the first settled FREE column is not necessarily the sink's best column, because the sink edge n+j→t costs `py[j]`, not 0. The implementation settles all 2n row/column vertices, then takes `jT = argmin over free j of (distCol[j] + py[j])` — that argmin IS distTo(t).

**Completeness is load-bearing.** The bipartite graph is complete (n×n matrix), so every vertex is reachable from the free rows every round — every dist finite, so the unconditional `px[i] += distRow[i]` can never add +Inf and NaN the duals. Generalize to a sparse instance and that guarantee dies with the completeness (algs4 would NaN the same way); the `default: return` arm in the settle loop is the defensive mark of this.

**Other kept algs4 details:** the relative-epsilon snap in `reducedCost` (`|rc| ≤ 1e-14·(|w|+|px|+|py|) → 0`, `floatingPointEpsilon` — float hygiene, load-bearing for the near-zero comparisons the certificates make; the white-box test checks the RAW reduced cost so the snap cannot hide a violation) and the exactness ceiling note (integer weights, intermediate results below 2^52 — `TestAdversarialShapes`' big-integers shape sits near it at 1e12-scale entries).

**Determinism:** all scans use strict `<`, so ties break by lowest index — same instance, same matching, every run (no RNG in the solver). Multiple optima are still possible (constant matrices: every permutation); tests compare WEIGHTS, never matchings.

**Panic contract:** exactly the constructor on a ragged matrix (names the row) or a NaN/±Inf entry (names the cell — encode forbidden pairs as a large finite penalty). nil/empty matrix → the empty assignment; nil receiver and out-of-range indices report −1/0. No `_ts` twin (maxflow immutability precedent; constructor snapshots the matrix). Rectangular m×n (m<n) instances: pad to square with a constant — documented caller recipe, deliberately not API.

**Tests.** `checkCertificate` (the four LP-duality identities — a proof of optimality, the bipartite-König-certificate counterpart), `bruteForce` (permutation enumeration, n ≤ 7), `spfaReference` (independent solver: one shortest augmenting path per free row via queue-based Bellman-Ford over REAL weights — no duals, no reduced costs, digests negatives unshifted; structurally unlike the shipped Dijkstra+potentials). Integer suites assert EXACT equality (eps 0): the whole solve stays in float64-exact arithmetic for integers. Floats use 1e-8 relative. Benchmarked direct vs algs4-style `composedDijkstra` (builds `EdgeWeightedDigraph` per round over pluto `dijkstra`; kept in `bench_test.go`): direct 2.6–2.9× faster and ~1300× less memory at n=200 (0.4 MB vs 500 MB, ~200 vs ~400k allocations).
