# quicklist notes

`quicklist.QuickList[T any]` is the segmented deque (Redis-quicklist equivalent, note/10-segmented-deque.md): a doubly-linked list of `segment[T]` nodes, each a packed `[]T` whose live region is `data[start : start+n]` (front slack makes `PushHead`/`PopHead` O(1), back slack the tail ops).  Constraint-free and zero-value usable (fill 0 → `DefaultSegmentFill` 128 via `fillTarget`; `segCap` tightens it by the `WithSegmentBytes` payload cap, `unsafe.Sizeof(T)` per element).  A segment splits in half when an insertion exceeds `segCap` (`insertAt` inserts then splits at `n/2` — splitting first breaks `fill == 1`), and `maybeMerge` **cascades** while any adjacent pair sums to ≤ `segCap/2` (one merge can drop the combined segment below threshold against its other neighbor — range removals need this; capture `s.prev` *before* `mergeSegments`, which unlinks and clears the pointer).  Index ops are seek-based (`locate` walks whole segments from the nearer end).  Compression (`WithCompression(codec, depth, enc, dec)`, Redis list-compress-depth): `recompress` after every mutating op walks all segments — materialize the first/last `depth`, pack the rest — so it costs O(S) per op; `materialize` copies into a fresh `segCap`-sized backing so a decompressed segment keeps push slack (a bare `dec` slice has `len == n` and overflows the next push — the oracle caught this).  Panics: exactly two, `PushHead`/`PushTail` on nil.  `checkInvariants` in thorough_test.go (link integrity, no empty/over-cap segments, no adjacent pair ≤ merge threshold, depth windows) — call it after every op in new tests; `TestRandomizedModel` is a 100k-op oracle vs `[]int` at seed 42.

`quicklist_ts` wraps a `quicklist.QuickList` value (not a re-implementation) behind `lock sync.RWMutex`, taking the plain package's `Option[T]` in `NewQuickList`.  `At`/`Set` and the snapshot iterators take the **write** lock (they can materialize compressed segments); only `Len`/`PeekHead`/`PeekTail` are read-locked (end segments are never packed).  `MoveHeadToTail` locks the two lists in pointer order (self-rotation takes one lock).  Full `Lock`/`Unlock` + `Nl*` surface.  Run its tests with `-race`.

**Phase-4 capabilities** (`capabilities.go`, plan §4.4 minimal sequence menu): `Slice`/`String`/`StringFunc`/`Equal`/`Clone`, all O(S + n), all total functions.  The reads walk `All()` so **compressed segments are read through transparently** (materialize + re-pack — the compression windows are unchanged; the `MarshalJSON` precedent).  `Equal` is the **order-sensitive** Equal (`[a b] ≠ [b a]`); the length check runs before any element compare, then elements go through `any(a) != any(b)` (Go `==` via interface conversion — the constraint-free phase-4 decision).  `Clone` copies the whole config (`fill`, `byteCap`, `elemSize`, `codec`, `depth`, `enc`, `dec`) and rebuilds with `depth` temporarily zeroed and one deferred `recompress` — the `UnmarshalJSON` O(S+n) trick; without it every `PushTail` would re-sweep at O(S).  The twin's four capabilities are **At-shaped reads → write lock** (the walk can materialize segments): `Slice` = `snapshot()`, `Equal` = two sequential snapshots (one lock at a time, no deadlock), `Clone` = write lock + `q.inner.Clone()` (the plain package's exported Clone — the config fields are unexported cross-package).  Tests: 1500-step randomized model at PCG seed (1,42) with `checkInvariants` + capability checks every 37 steps, compressed-vs-plain equality/cloning cases, rotation-not-equal; the twin adds the concurrency hammer + no-deadlock pair (`capBuild`/`capBracketOf` avoid the existing `build` helper names).
