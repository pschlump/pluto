# string_sort notes

`string_sort` is Sedgwick's §5.1 character-key radix sorts as stateless in-place functions over `[]string`: `LSDSort(a, w)` (w passes of key-indexed counting, least-significant byte first — **fixed-width keys**, every key at least w bytes, longer keys sort by their first w bytes only), `MSDSort(a)` (MSB-first recursion, `byteAt` -1 end-of-key sentinel so prefix keys sort first, `count [R+2]int` with the algs4 c+2/c+1 shift), and `Quick3String(a)` (3-way radix quicksort, fully in place). Ordering is **byte-wise lexicographic — exactly Go's native string `<`** — over a 256-bucket alphabet covering every Go string (binary-safe/UTF-8 alike), so `slices.Sort` is the exact oracle and the sorted sequence of a multiset is unique (`slices.Equal` against it checks sortedness+permutation in one). `less(v, w, d)` is `v[d:] < w[d:]` (the d-prefix invariant both recursive sorts maintain makes suffix comparison the full comparison). LSD/MSD stable, Quick3 not. **Non-generic** (`[]string` — the bitmap/geo precedent; radix ordering is inherent in the bytes, no comparison function to store) and stateless → **no `_ts` twin** (quick_sort precedent). Panic contract: exactly 2, both in LSDSort (`w < 0`, key shorter than w — the only function with a precondition), each naming the function. Quick3String carries the two quick_sort deviations (a library cannot pre-shuffle): **median-of-3 pivot byte** (algs4 uses the first key's byte) and **recurse-smaller-side/loop-larger** — stack O(log n) + longest shared prefix; MSD recursion depth ≤ longest key length (deep-common-prefix inputs rely on Go stack growth — `TestDeepCommonPrefix` sorts 2000 keys sharing a 2000-byte prefix). Insertion cutoff 15 shared by MSD/Quick3 (algs4's CUTOFF; quick_sort's own 12 is a different package's constant). MSD skips recursion into buckets known empty (no-op elimination, algs4 recurses and returns). Thorough tests at PCG 42,7: fixed-width/variable-width/equal-prefix-heavy/prefix-chain/binary-alphabet-256 models vs `slices.Sort`, `TestSortedAdversarial` (100k sorted/reverse/all-equal). Benchmarks (100k keys, M4 Max, clone included): MSD 2.5 ms vs `slices.Sort` 9.4 ms on random 16-byte keys, Quick3String most robust on long shared prefixes (11.1 ms on 48-byte-prefix keys, beating even `slices.Sort`), LSD 4.6 ms on random16 but 25.3 ms on long64 — every one of the w passes is a full counting sort.
