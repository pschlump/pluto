# sparse_vector notes

`sparse_vector` is Sedgwick & Wayne §3.5 `SparseVector.java` — a dimension-indexed sparse vector generic over `g_lib.Numeric` (~T union, so defined numeric types pass; `g_lib.Number` would reject them), one `map[int]T` of the nonzero entries, d fixed at construction. It is the container the planned `gauss`/simplex packages are built from: `Dot` costs O(nnz) not O(d), and `Axpy` (α·x plus y, in place — the BLAS name) is the elimination row operation.

Canonical form is load-bearing: `Put(i, 0)` deletes, `store()` (the one helper) deletes-on-zero in `Plus`/`Axpy` too, so `NNz` is always exactly the count of nonzero dimensions and `Get`'s ok is exactly "dimension i is nonzero" (a stored zero cannot exist — do not "optimize" the ok away). Consequences tested: cancel-to-zero prunes (`v + (-v)` is nnz 0; `Axpy(-1, v)` self-eliminates), `Scale(0)` is the empty vector.

Panic surface is 7 (fenwick_tree style, counted in the package doc): constructor `d < 1`; `Put`/`Axpy` on nil receiver; and the four dimension mismatches (`Dot` len, `DotSparse`/`Plus`/`Axpy` operand dim). Everything else REPORTS (heap/fenwick convention): `Put` out-of-range → false (the ZERO VALUE vector, dimension 0, returns false — only the nil POINTER panics), `Get` → (0,false), nil receiver → zero-vector-of-dimension-0 semantics for every read. The algs4 client (a.put(3,.5)… b.put(4,.9)…) is the pinned oracle; note `0.5+0.6` rounds to exactly the float64 1.1 (aligned-exponent add rounds up into 1.1's mantissa) and `0.5·0.6` is exactly 0.3, so the Go output matches the book's — verified, not assumed.

Plain `Axpy(α, v)` self-alias is safe because the range loop only overwrites/deletes the CURRENT key, never inserts; `Plus` builds a separate result map. `DotSparse` iterates the smaller map and probes the bigger — O(min nnz).

`sparse_vector_ts` (fenwick_tree_ts pattern): `Put`/`Axpy` write lock; reads read lock; real `Lock`/`Unlock` + `NlDimension`/`NlNNz`/`NlGet`/`NlPut`/`NlEach`/`NlDot`. The discipline rules: (1) `d` is immutable after construction → `Dimension` and the mismatch checks take NO lock; (2) `Each` SNAPS under the read lock and runs callbacks OUTSIDE it (a callback may `Put` the same vector — tested); `NlEach` is the live walk, callbacks must not lock; (3) the two-vector ops snapshot the operand under the operand's own read lock BEFORE the receiver's write lock — never two locks at once, else `v.Axpy(α, v)` racing `v.Axpy(β, u)` cross-deadlocks (the AB pattern: holds v.write wants x.read vs holds x.write wants v.read). That is also why there are no `NlAxpy`/`NlDotSparse`/`NlPlus`: a second vector's lock cannot nest under a held write lock; the regular forms are already atomic. `Dot` takes the caller's dense slice by reference — caller must not mutate concurrently (documented).

Benchmarks (d=2²⁰, nnz=1000, M4 Max): Put 97 ns, Get 83 ns, DotDense 9.9 µs vs the plain dense loop 320 µs (the 32× sparsity payoff), DotSparse 11.5 µs (twin pays the snapshot copies), Axpy 34.7 µs (writes + growth churn in the loop).
