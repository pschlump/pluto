# sll notes

`Sll[T any]` is the lean sibling of dll: stack ops (`Push`/`Pop`/`Peek` at the head), O(1) tail insertion (`InsertAfterTail`), value `Search`/`Delete`, `Reverse`, the cursor `SllIter` (Front/Current, forward only — no `Rear`/`Prev`), and `IterateOver` (`iter.Seq2[int, T]`; the same single-variable-yields-the-index trap as dll).  Error API: `ErrEmptySll`, `ErrNotFound`, with fixed precedence — `Delete` on an empty list returns `ErrNotFound`, `DeleteFound` returns `ErrEmptySll`.  Unlike dll, `DeleteFound` is a **value-based re-search** (O(n) — it removes the first element equal to the found element's data), not a direct splice.  `checkInvariants` in thorough_test.go verifies head/tail/count consistency — call it after structural changes.

The phase-4 set-convenience capabilities live in `capabilities.go`: sequences get the §4.4 **minimal menu only** — `Slice` (fresh `[]T` head→tail, the `IterateOver`/`MarshalJSON` order; nil→nil, empty→empty-non-nil), `String`/`StringFunc` (bracket-space format, nil format → `[]`), `Equal`, `Clone`.  Deliberately NO `Contains`/batches/`DeleteFunc` — an O(n) membership scan over a sequence would be a footgun.  `Equal` is the one **order-sensitive** Equal in pluto ([a b] ≠ [b a]; the set-shaped packages compare membership) and, because sll already stores `eq`, it compares **through the stored equality function** — field-based equality honored, no comparability requirement (unlike the constraint-free sequences' `any(a)==any(b)`); lengths are compared first, so a zero-value list's nil `eq` is never consulted and all four are total functions (nil/zero-value behave as empty).  `Clone` builds `&Sll[T]{eq: ns.eq}` and re-appends via `InsertAfterTail` — fresh nodes, same eq (verify with `Search`).  In the twin, `Slice` is the existing `snapshot()`; `StringFunc`'s format callback and `Equal`'s pairwise comparison run **after** the snapshots with no lock held (`eq` is constructor-only, safe to read unlocked), and `Equal` takes each side's snapshot under that side's own lock — never two locks at once, so opposite-direction comparisons cannot deadlock.  Tests: the capabilities block (`TestCapabilitiesSlice`/`StringDeterminism`/`StringFunc`/`Equal`/`Clone`/`NilAndZeroValue` + the PCG(1,42) 800-step model vs a `[]TestSllItem` reference, checked every 37 steps) plus, in the twin, `TestCapabilitiesConcurrent` (8×200 hammer — note the hammer list must be built with `NewSll`, zero-value inserts panic on the eq guard) and `TestCapabilitiesEqualNoDeadlock` (500-element lists, both directions).

`sll_ts` adds the `lock sync.RWMutex` and the lock-free `deleteLocked`; its cursor `SllIter` walks the live list under per-call read locks (like `dll_ts`'s `DllIter`) while `IterateOver` uses an eager snapshot.
