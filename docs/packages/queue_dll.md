# queue_dll notes

`queue_dll.Queue[T any]` is the FIFO queue on a doubly linked list  Like `dqueue`/`stack_sll_ts` it is **self-contained**, not a wrapper over `dll`: pluto's `dll` requires an equality function at construction, a queue never compares, and the `prev` pointers make `Backward` O(1) per step.  Same public API as `queue` (`Push`/`Enqueue` at the tail, `Pop` discarding, `Dequeue`/`Peek` returning `(T, error)`, `Len` aliasing `Length`, `Truncate`, `All`/`Backward`), constraint-free with a usable zero value, and exactly one panic: `Push`/`Enqueue` on a nil queue.  Every operation is **strict** O(1) with stable memory (one node allocation per push, no slice window) — it is `queue`'s stable-memory counterpart and `dqueue`'s FIFO face.  `All` walks head→tail via `next` with index 0 at the head; `Backward` tail→head via `prev` with indexes counting down from `Len()-1`; both walk the **live** list, so the queue must not be modified while an iterator runs (`TestIteratorReflectsLiveQueue` checks that contract).  No `_ts` twin exists — point shared-FIFO callers at `dqueue_ts`'s `PushBack`/`PopFront`.  `checkLinks` in thorough_test.go verifies prev/next bidirectionality and head/tail/count consistency — call it after structural changes.

The phase-4 set-convenience capabilities live in `capabilities.go`: the **minimal §4.4 sequence menu only** — `Slice`/`String`/`StringFunc`/`Equal`/`Clone`.  Sequences are not sets, so there is deliberately **no membership predicate and no batches** (`Contains`/`InsertSlice`/`DeleteFunc` and friends are omitted — an O(n) membership scan over a sequence would be a footgun).  `Slice` walks head→tail (FIFO order, the `All` order); nil receiver → nil, an empty or drained queue → **empty non-nil** slice (no `head == nil` early return — that bug returned nil for drained queues).  `Equal` is the one **order-sensitive** `Equal` in pluto (`[1 2]` ≠ `[2 1]`): pairwise `any(a) != any(b)`, so the element type must be comparable — a non-comparable type panics only when two elements are actually compared, and different lengths / nil-vs-empty are answered without touching any element.  `Clone` re-inserts via `Push` into a fresh queue (its own node chain; `checkLinks`-verified in the tests).  All five names are total functions — no new panics on a nil queue.  Tests: `TestCapabilities*` in capabilities_test.go (order-sensitivity both directions, rotation-not-equal, PCG 1,42 model) plus the `Example*` set in capabilities_example_test.go.
