# queue_dll notes

`queue_dll.Queue[T any]` is the FIFO queue on a doubly linked list  Like `dqueue`/`stack_sll_ts` it is **self-contained**, not a wrapper over `dll`: pluto's `dll` requires an equality function at construction, a queue never compares, and the `prev` pointers make `Backward` O(1) per step.  Same public API as `queue` (`Push`/`Enqueue` at the tail, `Pop` discarding, `Dequeue`/`Peek` returning `(T, error)`, `Len` aliasing `Length`, `Truncate`, `All`/`Backward`), constraint-free with a usable zero value, and exactly one panic: `Push`/`Enqueue` on a nil queue.  Every operation is **strict** O(1) with stable memory (one node allocation per push, no slice window) — it is `queue`'s stable-memory counterpart and `dqueue`'s FIFO face.  `All` walks head→tail via `next` with index 0 at the head; `Backward` tail→head via `prev` with indexes counting down from `Len()-1`; both walk the **live** list, so the queue must not be modified while an iterator runs (`TestIteratorReflectsLiveQueue` checks that contract).  No `_ts` twin exists — point shared-FIFO callers at `dqueue_ts`'s `PushBack`/`PopFront`.  `checkLinks` in thorough_test.go verifies prev/next bidirectionality and head/tail/count consistency — call it after structural changes.
