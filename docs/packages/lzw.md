# lzw notes

`lzw` is LZW compress/expand over byte slices (Sedgwick §5.5, **widening-code variant**): `Compress(data []byte) []byte` / `Expand(compressed []byte) []byte`. Encode table = `pluto/tst.Tst[int]` (intra-pluto composition, zero value usable); decode table = `[]string`. Bit format (internal `bitWriter`/`bitReader` in bits.go): codewords packed MSB-first exactly like algs4 `BinaryStdOut.write(x, r)` (r low bits from bit r-1 down to 0, byte buffer fills MSB-first, final partial byte zero-padded); 256 = EOF sentinel (always written, even for empty input → `80 00`), codes start 9 bits wide and widen to 16 (codebook max 65536, never reset). Encoder widens when the next assignable code reaches `2^W`; the decoder (one entry behind) widens at `2^W - 1` — lockstep hand-traced. **NOT wire-compatible with stock algs4 `LZW.java`, which uses FIXED 12-bit codes** — this matters for the bench-vs-java5 cross-check (semantic comparison only: identical input, each side's `Expand∘Compress == identity`). `Expand` returns nil on malformed input (truncation, missing EOF, code more than one step ahead — algs4's expand NPEs there, a documented algs4 bug; the exactly-one-ahead KwKwK case is handled). No panics, stateless, no `_ts` twin. `thorough_test.go`: seed-42 round trips (sizes to 100000, distributions that force width transitions ≥ 12 bits and a full 16-bit codebook), known vectors derived by hand-trace (TOBEORNOT…, KwKwK `AAAAAA`, empty), malformed-input sweeps.
