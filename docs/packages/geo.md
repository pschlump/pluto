# geo notes

`geo` is the pure geohash math behind the Redis GEO command family (request `note/08-geo.md`, built for Ultima's GEOADD/GEODIST/GEOHASH/GEOPOS/GEOSEARCH/GEORADIUS; `note/redis/src/geohash.c`, `geohash_helper.c`, `geo.c` lineage): Encode/Decode (the 52-bit interleaved score Redis stores in a zset — lat in EVEN bit positions, lon in odd, MSB-first lon,lat,lon…), Neighbors (N,NE,E,SE,S,SW,W,NW order, both axes wrap), RangesForRadius/RangesForBox (the score ranges for a sorted-set lookup — the area-of-interest half of a radius search; the caller post-filters with Distance), Distance (haversine, `EarthRadiusInMeters` 6372797.560856, the equal-longitude fast path), ToMeters/FromMeters (m/km/ft/mi, **mi = 1609.34 — Redis's factor, not 1609.344**). Non-generic and stateless like union_find/suffix_array — nothing is stored — so no `_ts` twin (the substring/quick_sort/lzw/maxflow precedent); safe for concurrent use; **no panics at all** (sentinel errors: `ErrOutOfRange` band/NaN coords, `ErrNegativeRadius` negative-or-NaN radius/dims, `ErrInvalidUnit`).

Layout: geo.go (doc/constants/errors/units), geohash.go (interleave/deinterleave, encodeStep/Encode, decodeArea/Decode, moveX/moveY/Neighbors), ranges.go (estimateStepsByRadius, boundingBox, windowCovers, windowRanges/canonicalize, RangesFor*), distance.go. `checkRangesAgainstC`/`checkCanonical` in geo_test.go.

Compatibility contracts to preserve:

- **Encode/Decode/Neighbors/step-estimator are bit-compatible with the Redis C**, pinned by two agreeing oracles baked into `vectors_test.go` (generated, frozen): a harness compiling the note's actual C sources (v8.9.241) at `%.17g`, and a live Redis 7.2.7 (GEOADD+ZSCORE scores, GEOPOS centers, a 20-query GEOSEARCH BYRADIUS membership differential). GEOPOS prints only ~12 digits — its rows compare at 1e-11; the C rows compare exactly.
- **Decode pins FUSED edge arithmetic** (`math.FMA(frac, scale, min)`): the reference C compiles `min + frac*scale` with contraction on, and that addition cancels ~7 digits near the band bottom, so unfused edges differ far beyond an ulp. Distance pins UNFUSED products via `math.FMA(x, y, 0)` (round(x·y)) — that is what keeps `Distance(p,p) == 0` and symmetric (Go's permitted FMA contraction of `degToRad*lat2 − degToRad*lat1` returned the multiply's rounding error otherwise — observed). Distance remains libm-ulp-unstable (~1e-11 rel on near-coincident points); vector tolerance 1e-9 vs the note's 0.5% gate.
- **The exact band corners spill above the score space**: Encode(85.05112878, 180) = 2^52+2^53 (a live Redis stores 13510798882111488); `scoreSpaceTop` = 13·2⁵⁰ bounds everything the range queries emit, and fullRange is [0, scoreSpaceTop).
- **Ranges are a conservative-complete superset** ([lo,hi) half-open, sorted, disjoint): no false negatives ever — 74,798 in-circle + 62,030 in-box fuzz samples, zero misses (seed 42/7) — false positives expected; caller post-filters (Distance for circles; for boxes the two-Distance rule documented on RangesForBox, the longitude test at the CANDIDATE's latitude).
- **Ranges diverge from Redis's C only by widening or fining-while-still-complete**: Redis checks coverage once and decrements the step at most once (under-covers near the poles and misses members — demonstrated); pluto's coverage test is arc-correct (wrapped east neighbor counts across the antimeridian; a center cell reaching the band edge covers everything poleward) and LOOPS the decrement, degrading to fullRange only when no 3×3 window can cover (pole-reaching shapes; the bounding box's 1/cos blowup past ±360°). Antimeridian circles keep the estimated (finer) step where Redis needlessly decrements. Never fewer results than Redis.

Tests: vectors (geo_test.go), round-trip (random points AND random raw 52-bit scores — the center of cell h re-encodes to h), the two completeness fuzzes, known city pairs ±0.5% plus exact identities (antipodal = πR, pole-to-pole fast path), units table, error/wraparound contracts, and the seed-42 model test cross-checking Encode/Decode against an independent interval-halving oracle, Neighbors against coordinate arithmetic (wrap cases skipped — pinned by C vectors), Distance against the spherical law of cosines. Benches: Encode 3.2 ns, Decode 3.5 ns, Neighbors 2.3 ns, Distance 16 ns, Ranges ~90–113 ns.
