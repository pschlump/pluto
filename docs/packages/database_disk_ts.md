# database_disk_ts notes

`database_disk_ts` is the composition layer of note/database.md: a record database ON TOP of `b_tree_disk_ts` (by-name, ordered) and `hash_index_disk_ts` (by-ID, equality) — it does NOT duplicate their disk machinery, it opens one store of each plus its own record file. Three files per Path: `.rec` (slots), `.eq` (hash store), `.ord` (tree store). Both indexes map their key → SLOT NUMBER, and every live slot is SELF-DESCRIBING — `[status 1B][len u32][next u64][id eqKS][name ordKS][data]` — the embedded keys are what make cross-index deletes O(1) (DeleteByID reads the name out of the slot; no scan) and what make reads self-verifying (read repair).

**The two contracts inherited, one added.** The eq side carries the hash-index contract (injective EncodeKey); the ord side the B+ tree contract (byte order == Compare order). The DB adds: DecodeKey must be a true INVERSE of EncodeKey on stored keys (`DecodeKey(EncodeKey(k)) == k`) — iteration yields decoded keys, and the DB re-encodes them to verify slots (RangeByName/All) and decodes slot bytes to drive the cross-index deletes. Fixed-width zero-padded encodings satisfy all of this for free.

**Durability is honest non-atomicity.** No cross-file commit exists. Sync order is LOAD-BEARING: record file fsync FIRST, then eq/ord store Sync — an index entry must never be durable while the record it points at is not. Crash windows: (a) Put's slot write without its index inserts → an ORPHANED slot (unreachable garbage that is NOT on the free list — deliberately leaked; a future compact would reclaim); (b) a Put between the two index inserts → by-ID visible, by-name not; (c) a delete interrupted between the index deletes and the free → a DANGLING entry. The order inside delete is index-deletes-BEFORE-free so the dangerous window (live entry over a REUSED slot) cannot happen by construction. Read repair: every point read verifies the slot is live AND carries the key it was looked up by; mismatch → the stale entry is deleted on the spot and the read reports not-found. The OTHER index's stale twin heals when next read (documented; checkInvariants tolerates it never being touched).

**Record-file layout.** 512-byte header: magic "pluto-db", version, slotSize, eqKS, ordKS, numSlots, freeHead (+1-encoded, 0 = none), and BOTH INDEX NAMES (32B each) — a record file belongs to one pair of indexes; wrong name/keySize/slotSize on reopen is ErrCorrupt. TRAP: `writeHeaderLocked` (run on every alloc/free) must rewrite the NAMES too — the first version wrote only the numeric fields and the first allocation zeroed the names, making every reopen ErrCorrupt (caught by TestReopenPersistence). Slots start at offset 512; a header that lags the file size (crash between slot append and header write) is recovered by TRUSTING THE FILE SIZE — unknown slots are free, since nothing durable ever pointed at them.

**Uniqueness model.** ID = primary key (Len = eq.Length). Names unique per record: Put with a name held by a different ID → ErrNameConflict — including the rename path (Put same ID new name when that name is taken). Same ID + same name = data rewrite (same slot); same ID + free new name = rename (ord.Delete(old) → rewrite slot → ord.Insert(new); the eq entry never moves). Put's presence checks read-repair dangling entries BEFORE deciding conflict vs rename, so crash garbage cannot wedge the database into permanent ErrNameConflict.

**Locking.** One DB mutex over everything; stores lock underneath. The DB lock is ALWAYS acquired first and nothing under it calls back — the only nesting rule. Reads take the write lock (a read is resolve-then-read-slot; the lock keeps the pair consistent). Iterators are snapshots: All/RangeByName collect (key, data) under one lock hold — the underlying eq.All()/ord.Range() are already store-level snapshots — then yield lock-free. The DB keeps its own copy of ord's Compare (priority_queue precedent) to bound RangeByName(lo, hi): the underlying Range(lo) has no upper bound; the DB's loop breaks when compare(name, hi) > 0.

**Test oracles.** checkInvariants (thorough_test.go) walks the by-ID index: each entry → live slot, embedded id matches, the slot's name resolves through the tree to the SAME slot, no slot reached twice; then every live slot in the file must be reachable (no orphans — holds because tests never crash mid-Put); the free list is in-bounds, acyclic and disjoint from live; eq.Length == ord.Length == live count. The model test is seed-42 PCG, 10000 ops over a 1500-ID space with names derived deterministically from ids (nameOf — conflicts impossible by construction, so the model needs no name bookkeeping), reopen cycles at 4000/8000. Read-repair tests scribble BEHIND the indexes' backs in-package: TestReadRepairDanglingEntry zeroes a live slot's status byte (the exact on-disk state of an interrupted delete); TestReadRepairMismatchedSlot re-points ada's tree entry at grace's slot via raw ord.Delete+Insert. Range-by-name spot check in assertModel compares against the model's own sorted-name filter — remember names are NUL-padded ([16]byte): compare with bytes.Compare on the raw arrays, trim "\x00" only for printing.

**Benchmarks.** Put = hash insert + tree insert + one slot WriteAt (plus a header WriteAt on allocation); GetByID ≈ hash Search + ReadAt; GetByName ≈ tree Search + ReadAt. The record file has NO cache — the OS page cache is it (documented); the two stores carry their own LRU/journal machinery unchanged.
