# b_tree notes

`BTree[T any]` is a Sedgwick/Bayer–McCreight B-tree: the constructor takes `order` (Sedgwick's M — max children per node, ≥ 3), so a node holds up to order-1 keys. `NewBTree[T cmp.Ordered](order)` / `NewBTreeFunc[T any](order, cmp)`; the panic contract is exactly 4: order < 3, nil cmp, `Insert` on a nil tree, `Insert` on a zero-value tree — every read tolerates nil/zero-value. `Insert` is **bottom-up** (a node that overflows to order keys splits around its median and pushes it up) — deliberate, because CLRS preemptive split mishandles odd orders like 3; it returns bool (true = added, false = duplicate replaced). `Delete` is CLRS-style borrow-then-merge repaired on the way back up, with `shrinkRoot` collapsing an emptied root; `DeleteAtHead`/`DeleteAtTail` are single descents down the left/right spine. `All`/`Backward` are `iter.Seq2[int, T]`. No `Index` (nodes carry no subtree sizes) and no set ops. `checkBTreeInvariants` in thorough_test.go (uniform leaf depth, key counts in [ceil(order/2)-1, order-1] except root, sorted keys, subtree key ranges, total == Length) — call it after structural changes; `TestTreeRandomModel` (seed 42) runs orders 3/4/6 against a sorted-slice model. No `_ts` twin. Note: this in-memory tree is the teaching implementation — for real workloads (data too large for memory) use `b_tree_disk_ts`.

The phase-2 set-convenience capabilities live in `capabilities.go`: `Contains`/`ContainsSlice`/`ContainsAny`, `InsertSlice`/`InsertIter`/`DeleteSlice`/`DeleteFunc`, `Slice`/`String`/`StringFunc`/`Equal`/`Clone`. The shared `insertContractCheck(caller)` + `insertAll` pair carries the insert panic contract to the batch inserters (panic only when a batch would store; empty batch tolerated). `All` is `iter.Seq2`, so `Slice` takes the value operand of the range; `InsertIter` stays `iter.Seq[T]` — self-feed via `slices.Values(tree.Slice())`. `Equal` is Len + one-way Search (shape- and order-independent). `Clone` is the recursive structural copy carrying `order` and copying each node's keys/children slices — **leaves keep nil children** (`make(slice, 0)` on a leaf makes `children != nil`, which crashes `All`'s `children[i]` indexing; that was a real bug caught by the Clone test). `DeleteFunc` is collect-then-delete; batch mutators return "receiver changed"; read side total over nil/zero-value. Tests exercise orders 3/4/5/6/8 and the generic `checkBTreeInvariants` after every batch path.
