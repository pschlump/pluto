# splay_tree notes

`SplayTree[T any]` mirrors the binary_tree contract with top-down Sleator-Tarjan splaying (dummy header node, zig-zig before each link): `Search` splays on hit **and** miss, `Insert` splays then splits/links around the root, `Delete` splays the victim then joins the subtrees (splay the left subtree's max, link the right subtree under it). Every access mutates the structure — reads on nil/zero-value trees are still tolerated because they are guarded by `root == nil` before any splay and never consult `cmp`. `Insert` returns bool (true = added, false = duplicate replaced, matching binary_tree). Sorted ascending inserts legitimately build a depth-n chain — that is the O(n) worst case; one deep `Search` roughly halves it (asserted in `TestTreeSortedInput`, don't "fix" it). The API is rb_tree-lean: no `Index`/`Reverse`/`Walk*`/`Front`/set ops; `All`/`Backward` are `iter.Seq2[int, T]` with `Backward` indexes counting down from `Len()-1`. `checkInvariants` in thorough_test.go (BST order, Length vs node count, Search hits every key) — call it after structural changes; `TestTreeRandomizedModel` uses seed 42. No `_ts` twin.

The phase-2 set-convenience capabilities live in `capabilities.go`: `Contains`/`ContainsSlice`/`ContainsAny`, `InsertSlice`/`InsertIter`/`DeleteSlice`/`DeleteFunc`, `Slice`/`String`/`StringFunc`/`Equal`/`Clone`. The shared `insertContractCheck(caller)` + `insertAll` pair carries the insert panic contract to the batch inserters (panic only when a batch would store; empty batch tolerated). Splay semantics are documented per method: `Contains`/batches/`Equal` are built on `Search` (a hit splays to the root — asserted in `TestCapabilitiesSplaySemantics`), while `Slice`/`String`/`DeleteFunc`'s collect pass and `Clone` walk/copy without splaying. `All` is `iter.Seq2`, so `Slice` takes the value operand of the range; `InsertIter` stays `iter.Seq[T]` — self-feed via `slices.Values(tree.Slice())` (documented in the method and examples). `DeleteFunc` is collect-then-delete; `Equal` is Len + one-way Search; batch mutators return "receiver changed"; read side total over nil/zero-value. Tests use int trees so the typed `checkInvariants` applies, plus the standard mirrored suite minus any twin block.
