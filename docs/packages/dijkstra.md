# dijkstra notes

`dijkstra` is Sedgwick's §4.4 shortest paths on int vertices `0..n-1` — the weighted sibling of `graph`: `EdgeWeightedDigraph`/`EdgeWeightedGraph` adjacency-list containers (self-loops/parallel edges allowed, no `RemoveEdge`) plus the constructor-style query objects `DijkstraSP`, `DijkstraUndirectedSP` and `DijkstraAllPairsSP` in the same package. The PQ is `pluto/index_pq` (intra-pluto composition — decrease-key is exactly `index_pq.Change`); `shortestPathsFrom(adj, s)` is the lock-free core shared by `NewDijkstraSP` and `NewDijkstraAllPairsSP`. All weights must be non-negative: `validateDigraphWeights`/`validateGraphWeights` scan **all** edges upfront (even unreachable ones) and panic naming the constructor and the offending edge. Panic contract: constructors with v < 1, `AddEdge` on a nil graph, the Dijkstra constructors on a nil/empty graph or out-of-range source, and negative weights; nil/zero-value graphs read as empty (`AddEdge` on a zero value reports false — every endpoint is out of range), nil query objects report +Inf/false/nil. `PathTo` walks `edgeTo` backwards and reverses: nil for no path, empty non-nil slice for s→s, source-first otherwise, weights summing to `DistTo`. `Adj` returns the live internal slice (documented; the _ts twin returns a snapshot copy). `dijkstra_ts` follows the `graph_ts` pattern exactly: constructors snapshot the adjacency under the read lock, validate the snapshot, then search lock-free; query objects are immutable with no-op `Lock`/`Unlock`, while the graphs expose the **real** `Lock`/`Unlock` with no `Nl*` methods — calling any public method while `Lock` is held deadlocks. The algorithms were cross-checked bit-for-bit against the algs4 Java reference (`note/bench-vs-java2/go/sp`); thorough_test.go re-verifies against an in-test Bellman-Ford reference with integer weights (exact float comparison) at fixed seeds.
