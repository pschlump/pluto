# fenwick_tree notes

`FenwickTree[T g_lib.Numeric]` is the binary indexed tree (Sedgwick "Beyond" §FenwickTree) over indices `0..n-1`, internal 1-based `tree []T` (`tree[k]` = sum of the lowbit(k) values ending at slot k-1). `Add`/`Sum` O(log n); `Value` is prefix-difference reconstruction (O(log n)), `Set` = `Add` by computed delta, `RangeSum(lo, hi)` inclusive. Constructors `NewFenwickTree(n)` (panics `n < 1`) and `NewFenwickTreeFrom(data)` (O(n) build; panics on empty). Indexed ops follow the `heap` convention — out-of-range reports `false`/zero (`Sum` of any out-of-range index is the zero value, incl. `Sum(-1)`); the only write panics are `Add`/`Set` on a nil tree (no sane answer). No-op `Lock`/`Unlock` for twin parity. `fenwick_tree_ts` adds the RWMutex (nil guards before lock acquisition) plus real `Lock`/`Unlock` and `NlLen`/`NlSum`/`NlRangeSum`/`NlValue`/`NlAdd`/`NlSet` for atomic read-modify-write compounds. `thorough_test.go` cross-checks a naive prefix-sum slice at seed 42 over 3000 interleaved ops; `checkInvariants` verifies the internal array.
