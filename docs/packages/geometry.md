# geometry notes

`geometry` is the §9 geometry batch (backlog item 19): three immutable query objects over `g_lib.Point2D` — `GrahamScan` (algs4 GrahamScan.java: y-sort, STABLE polar sort around the base, pop-on-non-left-turn), `ClosestPair` (algs4 ClosestPair.java: x-sort + recursion + merge-by-y + the ≤7-point strip; coincident early-exit at 0; the per-recursion strip `aux` allocation is the algs4 shape — 131k allocs at n=100k, the constant-factor price of the faithful port), and `FarthestPair` (hull + rotating calipers; checks the parallel-edge TIE pairs `(v[i],v[j1])`/`(v[i+1],v[j1])` in addition to the algs4 antipodal pairs — tie-dense hulls like rectangles and cocircular sets need them; the brute-force oracle is the witness). Not the `geo` package. Hull: corner-only (collinear turns pop), ccw from the lowest-y-then-lowest-x point; all-collinear → the two endpoints; all-equal → one vertex; nil/empty → empty non-nil.

**Two float traps are load-bearing, both inherited from geo's FMA contracts.** (1) `g_lib.CCW`/`g_lib.Area2` pin their products unfused via `math.FMA(x, y, 0)` (round(x·y)): Go's permitted FMA contraction (even across statements, even differently at different inlined call sites) makes `CCW(a, b, b)` return the multiply's rounding error instead of exactly 0 on arm64 — observed in this package's own tests before the pin (a hull endpoint "strictly right of its own edge"); every degenerate decision (polar ties, collinear pops, calipers ties) corrupts with it. `DistanceSquaredTo` is pinned the same way for cross-call-site consistency (the farthest-pair oracle caught the fused/unfused 1-ulp split between an inlined `check` closure and the test's direct call). Do NOT rewrite these expressions. (2) The **stable polar sort** is required: collinear-with-base points compare equal under `PolarOrder`, and the all-collinear input needs the farthest point of the run at `points[n-1]` — Java's `Arrays.sort` is stable, `slices.SortFunc` is NOT (a naive port returns a wrong degenerate hull).

**The pop loop has a base-vertex guard** (`len(hull) >= 2`): exact arithmetic never reaches it (every scan point turns strictly ccw with the first-angle group's survivor), but nearly-collinear float noise inverts CCW's sign and cascade-pops below the base — where algs4 underflows its stack and throws. Pluto's contract (one panic class: NaN at construction, message naming the constructor) degrades instead. Test reality: `jarvisHull` (gift wrapping, farthest-on-collinear-tie) is the independent hull oracle with EXACT sequence equality — uniform random PCG 42/7, complete 5×5–7×7 integer grids, and INTEGER-line collinear-heavy sets (CCW exact there); the float-line variant is a separate NO-PANIC smoke test only (`TestGrahamScanNearlyCollinearNoPanic` — with CCW at noise level there is no "the" hull to agree on). Closest/Farthest oracles are O(n²) brute force with EXACT squared-distance equality (same pinned `DistanceSquaredTo` on both sides), over uniform, duplicate-heavy tiny grids, cocircular (tie storm), and collinear inputs. Benchmarks (M4 Max): hull uniform 122 µs/2.6 ms/34 ms at n=1k/10k/100k (cocircular — the max-hull worst case — is FASTER: 83 µs/1.0/9.6 ms, fewer pops and a friendlier comparator); ClosestPair 159 µs/3.6/29.6 ms vs brute force 2.1 ms at just n=2k (≈15× at equal n); FarthestPair tracks hull cost + a linear calipers pass. No `_ts` twin (immutable query objects; suffix_array precedent).
