# graph notes

`Graph` is Sedgwick's §4.1 undirected graph on int vertices `0..n-1` (`[][]int` adjacency; self-loops/parallel edges allowed — a self-loop counts once in `E`, twice in `Degree`; handshaking Σdeg = 2E is a checked invariant). The §4.1–4.2 algorithms are constructor-style query objects in the SAME package (`dfs.go`/`bfs.go`/`cc.go`/`cycle.go`/`twocolor.go`), not separate packages: `NewDFSPaths`/`NewBFSPaths` panic on a nil/empty graph or an out-of-range source (no sane answer), and their result objects are immutable snapshots — later `AddEdge` is not reflected. `NewCycle` (algs4 `Cycle`: self-loop scan → parallel-edge scan → DFS with the `w != u` parent check; cycle reported with the first vertex repeated at the end — `[v v]` self-loop, `[v w v]` parallel) and `NewTwoColor` (algs4 `TwoColor`: DFS 2-coloring, no short-circuit; `Color(v)` meaningful only when `IsBipartite`; a self-loop is an odd cycle — never bipartite — parallel edges an even one — never break bipartiteness) are source-less and tolerate nil/empty graphs like `NewCC`. BFS uses `pluto/queue` internally (intra-pluto composition). No `RemoveEdge` — deliberate, matching Sedgwick. `graph_ts` deep-copies the adjacency under the read lock (`snapshotAdj()`) and runs the traversals **lock-free on the snapshot** — no lock held during a traversal, unlike the Walk-holds-lock rule elsewhere; `Adj` yields a snapshot slice. The randomized model test (fixed seed 42) cross-checks BFS/CC against plain-map references — it must NOT import sibling pluto packages for the reference; `TestGraphCycleTwoColorModel` cross-checks Cycle (vs an incremental-union has-cycle oracle + a multiplicity-aware closed-walk certificate) and TwoColor (vs a BFS-coloring oracle + proper-coloring certificate).

The Eulerian batch adds `EulerianCycle` and `EulerianPath` (eulerian.go, algs4 `EulerianCycle`/`EulerianPath`, §4.1 exercises) — Hierholzer's iterative walk over a local shared-edge view. The view is the load-bearing port detail: an undirected edge must be *consumable exactly once across both endpoints' lists*, but pluto adjacency holds v-w in both `adj[v]` and `adj[w]`, so `buildEdgeView` makes ONE `ueEdge` object per AddEdge, referenced from exactly two list slots — for a self-loop, both slots are the same list (adj[v] holds a loop twice per AddEdge; the algs4 `selfLoops % 2` pairing takes one object per pair of entries), and the walk dedupes via the `used` flag while `e.other(v)` crosses. Parity gates (all even for a cycle; 0 or 2 odd for a path) run before the walk; the E+1 length check is the connectivity oracle (a disconnected-but-even graph's walk covers one component, so the check subsumes an explicit CC test — algs4 skips the CC call for the same reason). The path start is the first odd-degree vertex (paths begin/end at the odd pair), else the first edge-bearing vertex. E==0 → no walk (algs4 convention, documented). Tests verify by *certificate* — every consecutive pair consumes one real edge instance from a multiplicity-aware multiset (test-side self-loop count must be HALVED: `adj[v]` holds a loop twice) against textbook existence oracles (parity + CC connectivity) over 400 fixed-seed random graphs, plus curated degenerates (self-loop-only, parallel pair, K4's four odd vertices, two disjoint triangles, isolates mixed in).
