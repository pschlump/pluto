# bitmap notes

`bitmap` is the Redis bit-operation family as stateless pure functions over `[]byte` (request `note/09-bitmap-bitfield.md`, built for Ultima's SETBIT/GETBIT/BITCOUNT/BITPOS/BITOP/BITFIELD/BITFIELD_RO): `GetBit`/`SetBit`, `BitCount`, `BitPos`, `BitOpAnd`/`BitOpOr`/`BitOpXor` (longest-source length, shorter sources read as zero)/`BitOpNot`, and `ExecuteFieldOps` (the BITFIELD GET/SET/INCRBY engine with per-op `FieldOp{Kind, Signed, Bits, Offset, Value, Overflow}` — the `#<idx>` multiplier and the sticky OVERFLOW prefix state are resolved by the caller).  The mirrored C is `note/redis/src/bitops.c` — **this Redis (8.9.241) keeps ALL the bit commands in bitops.c; the note's `bitfield.c` pointer predates that layout**.  Bit order: bit 0 = MSB of byte 0 (big-endian bit stream); the C's worked example (5-bit field 23 at offset 7 → `0x01 0x70`) is pinned in `TestBitOrderPins`.  Non-generic (hyperloglog/union_find precedent), pure functions (geo/substring precedent), **no `_ts` twin** — safe for concurrent use as-is.  Layout: bitmap.go (doc/Unit/errors/limits/GetBit/SetBit), bitcount.go, bitpos.go, bitop.go, bitfield.go.

Contracts to preserve:

- **nil vs empty non-nil mean different things** (as they do to Redis): nil = missing key = an infinite zero array (`BitPos(nil, 0, …)` → bit 0); empty = empty string = zero-length range (`BitPos([]byte{}, 0, …)` → not-found).  `BitCount` cannot tell them apart (both 0).
- **`BitPos` takes an explicit `endGiven bool`** — load-bearing, not cosmetic: without an explicit end, a search for 0 on an all-ones buffer answers the first bit PAST the buffer (zero-pad convention, returned with found=true — Redis replies `len*8`); with one, not-found.  `found=false` ⟺ Redis's -1 reply, exactly.
- **SetBit/ExecuteFieldOps are `append()`-shaped**: in-place when no growth is needed (same backing slice), new zero-extended slice otherwise (input untouched); always use the returned buffer.  Reads never mutate.  Growth is capped by the Redis offset limit: `MaxBitOffset` = 2^32−1 (`offset>>3 < MaxBytes` = 512 MiB = proto-max-bulk-len) — the limit applies to every FieldOp offset (reads included, the `getBitOffsetFromArgument` rule) but plain `GetBit` never errors (pure read past end = 0).
- **ExecuteFieldOps validates the WHOLE op list before running anything** (as the command parses all subcommands first); on error the buffer returns unchanged with nil results.  A SET/INCRBY under OverflowFail marks `failed[i]` (result 0, nothing written) — but the pre-growth to the furthest write bit still happens, the C's strGrowSize behavior.  GET-only slices never grow (nil stays nil).  Field widths: signed 1..64, unsigned 1..63 — **u64 rejected, i64 allowed (the note's sketch reversed the two; the C is followed)** — results are int64.
- **The overflow checkers keep the C's strict inequalities** (a result landing exactly on a limit is NOT an overflow) and its exact WRAP/SAT arithmetic — two's-complement sign-extension wrap for signed, mask for unsigned.  Ported verbatim from `checkSigned/UnsignedBitfieldOverflow` including the wraparound-cast `maxincr`/`minincr` computations.
- **BitCount's both-negative-inverted early return is NOT redundant**: start and end both negative with start > end → 0 even when the clamps would select a nonempty range (`BitCount(\xff, -1, -4, ByteUnit)` = 0 on a 1-byte buffer, where clamping alone counts byte 0).  `bitposCommand` has no such check — the models encode the difference.
- **Word-wise hot paths, never bit loops**: BitCount popcounts 32 bytes/iteration via four `bits.OnesCount64` accumulators (redisPopcount's shape), BitOp folds 8-byte words, BitPos word-skips all-ones/all-zeros words (redisBitpos).  Redis 8's BITOP DIFF/DIFF1/ANDOR/ONE are out of scope (the note asks for the classic four).
- Panic contract: exactly 2 (`BitPos` bit ∉ {0,1}; `BitCount`/`BitPos` Unit ∉ {ByteUnit, BitUnit}), each naming the method.  Errors via errors.Is: `ErrBitValue`, `ErrBitOffset`, `ErrBitfieldType`, `ErrInvalidFieldOp`.

Tests: `vectors_test.go` freezes the Redis corpus (bitops.tcl's BITCOUNT vector/range/misaligned tables, the full BITPOS interval/unaligned/word-skip tables incl. the end-given distinction, BITOP zero-stream/zero-pad tables, bitfield.tcl's command sequences incl. #3221/#3564); `thorough_test.go` cross-checks against structurally different models — bit-domain per-bit oracles for the ranges (seed 42/7), the ported bitops.tcl joint BITPOS/BITCOUNT sweep (10-byte one-special-bit buffer, both units, four range shapes; **the TCL's `randomRange` is EXCLUSIVE of max — port the exclusive draw or clamp endbit to the last real bit**), the per-bit fold for BitOp + associativity/distributivity laws, and the two bitfield.tcl fuzz loops with exact big.Int oracles (FAIL refuses exactly when exact arithmetic leaves the field range; WRAP lands the field on the exact sum reduced into range).  The 512 MiB boundary test allocates for real — skipped under `-short`.  Benches (M4 Max): BitCount ≈ 39 GB/s (1 MB / 100 MB, 0 allocs), BitOpOr 2 ragged sources 7.8–10.3 GB/s, GetBit 0.25 ns, in-place SetBit 1.6 ns, ExecuteFieldOps 8 ops ≈ 198 ns.
