# merge_sort notes

`merge_sort` is Sedgwick's §2.2 Mergesort (algs4 `Merge`/`MergeBU`/`MergeX`) as stateless in-place slice sorts — the **stable** member of the pluto sort family (the property quick_sort/heap_sort/shell_sort all lack). `Sort[T cmp.Ordered](data []T)` / `SortFunc[T any](data []T, cmpFn func(a, b T) int)` are the top-down sort with two adopted algs4 `MergeX` improvements: an insertion-sort cutoff at ≤ 7 (`insertionCutoff`, the stable strictly-greater hoisted-value form) and the already-ordered skip (`cmpFn(data[mid], data[mid+1]) <= 0` → no merge); MergeX's swap-src/dst trick is deliberately NOT adopted (constant-factor complexity). **Stability lives in three places, all take-left-on-tie**: the merge takes the LEFT run's element on ties (right wins only when strictly smaller), the cutoff's insertion sort shifts only strictly-greater elements, and the ordered skip moves nothing. `SortBottomUp`/`SortBottomUpFunc` keep `MergeBU` plain (widths 1,2,4,…, `hi = min(lo+2*width-1, n-1)`, no cutoff/skip) — both variants are stable with the same tie rule, so identical input yields the identical permutation (asserted). `Inversions`/`InversionsFunc` count during the merge (each right-run take adds `mid - i + 1`) and return **int64** (100k reverse-sorted = 4,999,950,000 > int32); they sort a **private copy** — the input is never modified (algs4's `Inversions.java` mutates its argument; pluto purity). Panic contract: exactly 1 class (`SortFunc`/`SortBottomUpFunc`/`InversionsFunc` with nil cmp, each message naming its function); nil/empty/single slices are no-ops, `Inversions` of them is 0. O(n log₂ n) compares on every input — no adversarial shape — at the cost of one O(n) aux slice allocated per call. Stateless → no `_ts` twin (quick_sort precedent). The test centerpiece is the **stability oracle**: `checkStableOracle` in thorough_test.go compares the output EXACTLY (not multiset-equal) against `slices.SortStableFunc` on struct slices with small-range keys and unique satellite tags — run at `rand.NewPCG(42, 7)` over random sizes, sizes at/below the cutoff, and inputs crafted so equal keys span merge boundaries; `TestStableWitness` pins a small hand-traced permutation; `TestInversionsBruteForce` cross-checks the count against an O(n²) double loop; `TestInversionsBig` pins the int64 overflow case; `TestInversionsInputNotModified` pins the purity contract.
