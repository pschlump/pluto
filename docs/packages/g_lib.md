# g_lib notes

`g_lib` is the one non-data-structure package: pure generic utility functions (min/max, `Abs`/`Pow`, slice search/manipulation, set/map conversion, `Ptr`) — no state, everything safe for concurrent use, stdlib only (`cmp.Ordered`, `slices`, one `sort.Strings`, one `reflect.DeepEqual`).  `Ptr` is on the Go 1.26 `new(expr)` form (returns a pointer to a copy — mutating the source afterwards doesn't affect it), `InArray` delegates to `slices.Contains`, `SortSlice` uses `slices.Sort` (no closure), and `Pow` uses a range loop.  The numeric constraints are the trap: `Numeric`/`SignedInteger`/`SignedNumeric`/`Unsigned` use `~T` (defined types pass), but `Number` (math.go, used by `Pow`) lists exact types only — `type celsius float64` does **not** satisfy it (see `TestConstraintTypeSets`, which compiles every member of every set); `uintptr` is only in `Unsigned`.  Slice-returning functions never mutate their input (`RemoveAt` returns a fresh copy, or the input unchanged on out-of-range pos); `FormatSorted` (the set-capabilities helper every hash-family `String()` calls) sorts only the formatted strings — never the elements — so an unordered `T` is fine and two calls over the same elements in any order produce the identical `[a b c]` string (that determinism is its whole purpose: hash iteration order is seeded randomly per process).  Empty-input conventions (tested): `MinArray`/`MaxArray` → zero value of T; `Remove`/`RemoveComparable`/`Unique` → nil slice; `ToBoolMap` → empty **non-nil** map; `KeysForStringMap` → nil but `GetMapKeys` → empty non-nil.  `TestPropertyRandomizedFixedSeed` (seed 42) cross-checks against reference models; `example_test.go` has a runnable example for every function — map-key examples must sort before printing (map order is nondeterministic).  The tracked `*.go.txt` files (`array_has.go.txt`, `mingl.go.txt`) are gotip-era scratch experiments — leave them alone.  `point2d.go` adds the §1.2 **geometry value types** for kd_tree and the geometry package: `Point2D{X, Y float64}` (comparable — a legal map key, the kd_tree contract; `String` "(x, y)"; `DistanceSquaredTo`/`DistanceTo`) and `RectHV` (`Contains` boundary-inclusive, `Intersects`, per-axis-clamp `DistanceSquaredTo`); NaN tolerated everywhere (no panics, NaN never orders, NaN rects match nothing), inverted rects contain nothing, kd_tree uses ±Inf as the whole plane.  The geometry batch (2026-10-20) added the planar predicate surface — `CCW` (orientation sign), `Area2` (its raw magnitude), `CompareXY`/`CompareYX` (the algs4 X_/Y_ORDER), and the `PolarOrder()` comparator-closure method (the pluto idiom for Java's `Comparator`) — with the products of `CCW`/`Area2`/`DistanceSquaredTo` pinned UNFUSED via `math.FMA(x, y, 0)`, the geo contract: Go's permitted FMA contraction (even across statements, and differently at different inlined call sites) otherwise makes `CCW(a, b, b)` return the multiply's rounding error instead of 0 — observed on arm64 while testing the geometry package.  NaN still never panics here (`CCW` reports "collinear"); the geometry package's constructors reject NaN input instead.
