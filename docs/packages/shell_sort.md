# shell_sort notes

`shell_sort` is Sedgwick's §2.1 Shell as stateless in-place slice sorts: `Sort[T cmp.Ordered](data []T)` / `SortFunc[T any](data []T, cmpFn func(a, b T) int)` — the 3x+1 gap sequence (1, 4, 13, 40, ...; `for h < n/3 { h = 3*h + 1 }`, then `h /= 3` down to 1), each pass a gapped insertion sort written in the **hoisted-value form** (algs4 uses `exch` — same compares, fewer writes; quick_sort's insertion sort uses the same form; the algs4 trailing `isSorted` assertion is the test suite's job, not shipped code). NOT stable. O(n^{3/2}) worst with this sequence, ~O(n^{1.25}) empirical average (the exact average is a long-standing open problem), O(n log n) compares on already-sorted input; **fully iterative** — no recursion, no stack-depth story, no adversarial input shape (the gap schedule is input-independent, unlike quick_sort's pivot story). Panic contract: exactly 1 (`SortFunc` with nil cmp, naming the function); nil/empty/single slices are no-ops. Stateless → no `_ts` twin (quick_sort precedent). `TestGapBoundarySizes` sweeps the sizes where `n/3` crosses each gap (3, 12, 39, 120, 363, 1092, ...); `TestLargeAdversarial` (1M sorted / 250k reverse) pins correctness past the last gap transition the small tests reach; `thorough_test.go` cross-checks against `slices.Sort` (sortedness + permutation) at `rand.NewPCG(42, 7)` over ints (small range → duplicates), strings (small alphabet), structs with satellite data, and full-range int64 values.
