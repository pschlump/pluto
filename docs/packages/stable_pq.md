# stable_pq notes

`stable_pq.StablePQ[T any]` is the stable min-priority queue (backlog Tier-2 item 12; algs4 §2.4 ex. `StableMinPQ`): among equal keys the earliest-inserted pops first. Stability rides a **strictly increasing int64 stamp** on `spqItem[T]{key T, seq int64}` ordered lexicographically (key compare, then seq) on a `pluto/heap` (the huffman `huffItem`/priority_queue composition pattern) — the stamp survives `Truncate`, so refill order stays FIFO across a clear (asserted). `NewStablePQ[T cmp.Ordered]()` / `NewStablePQFunc(fx)`; reversed comparator = stable max-PQ (reversal applies to the key only — ties stay FIFO). Panic contract exactly 3 in the heap shape (`NewStablePQFunc(nil)`, `Insert` on nil or zero-value — no stamp is assignable, the lru capacity precedent). `All` drains a private snapshot copy in priority-then-FIFO order (the priority_queue.All pattern — safe to mutate from inside the loop); no-op `Lock`/`Unlock`. **No `_ts` twin, documented deliberate**: nothing is lock-contentious that a wrapper wouldn't solve, and the README points shared-queue callers at wrapping + RWMutex themselves. Tests: `TestRandomizedModel` (PCG 42,7, 4000 steps vs a (prio, insertion-seq) model with FULL All-order checks every 37 steps), `TestInterleavedTieGroups` (interleaved equal-key groups — uses a numeric-seq `seqTask`, never string tags: "18" < "8" lexicographically is the trap that bit the first draft), `TestStabilityWitness`/`TestStabilityLongTies` (500 equal), stability vs plain `priority_queue` (which must NOT be stable), max-via-reversal. Bench (README table): the stability tax is the 16-byte item + tie-break branch — 10–20% on Insert vs `priority_queue` (50.6 vs 43.5 µs / 4096 ties-heavy), ~0 on Pop.


**Phase-5 capabilities** (`capabilities.go`, plan §4.5 heaps/PQ menu): `Slice`, `String`/`StringFunc`, `Equal`, `Clone` — the minimal menu, no membership batches and no predicate delete.  `Slice`/`String` materialize in **(key, insertion) order** — `All`'s order, the exact `Pop` order — which for keys is sorted order and **deterministic even under ties** (2,1,2,1 inserts → `[1 1 2 2]`).  `Equal` is **key-multiset equality with the FIFO stamps deliberately IGNORED** (plan §4.5): the stamps are internal tie-breaking bookkeeping, not content — same multiset in any insertion order (different stamps) is equal; sort copies of the keys with the stored comparator, pairwise `cmp==0`, through the comparator **never Go's `==`**.  `Clone` copies `cmp`, the stamp counter AND the inner heap's `(key, seq)` items intact (the `All` snapshot-rebuild pattern — a total order, so the pop order is identical however the heap arranges them), so the clone's pop order (FIFO ties included) and its future stamps are the receiver's; **witness test**: `task`-typed queues drained receiver-vs-clone give identical tag sequences, and a post-clone insert on both sides interleaves identically.  All total functions (nil/zero-value → empty; zero-value Clone → fresh, still no heap, like the receiver).  Tests: `capabilities_test.go` (stamp-ignoring tie-heavy Equal, `[1 1 2]` vs `[1 2 2]`, reversed comparator, non-destructive, the FIFO-order clone drain, 800-step PCG(1,42) model vs `[]int` every 37 steps, shuffled-rebuild finish) and `capabilities_example_test.go` (5 examples; the Slice one shows `[1 1 2 2]` determinism).
