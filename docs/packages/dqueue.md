# dqueue notes

`dqueue.Deque[T any]` is the double-ended queue on a doubly linked list — pluto's own plain package, the lock-free original of `dqueue_ts`.  Like `stack_sll_ts` it is **self-contained**, not a wrapper over `dll`: pluto's `dll` requires an equality function at construction, a deque never compares, and the `prev` pointers make `PopBack`/`Backward` O(1) per step.  Constraint-free (`T any`, zero value usable, no constructors), value semantics (`PopFront`/`PopBack`/`PeekFront`/`PeekBack` return `(T, error)`), own `ErrEmptyDeque`, and exactly two panics: `PushFront`/`PushBack` on a nil deque.  `All` is front→back with index 0 at the front; `Backward` is back→front with indexes counting down from `Len()-1` so they match `All`'s assignment for the same element; both **walk the live list** (`All` via `next`, `Backward` via `prev` — O(1) extra space, no snapshot), so the deque must not be modified while an iterator runs (`TestIteratorReflectsLiveDeque` checks the contract inverted from the ts twin).  `checkLinks` in thorough_test.go verifies prev/next bidirectionality and head/tail/count consistency — call it after structural changes.

`dqueue_ts` is the twin with the `lock sync.RWMutex`: same struct plus the lock, nil guards before the lock acquisition, and its `All`/`Backward` copy an eager value **snapshot** at call time (its `snapshot()` walks the list under the read lock) instead of walking the live list — safe to mutate the deque from inside the loop (pluto's ts owns its own `ErrEmptyDeque`).  Race coverage lives in `TestDequeConcurrent`; its `checkLinks` reads internals without the lock — single-goroutine tests only.
