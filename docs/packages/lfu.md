# lfu notes

`lfu` is the Redis LFU eviction frequency counter (request `note/05-lfu-counter.md`, built for the Ultima `allkeys-lfu`/`volatile-lfu` policies and OBJECT FREQ; the LRU counterpart is `lru`). Two layers in one package: `MorrisCounter` (counter.go) — the standalone 8-bit logarithmic counter, **the exact `LFULogIncr` math mirrored from note/redis/src/evict.c** (increment iff `r < 1/((v-InitVal)·logFactor+1)` with the base value clamped at 0 below `InitVal` = 5, saturating at `MaxVal` = 255; logFactor ≤ 0 makes every increment certain, which is also the tests' deterministic path through the public API) with `Decay` (clamped subtract, `LFUDecrAndReturn`); and `Lfu[K comparable]` (lfu.go) — the keyed table storing `{counter uint8, lastMin uint16}` per key in a `hash_grow.HashTab` (intra-pluto composition; eq/hash read only the key field — the map-pattern precedent), one probe per op, auto-growing with the keyspace. `Touch` is `updateLFU` exactly: decay by `elapsedMinutes(now, lastMin)/decayTime` (integer division — only full periods), then the Morris increment, then retimestamp. **Decay is recomputed from elapsed time, never accumulated** — `Counter` reports the decay-adjusted view *without storing* (what OBJECT FREQ and eviction compare), so reads are pure. Touch of an unknown key is **Add-then-Touch** (the note's picked behavior — first-ever Touch returns `InitVal+1`); `Add` resets to `InitVal` (a Redis SET replaces the object). `elapsedMinutes` is `LFUTimeElapsed` mirrored exactly **including its wrap quirk** (`65535-ldt+now` — the boundary pair ldt=65535/now=0 reads as 0 elapsed, one less than real; do not "fix", eviction parity depends on it); the clock is minutes since epoch truncated to 16 bits, wrapping every ~45.5 days, so idle stretches past 65535 minutes are invisible — inherent to the design. Constructors: `NewLfu(logFactor, decayTimeMinutes)` (positional per house convention; `DefaultLogFactor` 10 / `DefaultDecayTime` 1 are Redis's config.c defaults) and `NewLfuWithClock` (injected `func() time.Time`, how every test gets determinism). Panic contract: 4 in the hash-family shape (nil clock, Touch/Add on nil, Touch/Add on zero-value); reads tolerate nil/zero. `Incr` draws from the **global math/rand/v2 source** (skip_list precedent — no per-counter RNG); `incrWithR(counter, logFactor, r)` is the pure deterministic core the seeded tests drive (PCG 42,7).

Tests (`thorough_test.go`): `TestCounterDistribution` gates trial means within max(2, 12%) of the fluid-limit ODE expectation `InitVal + (√(1+2ln)-1)/l` across 100..100k accesses (observed 9.73/19.37/49.88/146.94 vs 9.37/19.04/49.62/146.32 — and redis.conf's own printed table observes 18/142 at the same points); `TestCounterDivergence` is the note's paired-counter gate (same access pattern, independent draws: means agree within 4 s.e., individual trials diverge in the large majority); `TestHotColdSeparation` (deterministic at factor 0, ~10σ statistical at factor 10); `TestDecayExactSweep` (every counter × periods past the uint8 range — `decayed` must compare in int before narrowing); `TestLfuRandomizedModel` (4000 steps, seed 42, logFactor 0 → exact oracle with natural int64 arithmetic; the model clock never crosses the 65536 wrap — wrap is covered by `TestLfuClockWrap`/`TestElapsedMinutes` so the oracle stays arithmetic-independent). Benchmarks: Touch ≈41 ns/op 0-alloc, Counter ≈31 ns, MorrisIncr ≈4 ns, Add ≈105 ns (hash_grow growth amortized).

`lfu_ts` wraps `*lfu.Lfu` behind one RWMutex (stream_ts/hyperloglog_ts composition pattern — no locks inside the borrowed structure; the note's "favor simplicity" guidance: Ultima calls from shard owner-goroutines, low contention). Nil guards **before** lock acquisition; Touch/Add on nil or zero-value panic with `lfu_ts:`-prefixed messages (a zero value cannot fabricate logFactor/decayTime/clock — no lazy `ensure()` unlike constructor-free hyperloglog_ts). Aliases `MorrisCounter` + the constants. Real `Lock`/`Unlock` + the full `Nl*` mirror (`NlTouch`/`NlAdd`/`NlDelete`/`NlTruncate`/`NlCounter`/`NlIdleMinutes`/`NlLen`) — the eviction scan is the canonical compound (Lock + NlCounter over candidates + NlDelete coldest + Unlock, `ExampleLfu_Lock`). Race coverage in thorough_test.go: exact-count concurrent touch/read, add/delete present⟺Len agreement, Lock+Nl eviction racing writers. Plain lfu keeps no-op `Lock`/`Unlock`.


**String capabilities** (set-capabilities plan §4.6, phase 8 — the one capability the caches got): `String`/`StringFunc(format func(K) string)` render the KEYS only, and because an `Lfu` has no natural iteration order (the backing hash_grow table hashes with a per-table random seed) they follow the **hash-family sorted rule** — the FORMATTED key strings are sorted (`g_lib.FormatSorted`), lexicographic, so `"11" < "3"` and the output is identical across separately seeded tables (determinism pinned) and **clock-invariant**: `Counter`'s decay-adjusted view changes with time but String renders stored state, so an idle table renders unchanged hours later (pinned with an injected clock). Counters are not rendered — one call away (`Counter`), the tries' keys-only rule. nil/empty/zero-value table and a nil format render `[]`. `lfu_ts` renders byte-identically even though it walks its own first-insert `keys` list (the JSON bookkeeping copy) snapshotted under the read lock while the plain package walks hash slots — sorting erases the difference (parity test with reversed insertion orders); the format callback runs outside the lock (a `Touch`/`Add` from inside the callback is the unlocked-callback proof).
