# floyd_warshall notes

`floyd_warshall` is Sedgwick's §4.4 `FloydWarshall` — all-pairs shortest paths over `dijkstra.EdgeWeightedDigraph` with negative weights legal and negative cycles detected ANYWHERE in the graph (the structural difference from `bellman_ford`, whose source-rooted search only sees cycles reachable from s — FW finds a cycle in a component no candidate source reaches). Input is the adjacency-LIST graph (algs4 takes an adjacency-matrix digraph); the V×V `dist`/`edgeTo` matrices are built in the constructor: parallel edges collapse to the minimum per pair via the strict `<` (the matrix form cannot represent parallels at all), and a non-negative self-loop never beats the diagonal 0 — exactly algs4's self-loop reset, generalized; a negative self-loop survives and is an immediate cycle. `edgeTo` holds zero values for "no edge" (DirectedEdge is a value type): algs4's `edgeTo[v][i] == null` skip is `dist[v][i] == +Inf` here — equivalent, because a nil edgeTo entry always accompanies a +Inf distance except the (v,v) diagonal-0 case, and processing `i == v` there is a provable no-op (`0 + d < d` is false); a strict-`<` update never fires for `w == i`, so `edgeTo[i][i]`'s zero value can never be copied. On a negative diagonal the constructor returns EARLY with the matrices partially computed — queries panic then (algs4 throws UnsupportedOperationException), and `NegativeCycle` reconstructs from the frozen predecessor row: a stamped walk from the detection vertex v that records each visited vertex's position, so the rho-shaped tail is skipped exactly and the first revisited vertex is the cycle entry; the walk provably never dies out (every vertex it reaches is reachable from v and so has a predecessor edge, and v itself has one because its diagonal went negative). Panic contract: nil/empty graph, non-finite weight (NaN or ±Inf — negatives are legal, degenerate floats are not; a deliberate tightening over dijkstra's negative-only scan), and `Dist`/`HasPath`/`Path` after a negative cycle. Memory is the algorithm's price: O(V²) for both matrices (the `edgeTo` predecessor matrix is V×V `DirectedEdge` values, ~40 B/entry — document for large V). No epsilon anywhere (maxflow convention): integer-weight instances compare exactly. Test oracles: a super-source Bellman-Ford reference decides "negative cycle anywhere" (all-zero init; improvement in the n-th round means a cycle), per-source relax-everything produces the full matrix (exact on integers), the triangle inequality over all V³ triples is the self-contained optimality certificate, tinyEWD is cross-checked against `dijkstra.NewDijkstraAllPairsSP`, tinyEWDn against `bellman_ford` from every source, all at PCG 42/7 (both cycle/clean branches asserted to occur); the float test uses exact 1/8-multiple weights so sums stay exact in binary floating point. Benchmark reality (dense E ≈ 0.8·V²): 1.3 ms vs 1.9 ms (V=100), 10.2 vs 18.4 ms (V=250), 65.5 vs 108.7 ms (V=500) against V Dijkstras — Floyd-Warshall wins by 1.4–1.8× on dense graphs, is the only option with negative weights, and loses badly on sparse ones (its O(V³) is paid regardless of E). `floyd_warshall_ts` is the query-object twin over `dijkstra_ts.EdgeWeightedDigraph` (the `mst_ts`/`bellman_ford_ts` pattern): per-vertex `Adj` snapshots under the read lock (same per-vertex atomicity caveat — dijkstra_ts exports no whole-graph snapshot), then the O(V³) core runs lock-free; the query object is immutable with no-op `Lock`/`Unlock`, and the race hammer keeps writer weights non-negative so concurrent constructors never hand readers a panicking negative cycle.
