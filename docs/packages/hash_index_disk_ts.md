# hash_index_disk_ts notes

`hash_index_disk_ts` is the equality-only sibling of `b_tree_disk_ts`: the same disk machinery (block file, superblock + named-index registry, free list, LRU write-back cache with veto/pins/epochs, background flusher, journal + CRC recovery, `simulateCrash`), but the index is an **extendible hash** so a Search reads ONE directory block and ONE bucket block expected — no comparison descent. There is NO Compare and NO caller Hash anywhere: the hash is a frozen internal xxHash64 (seed 0, the hyperloglog precedent — changing it breaks on-disk compatibility), keys are identified by `bytes.Equal` of their encodings, and the ONLY caller contract is that `EncodeKey` is injective (a non-injective encoding silently collapses keys — documented, tested in `TestNonInjectiveEncoding`). The `hash` function lives in a struct field purely so tests can force 64-bit collisions (`TestDegenerateChains` overrides it under the lock; the store is then never reopened — its layout is only consistent under the override).

**Extendible-hash core.** A directory of 2^depth slots (slot = TOP depth bits: `h >> (64-depth)`, depth 0 → slot 0); each primary bucket stores localDepth d, every entry shares the top d hash bits, 2^(depth−d) slots point at one bucket. Split of a full bucket: `p := slot >> (depth - localDepth)` MUST be computed BEFORE any doubling (a doubling re-indexes every slot — the #1 trap); if `localDepth == depth` double the directory FIRST; then `nd := localDepth+1`, `span := 1 << (depth - nd)`, `base := p << (depth - localDepth)` with the POST-doubling depth; directory slots `[base, base+span)` keep the old bucket, `[base+span, base+2*span)` get the new one; the partition bit of each entry is `hash >> (63 - localDepth) & 1` (bit 1 moves — the same bit as slot bit `depth-localDepth-1`). The retry loop terminates because each split strictly raises the target bucket's local depth; the only keys that never separate are identical 64-bit hashes — guarded by an explicit `allSame` check (which includes the NEW key's hash) — plus the `maxDepth = 26` cap; both fall back to appending an overflow block to the chain.

**Directory doubling.** When the doubled directory still fits the same block count, the rewrite is IN PLACE, top-down: `for i := slots-1; i >= 1; i-- { set(i, get(i>>1)) }` — `i>>1 < i` so the source is never overwritten first. When the block count grows, the directory RELOCATES to a fresh contiguous run at the end of the file (`allocContiguous` — the free list cannot promise a run), the pointers are copied, the old run goes back through `freeBlock`, and the registry entry's dirStart/depth are updated. Deletes NEVER merge buckets or shrink the directory — the high-water-mark policy (the b_tree stale-separator precedent); only emptied OVERFLOW blocks are unlinked (tail relink) and freed.

**On-disk format.** Magic `"pluto-hx"`; superblock fields sbMagic/sbVersion=1/sbBlockSize/sbNumBlocks/sbFreeHead + 56-byte registry entries (name[32], dirStart, length, keySize u32, depth u32) — registry cap (BlockSize−32)/56. Block types: blkBucket=1, blkOverflow=2, blkDir=3. Bucket header 17 bytes (type, count u32, localDepth u32, overflow u64) then UNsorted (key ks, value 8) entries — unsorted because equality is the only comparison; maxEnt = (BlockSize−17)/(ks+8) (254 @ 4 KiB/8-byte keys vs the B+ tree's 255: two more header bytes buy the whole comparison descent away). Directory blocks: 8-byte header + 8-byte slots, (BlockSize−8)/8 per block.

**Eviction discipline** (the b_tree pin pitfall, adapted): never reference a clean unpinned block across another `cacheGet`. The patterns: re-fetch blocks BY NUMBER after intervening cacheGets (the insert `roomNo` path re-fetches before `bucketAppend`); `markDirty(primary)` BEFORE `fillBucketChain`'s allocations; gather split entries as COPIES before the allocations that rebuild the buckets; degenerate-chain append re-fetches the tail. `fillBucketChain` marks each block dirty before allocating the next.

**Corruption guards:** `dirGet` returns ErrCorrupt for a slot value of 0 (block 0 is the superblock, never a bucket); `checkBucketType` validates the type byte on every bucket/overflow load (primary expects blkBucket, chain blocks expect blkOverflow with depth 0).

**Durability, locking, JSON** are byte-for-byte the b_tree_disk_ts contracts: flush = journal batch → journal fsync → data writes → data fsync → journal truncate; one store mutex, reads take the WRITE lock (Search mutates the LRU — union_find_ts precedent); `MarshalJSON` sorts by encoded key bytes via an order permutation (hash_set String precedent — bucket order is not key order); `UnmarshalJSON` decodes and encodes keys BEFORE taking the lock and PANICS on nil/zero-value indexes when storing entries (insert family). NOTE the reentrancy trap fixed here: `collect` is split into a locking wrapper + `collectNoLock` — `UnmarshalJSON` holds the store lock and must snapshot through the noLock core (`sync.Mutex` is not reentrant; calling `collect` under the lock self-deadlocks — the first full-suite run caught exactly that).

**Test oracles.** checkInvariants verifies: routing (every entry's hash resolves at the global depth back to the primary it lives under), localDepth ≤ depth, slots sharing a bucket share the top-localDepth pattern, count ≤ maxEnt per block, chain types/depth-0/acyclicity, no duplicate keys, total == registry length. The model test is seed-42 PCG, 20000 ops over a 5000-key space, 512-byte blocks + 64-block cache, reopen cycles at 8000/14000 ops. Arithmetic that must not drift: maxEnt(512,8)=30, maxEnt(512,16)=20, maxEnt(4096,16)=169; slotsPerDirBlock(512)=63, (4096)=511; dirBlockCount(12)@512 = 66; 5000 keys @ 512 blocks forces depth ≥ 8 (2^7×30 = 3840 < 5000). Freeing does NOT shrink the file (freed blocks join the in-file free list — observe `freeHead`, not `numBlocks`), and "delete every third of n" removes ⌈n/3⌉ keys, not n/3 — count them, don't compute n−n/3.

No `_ts`-twin question arises: like `b_tree_disk_ts` the package IS the thread-safe form; there is no plain twin (the b_tree_disk_ts precedent).
