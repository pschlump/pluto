# patricia_trie notes

`PatriciaTrie[T any]` is Sedgwick's Patricia trie in the **crit-bit formulation** (keys live only at leaves; internal nodes carry just a bit index and two children) — chosen because Delete becomes a provable leaf-removal + unary-parent collapse and iteration is a plain in-order walk. Bit extraction uses an order-preserving prefix-free encoding (each byte → a `1` marker bit + its 8 bits MSB-first, end-of-key → a `0` bit) so prefix pairs like `"a"`/`"a\x00"` are unambiguous, `""` and `"\x00"` are ordinary keys, and iteration order equals byte-wise lexicographic with prefixes first. Constructor-free like `trie`/`tst`: zero value fully usable, the single panic is `Insert` on a nil receiver. n keys ⇒ n leaves + n−1 internal nodes, no unary internal nodes, bit indexes strictly increasing root→leaf; a full drain restores `root == nil`. `KeysWithPrefix` returns an ascending `[]string` (nil when none, mirroring `trie`); `All`/`Backward` are `iter.Seq2[string, T]` (the key takes the index slot).

The phase-3 set-convenience capabilities live in `capabilities.go`, mirroring `trie`'s method for method (the empty string is an ordinary key here, as in `trie` — only `tst` rejects it): `Keys` (literally `KeysWithPrefix("")`), `Values` (value side of `All`, index-aligned with `Keys`), `String`/`StringFunc` (keys only, bracket-space format, in-order walk = ascending — no sorting), `Equal` (**keys only** — the no-boxing rule; cross-family note: tst rejects the empty key that patricia/trie store, so cross-family Equal is meaningful only for non-empty key sets), `Clone` (recursive node-by-node deep copy of bit/key/value/children), `ContainsSlice`/`ContainsAny`, `DeleteSlice`. No batch insert; `Contains` already existed. All total functions — none panics.

`LongestPrefixOf(key) (string, T, bool)` (request `note/07-patricia-trie-ts.md`) walks the query's bit path: every stored prefix of the query hangs off that descent — at a branch where the query's bit is 1, the 0-side holds at most one candidate (the key ending at that bit = the subtree's leftmost leaf); the final leaf is tested last; deeper hits are longer. O(w) descent, O(w + h²) worst case. `KeysThatMatch(pattern)` is a Redis glob — the exact `stringmatchlen` (note/redis/src/util.c) port (`*`,`?`,`[abc]`,`[a-z]`,`[^…]`,`\x` escaping; **not** trie/tst's `.`-wildcard), implemented in match.go (`globMatchImpl` is an index-cursor port incl. the `skipLongerMatches` early-out and the 1000-nesting cutoff; `globLiteralPrefix` extracts the escape-resolved bytes before the first wildcard to prune the descent) returning a live-walk `iter.Seq2[string, T]`. C quirks pinned by tests: `\*` literal, trailing lone `\` literal, unterminated `[` runs to end of pattern (bare `[` matches nothing, unterminated `[^` matches any byte), `[]` is an empty class, `[a-]` is the range `]`..`a`, and `*` does **not** match the empty string (the C loop never runs on one — only the empty pattern matches `""`). The test oracle `refStringMatchLen` is a second, structurally different port (element-at-a-time recursion, no skipLonger/nesting) cross-checked against the package matcher on 20k random pattern/string pairs; binary-safe keys covered. `checkInvariants` in thorough_test.go — call it after structural changes; `TestPatriciaTrieRandomizedModel` (seed 42) also verifies LongestPrefixOf and KeysThatMatch against the model every 37 steps; `TestDeletePrefixSharedKeys` is the crit-bit delete bug farm (all {a,b}⁰⁻⁴ keys + NUL-suffixed variants, shuffled drain with per-delete structure checks). `bench_test.go` holds the `BenchmarkTable*` comparison vs `tst`/`trie` (1M random 16-byte keys; the R-way trie runs at 32k — ~30 GiB at 1M — its per-op costs are depth-bound so comparable); the measured table lives in README.adoc.

`patricia_trie_ts` is the twin (main file `patricia_trie_ts/patricia_trie.go`, per house naming) — the full self-contained copy of the plain package (including the glob matcher) behind one `sync.RWMutex`, following `trie_ts`/`tst_ts`: nil guards **before** lock acquisition, `Insert` panics with the `patricia_trie_ts:` prefix before locking, eager-snapshot `All`/`Backward`/`KeysThatMatch` (collected under the read lock at call time — `snapshotPairs()` is the shared collector; the plain package's iterators walk the live trie — contracts differ), `KeysWithPrefix` an eager slice by construction, `Dump` holding the read lock for the whole traversal, and the real `Lock`/`Unlock` plus `NlInsert`/`NlSearch`/`NlDelete`/`NlIsEmpty`/`NlLen`. It mirrors the capability menu with the twin lock discipline: `Keys`/`Values` snapshot under the read lock, `String`/`StringFunc`/`Equal` compute after the snapshot (format callback runs unlocked; `Equal` never holds two locks), one-lock batches with atomic `DeleteSlice`. The test suite is the plain package's ported in full (same seed-42 model test, same glob vectors/randomized oracle against the duplicated matcher) plus the ts-specific tests: `TestIteratorSnapshotSemantics`, `TestLockNlCompound`, the race trio `TestPatriciaTrieConcurrent`/`TestPatriciaTrieConcurrentDelete`/`TestPatriciaTrieConcurrentCompound`, and the capabilities concurrency block (`TestCapabilitiesConcurrent`/`BatchAtomicity`/`EqualNoDeadlock`).
