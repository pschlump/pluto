# hash_tab_bt notes

`HashTab[T any]` is the fixed-size hash table whose buckets are each a `*binary_tree.BinaryTree[T]` — the third intra-pluto composition after `priority_queue`/`heap` and `heap_sort`/`heap` (a bucket that is a search tree is exactly what `binary_tree` is).  Because the bucket is a tree, the element type needs an **ordering**, not just equality: two constructors — `NewHashTab[T interface{ cmp.Ordered; comparable }](n)` (orders with `binary_tree.Compare[T]`, hashes with `==`-consistent `maphash.Comparable` under a per-table random seed — the `& comparable` intersection exists only because `maphash.Comparable` demands it; every `cmp.Ordered` type is comparable) and `NewHashTabFunc(cmp func(a, b T) int, hash func(T) uint64, n)`.  Equality is derived — `cmp(a, b) == 0` — and the cmp+hash pair **must agree**: equal-comparing elements must hash equal, or Search/Delete look in the wrong bucket.  n buckets (n ≥ 5) fixed for the life of the table.  `Walk`/`All`/`Values`/`Dump` visit bucket order and, within a bucket, the tree's **in-order (ascending per cmp)** — the opposite of `hash_tab`'s newest-first chains — document, don't assert the combined order (random seed).  `Dump` shows no hash values (tree nodes keep none, unlike `hash_tab`'s `h=` lines).  Panic contract: exactly 4, identical in shape to `hash_tab`/`hash_grow` (`NewHashTabFunc` nil cmp or hash, `n < 5`, `Insert` on nil, `Insert` on zero-value); nil and zero-value tables tolerate every read.  The package drops the `Hashable`/`Stringer` hash priority, the no-op `WriteLock`/`ReadLock`, the `NlSearch`/`NlDelete` aliases, and `WalkFunc` (`Values` covers it); `Insert` returns bool, and `Walk` passes the **bucket index** as pos.  Complexity O(log(n/k)) average, O(n) worst (all keys in one bucket inserted sorted — `binary_tree` is unbalanced).  The pluto `hash_tab_bt_ts` twin exists — the README points shared-table callers at it.  `checkInvariants[T any]` in thorough_test.go uses the table's own `cmp`/`hash` to verify placement (bucketOf(hashOf(x)) == stored bucket), ascending in-order per bucket, Search hits every element, node count == `Len`, and `All`/tree agreement — call it after structural changes.

`hash_tab_bt_ts` is the twin with the `lock sync.RWMutex` — it keeps the plain `binary_tree` buckets and the one table lock guarding everything (no per-bucket locks); buckets are unexported and touched only while the lock is held.  Nil guards come **before** the lock acquisition, `All`/`Values` copy a **value snapshot at call time** under the read lock (value copies, as in hash_grow_ts/queue_ts/heap_ts), and `Walk`/`Dump` hold the read lock for the whole traversal so callbacks must not touch the table.  It exposes the **real `Lock`/`Unlock`** (nil no-ops) plus `NlIsEmpty`/`NlLen`/`NlSearch`/`NlInsert`/`NlDelete` for compound operations (`NlInsert` is the Insert body, so it carries the zero-value panic); calling a locked public method while holding `Lock` deadlocks.  Its `Walk` reads `length` only under the lock (never before acquiring it).  Race coverage lives in `TestConcurrentInsertSearchIterate`/`TestConcurrentDelete`/`TestConcurrentCompound` in thorough_test.go; `checkInvariants` there reads internals without the lock — single-goroutine tests only.
