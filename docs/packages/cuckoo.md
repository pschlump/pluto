# cuckoo notes

`HashTab[T any]` is the auto-growing **cuckoo** hash table — the sibling of `hash_grow`.  One 64-bit base hash per element (`NewHashTab[T comparable](n, growAt, shrinkAt)` uses `==` + a per-table random `maphash` seed; `NewHashTabFunc` takes the eq+hash pair, which must agree), **the full hash stored beside the element**, and four candidate positions derived by shift-and-mask: `h&mask`, `h>>1&mask`, `h>>2&mask`, `h>>3&mask` — so **table sizes are powers of two** (n rounds up, minimum 256, n<5 panics).  Search/Delete examine exactly 4 slots (hash pre-check then eq); Delete just clears the slot (no chain repair).  `Insert` displaces along a kick chain (`placeInto` with a rotating start index); a chain that exceeds `maxKicks` **rolls the table back** (first-writes recorded, restored on failure — a failed chain must not leave the item half-placed or drop a displaced element) and escalates through resizes.  Resizes: collision loop (sync, always), saturation > growAt after an insert (default 0.85), saturation < shrinkAt after a delete (default 0.10, halving, floor 256, best effort); thresholds configurable, <=0/NaN → default, shrink >= grow → both defaults, shrink clamped to ≤ grow/2 (hysteresis — a higher shrink threshold would oscillate the resize loop), and a grow threshold > 1 defers threshold growth (only collision loops grow).  `tryRebuild` re-derives positions from the **stored** hashes (no re-hashing) into a fresh array, swapping only on success; `resizeTo` escalates by doubling.  Empty slot = explicit `used` flag, so a hash of exactly 0 is legal (no remap, unlike `hash_grow`).  `Capacity()`/`Saturation()` report size and load.  Panic contract: the 4 hash_grow-shaped panics **plus one documented pathological panic** — hash funcs that make several distinct elements' candidates coincide at every table size (e.g. >4 elements on one hash) can never be separated and Insert panics after its resize attempts.  `checkInvariants` in thorough_test.go verifies stored-hash == re-hash, slot ∈ its hash's 4 candidates, occupancy == Len, and iterator agreement — call it after structural changes.

`cuckoo_ts` is the twin with the `lock sync.RWMutex` and the same internals, plus the **background resize machinery**: a collision-loop resize is synchronous inside Insert (the element must place before returning), but crossing a threshold (`spawnResize` from `NlInsert`/`NlDelete`, write lock held) starts a goroutine (`backgroundResize`) that takes the write lock itself, rebuilds via `resizeTo`/`tryRebuild`, and **re-checks the thresholds after each rebuild** before exiting; the `resizing` flag (guarded by the write lock) caps it at one goroutine per table — triggers detected under the lock and clears under the lock, so check-and-spawn is race-free without atomics.  The table is always valid between trigger and rebuild (merely saturated; a full table still inserts via the sync loop path).  `Truncate` makes the goroutine exit on its next check (desiredSize requires length > 0).  Real `Lock`/`Unlock` + `Nl*` (`NlIsEmpty`/`NlLen`/`NlSearch`/`NlInsert`/`NlDelete`) — a background resizer queues behind a held `Lock`, so don't hold it indefinitely.  Snapshot `All`/`Values`; `Walk`/`Dump` hold the read lock throughout.  Tests use the generic `waitQuiescent[T]` (polls `resizing` under Lock) before asserting capacity; ts `checkInvariants` takes the write lock itself (uses `NlSearch` inside) so it is safe even with a resizer in flight.

**Scan (both packages, note/11):** same generation-stamped cursor design as hash_grow (`scan.go` in each) — here reverse-binary is even less applicable: a cuckoo rebuild re-places every element into ANY of its 4 candidates, and so does an insert's displacement chain mid-generation, in either direction.  `generation` bumps in `tryRebuild` (successful rebuilds only — grow AND shrink) and `Truncate`; stale cursors restart at slot 0.  At-least-once coverage is exact for a frozen table and across rebuilds, best-effort under concurrent insert churn (kick-chain displacement can carry a present element across the cursor — documented; `TestScanTerminationUnderChurn` asserts bounded-step termination, the frozen/grow/shrink tests assert exact coverage, `TestScanDuringBackgroundResize` in cuckoo_ts runs the scanner against the background resizer under -race).
