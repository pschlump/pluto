# hash_tab notes

`HashTab[T any]` is the fixed-size chained hash table: n buckets (n ≥ 5) fixed for the life of the table — it never grows or re-hashes; point unknown-size callers at `hash_grow`.  Each bucket is a singly linked chain of self-contained `bucketNode[T]` (data by value + the raw hash kept for `Dump`) — **not** a wrapper over `sll`, for the `stack_sll_ts`/`dqueue_ts` self-contained rationale: the chain never uses sll's tail pointer or error API, and `Delete` splices the node out in one walk with a prev pointer.  `Insert` pushes at the chain head, so `Walk`/`All`/`Values` visit bucket order and, within a bucket, newest-first — document, don't assert.  `Insert` **replaces** an equal element and returns bool.  Two constructors (`NewHashTab[T comparable](n)` / `NewHashTabFunc(eq, hash func(T) uint64, n)`); `NewHashTab` uses `==` + a **per-table random `maphash` seed** (bucket order and `Dump` hashes nondeterministic — the tests' FNV `newTestTab` is used when placement matters), and the eq+hash pair **must agree**.  A hash of exactly 0 needs no remap (empty = nil chain, not a hash marker — unlike `hash_grow`).  Panic contract: exactly 4, identical in shape to `hash_grow` (`NewHashTabFunc` nil eq or hash, `n < 5`, `Insert` on nil, `Insert` on zero-value); nil and zero-value tables tolerate every read.  The `hash_tab_ts` twin exists — the README points shared-table callers at it (or `hash_grow_ts` when the size is unknown).  `checkInvariants[T comparable]` in thorough_test.go verifies node placement (hash % size == bucket index), node count == `Len`, Search hits every element, and `All`/chain agreement — call it after structural changes.
