# bag notes

`bag.Bag[T any]` is Sedgwick's §1.3 Bag — the constraint-free, constructor-free **add-only** collection (the queue/stack precedent: no ordering, no equality, zero value usable, single panic `Add` on a nil bag). Singly linked with head **and** tail pointers: `Add` appends at the tail, so `All` (`iter.Seq2[int, T]`) iterates in **insertion order** — the ResizingArrayBag convention, deliberately NOT algs4 LinkedBag's reverse iteration (an implementation artifact; document, don't copy). `Backward` collects the chain into a slice and yields it reversed (no back pointers — the skip_list `Backward` precedent, O(n) space), indexes counting down from `Len()-1` so they match `All`'s assignment for the same element. Also `Len` aliasing `Length`, `IsEmpty`, `Truncate`. Both iterators walk the **live** list (`TestIteratorReflectsLiveBag`). JSON follows the dll convention with one inverted nuance: the list encodes as a JSON array in `All` order, `UnmarshalJSON` decodes BEFORE mutating (a decode error leaves the bag untouched), `[]`/null clear and are tolerated — but unlike dll, unmarshaling non-empty data into a nil `*Bag` **struct field succeeds** (json allocates a usable zero value; only a direct call with elements on a nil receiver panics — `TestJSONStructField`). `checkLinks` in thorough_test.go (forward count == Length, walk ends at tail, `tail.next` nil) — call it after structural changes; `TestRandomizedAgainstModel` (PCG 42,7) cross-checks against a slice model.

`bag_ts` is the twin with the `lock sync.RWMutex` (own struct plus the lock, the queue_ts/dqueue_ts pattern — not a wrapper): nil guards **before** lock acquisition, `noLockAdd`/`noLockIsEmpty` internals, and `All`/`Backward` are **eager value snapshots at call time** (inverted contract — `TestIteratorSnapshotSemantics`). Like the container twins it exports no `Lock`/`Unlock`/`Nl*` (only the hash-family twins do). Race coverage: `TestBagConcurrent` (8 writers × 500 adds — every value lands exactly once, plus iterator goroutines), `TestBagConcurrentTruncate`, `TestBagConcurrentJSON`.

The phase-4 set-convenience capabilities live in `capabilities.go`, both packages: the **minimal §4.4 sequence menu only** — `Slice`/`String`/`StringFunc`/`Equal`/`Clone`; **no membership predicate and no batches** (a bag is a multiset, not a set — `Slice` keeps duplicates, and an O(n) `Contains` would be a footgun).  `Slice` yields **insertion order** (the `All` contract); `Equal` is the one **order-sensitive** `Equal` in pluto — the SAME multiset added in a different order is a different bag (pairwise `any(a) != any(b)`, comparable element type required, panics only when two elements are actually compared); `Clone` re-inserts via `Add` (tail append preserves insertion order; `checkLinks`-verified in the plain package).  Twin: `Slice` delegates to the `iter.go` `snapshot()` — **guard nil before calling it** (unlike `All`, `snapshot()` locks unconditionally); `Equal` snapshots each side separately, never two locks (`TestCapabilitiesEqualNoDeadlock`); `Clone` snapshots then rebuilds a local dup; format callbacks run outside the lock.  The add-only shape shows in the tests: the model mix is Add + occasional Truncate, and the rotation check is guarded with `slices.Equal` — an all-duplicates bag rotates to itself, which is legal.  All are total functions — no new panics.
