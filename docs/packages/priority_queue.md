# priority_queue notes

`PriorityQueue[T any]` composes `pluto/heap` (an intra-pluto composition, like `heap_sort` — legitimate here because the heap is exactly the building block, unlike the stack_sll_ts case): it stores the heap plus its **own copy of the comparison function** so `All` can build an ordered snapshot heap with the queue's ordering (the heap does not export its comparator).  Two constructors (`NewPriorityQueue[T cmp.Ordered]` / `NewPriorityQueueFunc`), value semantics (`Pop`/`Peek`/`Delete` return `(T, bool)`; `Search` returns `(T, pos, bool)` with `-1`), `UpdatePriority` = `heap.Fix` (returns bool), and `All` yields **priority order — genuinely sorted, unlike heap's `All`** — by draining a private snapshot copy (non-destructive, safe to mutate from inside the loop).  3-panic contract (`NewPriorityQueueFunc(nil)`, `Insert` on nil or zero-value); no-op `Lock`/`Unlock` kept.

`priority_queue_ts` composes `pluto/heap_ts` the same way (own comparator copy for the `All` snapshot): real `Lock`/`Unlock` delegating to the heap's, `Nl*` methods (`NlSearch` uses the queue's own comparator), and `All`'s snapshot is copied out under the heap's **write** lock then drained privately.  Search positions may be invalidated by concurrent mutation; `UpdatePriority`/`Delete` report `false` for a stale position — use `Lock` + `Nl*` for atomic search-then-update.

**Phase-5 capabilities** (`capabilities.go`, plan §4.5 heaps/PQ menu): `Slice`, `String`/`StringFunc`, `Equal`, `Clone` — the minimal menu, no membership batches and no predicate delete.  This is the **one §4.5 package whose Slice/String order is SORTED**: its `All` is genuinely sorted (priority order, minimum first — the JSON marshal's order), so `Slice` materializes via `All` (O(n log n); nil→nil, empty→empty-non-nil) and `String`/`StringFunc` render that order.  `Equal` is multiset equality but **without the SortFunc step the heap needs**: both sides' `Slice()` sequences come out already ordered by the comparator, so Equal is a length check plus a direct pairwise `cmp(a,b)==0` walk — ties safe by construction, comparator-based (never Go's `==`, non-comparable element types fine), consistent-comparator precondition documented.  `Clone` copies the queue's own `cmp` and delegates to `pq.h.Clone()` — the heap's backing-array copy preserves the exact layout and pop sequence (O(n)); a zero-value queue clones to a fresh zero value.  All total functions (nil→empty semantics; `Clone(nil)`→nil).  The `priority_queue_ts` twin mirrors with the lock discipline: `Slice`/`String` go through `All`'s snapshot (`StringFunc`'s format callback runs outside the lock), `Equal` snapshots each side sequentially (never two locks — deadlock-free in opposite directions), `Clone` delegates to `heap_ts.Clone`'s read-locked snapshot and local rebuild; no new `Nl*` (the capabilities are self-locking, not compounds).  Tests: `capabilities_test.go` (sorted-order Slice assertions, multiset Equal incl. `[1 1 2]` vs `[1 2 2]`, tie-heavy multisets, reversed-comparator consistency, non-destructive check, clone pop-sequence lockstep drain, 800-step PCG(1,42) model with `checkCapModel` every 37 steps, shuffled-rebuild-must-be-equal finish) and `capabilities_example_test.go`; the twin adds `TestCapabilitiesConcurrent` + `TestCapabilitiesEqualNoDeadlock`.
