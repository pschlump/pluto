# priority_queue notes

`PriorityQueue[T any]` composes `pluto/heap` (an intra-pluto composition, like `heap_sort` — legitimate here because the heap is exactly the building block, unlike the stack_sll_ts case): it stores the heap plus its **own copy of the comparison function** so `All` can build an ordered snapshot heap with the queue's ordering (the heap does not export its comparator).  Two constructors (`NewPriorityQueue[T cmp.Ordered]` / `NewPriorityQueueFunc`), value semantics (`Pop`/`Peek`/`Delete` return `(T, bool)`; `Search` returns `(T, pos, bool)` with `-1`), `UpdatePriority` = `heap.Fix` (returns bool), and `All` yields **priority order — genuinely sorted, unlike heap's `All`** — by draining a private snapshot copy (non-destructive, safe to mutate from inside the loop).  3-panic contract (`NewPriorityQueueFunc(nil)`, `Insert` on nil or zero-value); no-op `Lock`/`Unlock` kept.

`priority_queue_ts` composes `pluto/heap_ts` the same way (own comparator copy for the `All` snapshot): real `Lock`/`Unlock` delegating to the heap's, `Nl*` methods (`NlSearch` uses the queue's own comparator), and `All`'s snapshot is copied out under the heap's **write** lock then drained privately.  Search positions may be invalidated by concurrent mutation; `UpdatePriority`/`Delete` report `false` for a stale position — use `Lock` + `Nl*` for atomic search-then-update.
