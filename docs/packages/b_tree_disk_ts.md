# b_tree_disk_ts notes

`b_tree_disk_ts` is the production B-tree: a disk-backed, thread-safe **B+ tree** store where one data file is a random-access array of fixed-size blocks (default 4096 — one block = one OS-page-sized read; keys-per-block is COMPUTED from `blockSize/(keySize+8)`, ~255 entries for 8-byte keys, never hardcoded). Block 0 is the superblock: magic, blockSize, numBlocks, freeListHead, and a registry of named trees — one store hosts MULTIPLE B+ trees as indexes over the same data set (values are always `uint64` record offsets; keys are generic via caller `EncodeKey`/`DecodeKey`/`Compare` fixed-size functions). Leaves hold (key, value) sorted for binary search and are right-linked for ordered scans (`All`/`Range` are lock-held snapshots); internal blocks hold separators + child pointers. Separators may stay STALE after deletes (still valid bounds — the standard B+ simplification; the invariant checker verifies routing loosely, don't "fix" it). Emptied blocks chain onto a free list for reuse. The cache is pluto `lru.Lru[uint64, *cacheBlock]` with a veto (`dirty || flushing || pins > 0`) and a SOFT cap (it briefly exceeds capacity when nothing is evictable — a forced synchronous flush from inside `cacheGet` would orphan in-flight descent state or deadlock the flusher; do not "fix" this). A flusher goroutine (FlushInterval + half-dirty signal) snapshots dirty blocks under the store lock, then journals + writes + fsyncs WITHOUT the lock; per-block dirty epochs decide whether a re-dirtied block stays dirty. The journal (Path+".journal") is append-only whole-block redo batches — magic | seq | count | (blockNo + image)×n | crc32 (pluto `crc`, Castagnoli) | commit — fsynced BEFORE data writes; recovery on open replays valid committed batches, stops at the first bad magic/CRC/commit or torn tail, then truncates. Durability contract: ops are durable once `Sync()`/`Close()` returns; a crash never corrupts and never loses pre-flush state, but post-flush ops may vanish. Locking: one store mutex — reads take the WRITE path because the LRU mutates (union_find_ts precedent); IO errors are returned, programmer errors (nil funcs, KeySize ≤ 0, capacity) panic; after `Close`, ops return `ErrClosed`. Tests include `simulateCrash()` recovery tests (flusher stopped for a deterministic crash point — assert recovery restores exactly the last-Sync snapshot), torn-journal variants, and a 20k-op seed-42 model test with Sync/reopen cycles. Watch the eviction pitfall the suite guards: a clean unpinned block must never be referenced across a child `cacheGet` (it can be evicted; splits write into orphaned memory) — descent pins `cur`.
