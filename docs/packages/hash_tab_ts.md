# hash_tab_ts notes

`hash_tab_ts` is the twin with the `lock sync.RWMutex` — `hash_tab`'s chained buckets behind one table lock, following the `hash_grow_ts`/`hash_tab_bt_ts` pattern.  Nil guards come **before** the lock acquisition (a nil-receiver `lock.RLock()` would itself panic), `All`/`Values` copy a **value snapshot at call time** under the read lock (the plain package's iterators walk the live chains), and `Walk`/`Dump` hold the read lock for the whole traversal so callbacks must not touch the table.  `Delete` holds the write lock across the chain walk and the unlink (atomic search-and-delete, like `dll_ts`).  It exposes the **real `Lock`/`Unlock`** (nil no-ops) plus `NlIsEmpty`/`NlLen`/`NlSearch`/`NlInsert`/`NlDelete` for compound operations (`NlInsert` is the Insert body, so it carries the zero-value panic); calling a locked public method while holding `Lock` deadlocks.  Race coverage lives in `TestConcurrentInsertSearchIterate`/`TestConcurrentDelete`/`TestConcurrentCompound` in thorough_test.go; `checkInvariants` there reads internals without the lock — single-goroutine tests only.

`capabilities.go` mirrors hash_tab's method for method (same names, same semantics; `capabilities_test.go` is the plain package's file verbatim plus the twin-only tests at the bottom).  Lock discipline, per the plan: mutating batches (`InsertSlice`/`InsertIter`/`DeleteSlice`) take the **write lock once for the whole batch** — atomic, all-or-nothing (`TestCapabilitiesBatchAtomicity` polls `Len` while a 5000-element batch runs and asserts only the pre/post sizes are ever observed); `DeleteFunc` snapshots under RLock, runs the caller predicate **with no lock held** (call-backs legal, tested), then deletes the matches under one write lock; `Slice`/`String`/`StringFunc` snapshot under RLock and compute unlocked (`StringFunc`'s format may call back into the table); `Equal`/the read batches never hold two locks — `Equal` snapshots the receiver then `Contains`es against the operand one element at a time, so comparing the same pair in opposite directions from two goroutines cannot deadlock (tested).  `ContainsSlice`/`ContainsAny` hold RLock once around the whole batch via `nlContains` (over `NlSearch`).  **No new `Nl*` methods** — the capabilities are self-locking, not compounds.  `insertContractCheck` panics name the actual method (`InsertSlice`/`InsertIter`) with the `hash_tab_ts:` prefix, and fire only when an element would actually be stored.
