# fib_heap notes

`fib_heap.IndexFibonacciPQ[T any]` is the indexed Fibonacci priority queue (backlog §3.9; Fredman–Tarjan, algs4 §9 `IndexFibonacciMinPQ`, CLRS ch. 19) — `index_pq`'s full API on the decrease-key-optimized structure: circular doubly-linked root list + min pointer, nodes `{value, index, parent, child, left, right, degree, mark}` with `nodes []*fibNode` as the index→node map (index_pq's `qp` equivalent), lazy O(1) `Insert` (ring splice only), `Pop` = extract-min (promote children, **consolidate** same-degree roots, recompute min), decrease = `cut` + `cascadingCut` (mark bits) + min update, increase-direction `Change` = **extract + re-insert with the new value** (the CLRS delete-then-insert trick — one `extract` routine is the removal machinery for `Pop`, `Delete`, AND increase-`Change`; no subtree-dissolve code). Plus `DecreaseKey(k, v) bool` beyond index_pq's surface: refuses (false, no change) a v that does not order strictly before the current value — the Dijkstra/Prim shape (algs4 parity; also nil/zero-value-tolerant like `Delete`). Panic contract: exactly index_pq's 4 with `fib_heap:` prefixes. No `Lock`/`Unlock`, **no `_ts` twin** (binomial_queue precedent, documented in README + root README: the amortized single-threaded decrease-key is the point, a global lock would erase it — shared callers go to `index_pq_ts`).

**Ties poison a mirror oracle**: when two indices hold equal minimum values, `Pop` may legally return either — after that the two structures hold different index sets and every presence-sensitive op diverges. The model test (`TestIndexFibonacciPQRandomizedModel`, PCG 42,7, 4000 steps, every return value cross-checked against pluto `index_pq` as oracle + a map ground-truth) therefore draws values from a wide range (no ties) so Pop/Peek indices are deterministic and the mirror is exact; ties are covered separately by `TestTies` against the map oracle only. `checkInvariants` in thorough_test.go verifies ring bidirectionality, parent pointers, heap order, degree == child count, roots unmarked, min is the minimum root, nodes/length agreement, and the **Fibonacci size lemma** (degree-d node roots ≥ F(d+2) nodes — the log_φ degree bound that makes Pop O(log n)) — call it after structural changes. Consolidate reuses `scratchRoots`/`scratchTable` grown on demand (cleared after use so scratch does not pin removed subtrees) — Pop is 0-alloc steady state.

Benchmark reality (M4 Max, in README): `DecreaseKey` 5.7 ns vs `index_pq.Change` 31.5 ns — the amortized O(1) is real — but Insert (1 node alloc), Pop (consolidation constants) and the dense-graph Dijkstra driver all LOSE to the binary heap at practical sizes (1.22× at V=400, 1.11× at V=1500 — asymptotics favor fib, constants don't; the textbook's own caveat). Document, don't hide.


**Phase-5 capabilities** (`capabilities.go`, plan §4.5 heaps/PQ menu): `Slice`, `String`/`StringFunc`, `Equal`, `Clone` — the minimal menu, no membership batches and no predicate delete.  `Slice`/`String` materialize the **values in priority order** (minimum first — `All`'s snapshot-drain order, the order `Pop` would produce); pair values with indices via `All` directly.  `Equal` is the **map-shaped exception** within §4.5: it compares the **index→value bindings** (same Len + every present index holds a value with `cmp(a,b)==0` — never Go's `==`, non-comparable value types fine), NOT the value multiset — swapping the values of two present indices keeps the multiset but changes the content, so those queues are NOT equal (swap-tested both directions).  Preconditions: consistent comparison functions (skip_list wording).  `Clone` = the private `clone()` All already uses, nil-guarded — same index space `n`, same `cmp`, same bindings; forest shape may differ (unobservable).  All total functions (nil/zero-value → empty reads; `Clone(nil)`→nil; `Insert` still panics on nil/zero-value — the capabilities never write).  Tests: `capabilities_test.go` (binding Equal incl. the swap + different-index-set cases, non-destructive check, clone index-space preservation, 800-step PCG(1,42) model vs `map[int]int` over the full indexed op mix — Insert/Change/DecreaseKey/Delete/Pop/Peek/Truncate — with **wide values `IntN(100000)`** per this file's ties-poison-oracles warning, Pop checked by min VALUE not index, `checkInvariants`+`checkCapModel` every 37 steps, shuffled-rebuild-must-be-equal finish) and `capabilities_example_test.go` (5 examples, the Equal one demonstrating the swap).
