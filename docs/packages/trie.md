# trie notes

`Trie[T any]` is Sedgwick's §5.4 TrieST — a byte-oriented R-way trie (R=256, arbitrary UTF-8 keys, empty key stored at the root) string-keyed symbol table. Like `queue`/`stack` it is **constructor-free**: no comparison function exists (ordering is inherent in key bytes), so the zero value is fully usable and the only panic is `Insert` on a nil `*Trie`. `Insert` returns added-vs-replaced bool (the trees' duplicates-replace convention); `Delete` prunes childless value-less nodes on the way back up. `All` is `iter.Seq2[string, T]` in ascending key order over the **live** trie (a single-variable range yields the KEY — it is `Seq2[string, T]`, so `for k, v := range` works naturally); `KeysWithPrefix`/`KeysThatMatch` (`.` = any one byte) return ascending `[]string`, nil when none. The `[256]*trieNode[T]` children array is the documented memory trade-off (2 KiB/node) — point memory-sensitive callers at `tst`.

The phase-3 set-convenience capabilities live in `capabilities.go`: the tries ARE pluto's string sets, so they get the go-set ergonomics directly — `Keys` (literally `KeysWithPrefix("")`), `Values` (the value side of `All`, index-aligned with `Keys`), `String`/`StringFunc` (keys only, bracket-space format, byte order — deterministic with no sorting), `Equal` (**keys only** — values are `T any`, comparison not expressible without boxing; no `EqualKeys` alias; note trie stores the empty key at the root while tst rejects it, so cross-family Equal is meaningful only for non-empty key sets), `Clone` (recursive node-by-node deep copy — the fresh 2 KiB arrays' unused slots stay unallocated, no memcpy), `ContainsSlice`/`ContainsAny` and `DeleteSlice` over keys. No batch insert (map-shaped — callers loop); `Contains` already existed. All total functions: none panics, nil/zero-value behave as empty.

`trie_ts` is the twin: `lock sync.RWMutex` on the same struct, nil guards before lock acquisition, eager snapshot `All`/`KeysWithPrefix`/`KeysThatMatch` (collected under the read lock, safe to mutate from inside the loop), real `Lock`/`Unlock` + `NlIsEmpty`/`NlLen`/`NlSearch`/`NlInsert`/`NlDelete`, panic message prefixed `trie_ts:`. The twin mirrors the capability menu with the twin lock discipline: `Keys`/`Values`/`Slice`-shaped reads snapshot under the read lock, `String`/`StringFunc`/`Equal` compute after the snapshot (the format function runs unlocked; `Equal` snapshots one side and probes the other key by key so it never holds two locks), `DeleteSlice` and the batches hold one lock for the whole batch. Race coverage: `TestTrieConcurrent`/`TestTrieConcurrentDelete`/`TestTrieConcurrentCompound` plus the capabilities concurrency block; `checkInvariants` reads internals without the lock — single-goroutine tests only.
