# trie notes

`Trie[T any]` is Sedgwick's §5.4 TrieST — a byte-oriented R-way trie (R=256, arbitrary UTF-8 keys, empty key stored at the root) string-keyed symbol table. Like `queue`/`stack` it is **constructor-free**: no comparison function exists (ordering is inherent in key bytes), so the zero value is fully usable and the only panic is `Insert` on a nil `*Trie`. `Insert` returns added-vs-replaced bool (the trees' duplicates-replace convention); `Delete` prunes childless value-less nodes on the way back up. `All` is `iter.Seq2[string, T]` in ascending key order over the **live** trie (a single-variable range yields the KEY — it is `Seq2[string, T]`, so `for k, v := range` works naturally); `KeysWithPrefix`/`KeysThatMatch` (`.` = any one byte) return ascending `[]string`, nil when none. The `[256]*trieNode[T]` children array is the documented memory trade-off (2 KiB/node) — point memory-sensitive callers at `tst`. `trie_ts` is the twin: `lock sync.RWMutex` on the same struct, nil guards before lock acquisition, eager snapshot `All`/`KeysWithPrefix`/`KeysThatMatch` (collected under the read lock, safe to mutate from inside the loop), real `Lock`/`Unlock` + `NlIsEmpty`/`NlLen`/`NlSearch`/`NlInsert`/`NlDelete`, panic message prefixed `trie_ts:`. Race coverage: `TestTrieConcurrent`/`TestTrieConcurrentDelete`/`TestTrieConcurrentCompound`; `checkInvariants` reads internals without the lock — single-goroutine tests only.
