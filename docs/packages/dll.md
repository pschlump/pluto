# dll notes

`Dll[T any]` is the equality-based sibling of the trees: `NewDll[T comparable]()` compares with `==` (zero boxing), `NewDllFunc` takes an equality function, and the stored `eq` is consulted **only** by `Search`/`ReverseSearch` and the `Delete` calls built on them — stack/queue/positional ops never compare.  Unlike the trees, dll has an **error-based** API (`ErrEmptyDll`, `ErrNotFound`, `ErrOutOfRange`, `ErrInternalDll`; compare with `errors.Is`) — errors, not panics, report empty/not-found/out-of-range.  The panic contract covers only the insert family: `InsertBeforeHead`, `Push`, `AppendAtTail`, `Enqueue`, `Concat` (only when the source has elements), `UnmarshalJSON` (when the data holds elements) panic on nil or zero-value lists.  Two opposite-of-the-trees conventions to preserve: `Walk`/`ReverseWalk` callbacks return **true to stop**, and `Search` returns `(*DllElement, pos)` with a `-1` sentinel rather than `(T, bool)` (the element is needed for `DeleteFound`/`Current`).  `DllIter` (Front/Rear/Current) walks both directions with `Pos()`.  `MarshalJSON`/`UnmarshalJSON` (json.go) implement the json interfaces: the list encodes as a JSON array of its elements head→tail (`[]` for empty and for a direct nil call; `json.Marshal` on a nil `*Dll` itself writes `null`), `UnmarshalJSON` decodes `[]T` first (a decode error leaves the list untouched) then **replaces** the contents and keeps `eq` — `[]`/`null` clear and are tolerated on nil/zero-value (the Concat precedent), and for a nil `*Dll` struct field `json.Unmarshal` allocates a zero-value list, so non-empty data hits the insert panic (create the list with `NewDll` first).  `checkList` in thorough_test.go verifies link bidirectionality and head/tail consistency — call it after structural changes.

`dll_ts` adds the `lock sync.RWMutex` and `noLock*` lock-free internals; `Delete` holds the write lock across its search (atomic search-and-delete), `Concat` snapshots the source under the source's lock first, and `Lock`/`Unlock` are the **real** exposed write lock (no-ops in plain dll).  Its legacy `DllIter` walks the live list — each method takes the list's read lock per call plus the iterator's own `iterLock` — unlike the snapshot `All`/`Backward`.  `All`/`Backward` are `iter.Seq2[int, T]`: a single-variable range yields the INDEX, not the value (use `for i, v := range`).  Its `MarshalJSON`/`UnmarshalJSON` mirror dll's with the lock rules: `MarshalJSON` snapshots under the read lock and encodes unlocked; `UnmarshalJSON` decodes **before** the lock (element-level unmarshalers must not run under it), checks the nil/eq guards before acquiring it, then replaces the contents under one write-lock hold via `noLockAppendAtTail`.
