# zstd notes

`zstd` is the Zstandard format (RFC 8878): `Compress`/`Expand` plus the streaming `NewReader`/`NewWriter`. Decode is complete (every zstd(1) output); encode writes legal *stored* frames — raw blocks, 128 KiB window, no checksum. Structured as `zstd.go` (frame loop + stored writer), `bitreader.go` (backward entropy reader, forward LSB-first description reader), `fse.go` (table build, normalized-count header, predefined distributions, sequence code tables), `huffman.go` (weights, flat table, stream decode), `block.go` (literals section, sequences, execution), `xxhash.go` (the content checksum), `stream.go`.

## The wire facts that bit

- **A forward bit reader that under-fills mid-loop corrupts silently.** The FSE normalized-count header is a forward LSB-first stream of small fields; a zero-run is a chain of 2-bit repeat fields and can consume 40+ bits without touching the loop head that refilled the accumulator. The first cut reloaded once per outer iteration, so a long run read stale accumulator bits and mis-parsed the distribution (a `[127, 0…, 1]` ML table became 42 symbols/6 bytes instead of 51/7). Symptom downstream: FSE states drift among same-symbol cells for dozens of sequences, then one symbol flips — the first content mismatch lands far from the actual divergence. `peek` now loads lazily; `consumed` counts bits, not loaded bytes.
- **A compressed block's header size is its compressed size.** The 21-bit field bounds the on-disk bytes for raw and compressed blocks but is the *regenerated* size for RLE. Passing the header field as the expected output length of a compressed block fails every nonempty stream; the regenerated size is derived, bounded only by Block_Maximum_Size.
- **The checksum covers regenerated bytes.** Feed the XXH64 each block's decoded output, not `out[last N]` with the block-header size (the first cut checksummed 59 bytes of a 2045-byte block).
- **The Huffman header byte's sense is inverted from intuition**: ≥128 is the *direct* 4-bit-weights form (count = byte−127); <128 is the FSE-compressed form (byte = stream length). Getting this backwards still decodes many streams — small alphabets often parse either way — and dies on real ones.
- **The Huffman weights header byte bounds the whole FSE payload** — table description AND bitstream together; the consumed size is 1+headerByte. The first cut read 1+desc+headerByte, which pointed the jump table four bytes early and made every stream size after it garbage. Found decoding libarchive (bsdtar --zstd); the zstd(1) goldens never saw it because the CLI writes direct 4-bit weights for these alphabets.
- **The canonical Huffman fill places each symbol at val rounded down to its shift boundary** (code = val>>shift, base = code<<shift). A literal  scatters symbols past the table; verified against RFC 8878 Table 25's weights [4,3,2,0,1] → 0000/0001/001/01/1.
- **`-T0` makes zstd(1) nondeterministic.** The multithreaded CLI changes framing between runs on the same input; every golden must use `-T1`. Two "identical" probes disagreeing on leftover bits was this, not the format.
- **The last sequence reads no state updates** (RFC 8878 §3.1.1.3.2.1.2); init order is LL→OF→ML, extra-bits order OF→ML→LL, update order LL→ML→OF. A leftover-bits theory blaming a "delayed encoder tail" was a red herring from the two bugs above — fixed, streams end exactly.
- **zstd's OF table base is pre-resolved**: baseValue(code≥2) = (1<<code)−3, and code 0/1 take the repeat-code paths (code 1 adds the ll==0 shift into the value). Equivalent to the RFC's `Offset_Value = (1<<code)+bits` then `offset = value−3`, but worth knowing when reading the C.
- **The descriptor byte's unused bit must be zero but the reserved bit must be *rejected*** (RFC differs); both are checked.
- **`binary.LittleEndian.Uint32` on a short dictionary-ID slice panics** — the DID field is 1, 2, or 4 bytes; read it by width. Found by the corruption sweep, not by hand.
- **XXH64's mergeRound has no rotation** (`acc ^= v; acc = acc·P1 + P4`) — the `rotl 27` belongs to XXH32's merge. The zero/short vectors pass either way; the ≥32-byte path diverges.

## Stored-frame shape (the encoder's contract)

Magic, descriptor `0x00` (no FCS, no checksum), window `0x38` (exponent 7 → 128 KiB, so Block_Maximum_Size = 128 KiB), then raw blocks of ≤128 KiB (3-byte header: `size<<3 | 0`, last block `|1`), the final block possibly empty. Empty input is one empty last block — 9 bytes total, pinned in the test.

## Streaming shape

The reader pulls input through an 8 KiB fill, parses frame headers (up to 18 bytes) and block headers as they arrive, and decodes whole blocks — the format's own streaming unit. The decoded buffer doubles as match history: inside a frame only `len − window` bytes are deliverable; at a frame boundary everything is. Frame entropy state (Huffman table, FSE tables, repeat offsets) resets per frame. A clean exhaustion of input at a frame boundary is io.EOF, not corruption.

## Tests

`zstd_test.go`: corpus round trips; system goldens (levels `-1`..`-19`, `-22`, `--long=25`, `--check`; `-22` skipped where the CLI refuses tiny inputs); system reads ours; concat + skippable; malformed vectors, every-prefix sweep, and a 3,000-case corruption sweep; the empty-frame byte shape. `stream_test.go`: byte-at-a-time golden reads; multi-frame with checksum + skippable; sticky EOF; truncation sweep; writer round trip incl. empty and after-close; zstd(1) decodes our streamed output.

Interop reality (Nov 2026, zstd 1.5.7): all CLI presets decode byte-exact; `zstd -t`/`-dc` verify our stored frames both directions.
