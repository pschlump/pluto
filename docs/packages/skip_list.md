# skip_list notes

`SkipList[T any]` is a lean API like `rb_tree` (no `Index`/`Walk*`/`Front`/set ops): insert/search/delete, `FindMin`/`FindMax` (O(1)/O(log n)), `DeleteAtHead`/`DeleteAtTail`, `Truncate`, per-level `Dump`, and `All`/`Backward` — plus the **span-annotated positional/range family** (Redis `zskiplist` lineage, for the Ultima ZSET commands): `Rank`/`AtIndex` (exact-match 0-based rank and its inverse), `Ceil`/`Floor`, `CountRange`, `Range`/`RangeBackward`, `DeleteRange`/`DeleteByRank`.  Every forward pointer carries a `span` — the number of level-0 nodes in `(node, forward[i]]`, with a nil forward counting the remaining nodes, so **spans along any level sum to Length()** — maintained by Insert (`findPathRank` fills caller-allocated `update`/`rank` arrays, which stay stack-allocated), Delete, DeleteAtHead (span-aware head copy), and `spliceOut` (the shared O(log n + m) bulk-unlink for both delete-by-range and delete-by-rank; per level it walks that level's chain across the run because the run's *last* node differs per level).  `Range`/`RangeBackward` are `iter.Seq2[int, T]` yielding the element's **global 0-based rank** (the index `All` would assign; `RangeBackward` counts down through the same indexes) and walk the live nodes like `All`.  Nodes hold a variable-length `forward` slice (towers, max 32 levels, p=0.5) drawn from the **global** `math/rand/v2` source — there is no per-list RNG, so outputs that depend on tower heights (the `level` field, `Dump` line counts) are nondeterministic and must not appear in example outputs or fixed assertions.  `Backward` collects the level-0 chain into a slice (no back pointers, O(n) space); `All` walks the chain in O(1) space.  `checkInvariant` in thorough_test.go verifies the structural invariants (level-0 count == Length, every level strictly ascending, head.forward non-nil exactly below `level`, no tower taller than `level`, **span lengths == forward lengths, per-level span sums == Length, every non-nil link span ≥ 1**) — call it after structural changes; `TestRankRangeRandomizedOracle` (fixed seed, 10k ops) cross-checks the whole new family against a sorted-slice oracle, and the Insert/Search/Delete benchmarks gate span overhead at 5%.

`skip_list_ts` adds the `lock sync.RWMutex`; its unexported helpers (`ensureHead`, `findPath`, `findPathRank`, `isEmpty`, `deleteLocked`, `toSlice`, `spliceOut`) are the lock-free internals that the locked public methods call.  It mirrors the whole positional/range family, plus the **real `Lock`/`Unlock`** and `Nl*` no-lock variants (`NlIsEmpty`, `NlLen`, `NlRank`, `NlAtIndex`, `NlCeil`, `NlFloor`, `NlCountRange`, `NlDeleteRange`, `NlDeleteByRank`) for atomic compounds such as rank-then-delete (iterators get no `Nl*` forms — a lock cannot be held across their consumption).  Unlike the plain package's live-walk `Range`, its `Range`/`RangeBackward` **snapshot only the m elements of the range** under the read lock at call time (the `All`/`Backward` snapshot convention, at O(log n + m) cost), so mutating during iteration is safe.  It mirrors the capability menu too (`capabilities.go`, messages say `skip_list_ts:`; `Slice` = `toSlice`, which returns nil for any empty list — the plain package's drained-sentinel empty slice differs); twin lock discipline as usual: batch mutators atomic under one write-lock hold (the delete loop guards `isEmpty` before each `deleteLocked`, whose contract requires a non-empty list), compute-after-snapshot for `Slice`/`String`/`Equal`/`DeleteFunc`'s match pass (predicate unlocked, may call back), `Equal` never two locks, `nlContains` added for the membership batches, `Clone` = RLock snapshot + unlocked re-insertion into the local copy.

The phase-2 set-convenience capabilities live in `capabilities.go`: `Contains`/`ContainsSlice`/`ContainsAny`, `InsertSlice`/`InsertIter`/`DeleteSlice`/`DeleteFunc`, `Slice`/`String`/`StringFunc`/`Equal`/`Clone`. The shared `insertContractCheck(caller)` + `insertAll` pair carries the insert panic contract to the batch inserters (panic only when a batch would store; empty batch tolerated); the messages say "nil list", mirroring `Insert`. `Slice` walks the level-0 lane directly (ascending, no sorting; nil/never-filled list → nil, drained list → empty slice); `All` is `iter.Seq[T]` here, so `InsertIter` takes another list's `All()` directly and self-feeding via `self.All()` is safe (drained first). `Equal` is Len + one-way Search (membership, never tower layout). **`Clone` is re-insertion, not a structural copy** — fresh tower heights drawn from the global RNG, so never compare a clone's `level`/`Dump` against the receiver's; the clone test instead cross-checks `AtIndex`/`Rank` (the spans must be real) plus independent mutation. `DeleteFunc` is collect-then-delete; batch mutators return "receiver changed"; read side total over nil/zero-value. Tests use the generic `checkCapLevel0` (level-0 ascending + count == Length) plus the typed `checkInvariant` on `TestSkipListNode` paths — tower heights are RNG-drawn and never asserted (`TestCapabilitiesDeleteFuncMassDelete` also re-verifies `Rank` positions after the bulk delete).
