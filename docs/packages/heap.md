# heap notes

`Heap[T any]` is the min-heap (stdlib container/heap lineage — keep the Go Authors attribution in the header): stored comparator via `NewHeap[T cmp.Ordered]`/`NewHeapFunc` (reversed comparator ⇒ max-heap), value semantics, and the **indexed operations report `false` on out-of-range instead of panicking** (`Delete`, `Fix`, `SetValue`, `GetValue` all return bool; `Search` returns `(T, pos, bool)` with the `-1` sentinel — no vestigial always-nil err).  `All` yields **internal breadth-first order, not sorted order** — never assert sorted output from `All`; drain with `Pop` for sorted order.  `AppendHeap` bulk-appends unordered, then `Heapify` rebuilds (call it for `i = Len()/2-1` down to 0).  Panic contract: exactly 3 (`NewHeapFunc(nil)`, `Push`/`AppendHeap` on nil or zero-value).  `Pop`/`Delete` zero the slot and nil the slice on full drain.  No-op `Lock`/`Unlock` kept (heap_ts is the prospective twin).  `checkHeapInvariant` in heap_test.go verifies the parent≤children property — call it after structural changes.  `Dump` prints an indexed internal-order listing.

`heap_ts` is the twin with the `lock sync.RWMutex`: same tolerant index ops and 3-panic contract, eager value-snapshot `All`, and — unlike the plain package — **real `Lock`/`Unlock` plus the `Nl*` methods** (`NlLen`/`NlGetValue`/`NlPush`/`NlPop`/`NlDelete`/`NlFix`, the lock-free bodies `nlPop`/`nlDelete`/`nlFix`) for compound operations; calling a locked public method while holding `Lock` deadlocks.

**Phase-5 capabilities** (`capabilities.go`, plan §4.5 heaps/PQ menu; this file's exemplar is the one the other 8 §4.5 packages mirror): `Slice`, `String`/`StringFunc`, `Equal`, `Clone` — the minimal menu, no membership batches and no predicate delete (a heap is a multiset with a pop order, not a set).  `Slice`/`String` use the **internal breadth-first backing order** — the same order `All` yields and JSON marshal emits — NOT sorted (drain with `Pop` for sorted); `heap.Slice()` on 3,1,2 pushes yields `[1 3 2]`.  `Equal` is **multiset equality**: length check first, then `slices.SortFunc` copies of both sides with the stored comparator and pairwise `cmp(a,b)==0` — non-destructive, ties safe, and unlike the phase-4 sequence family it goes **through the comparator, never Go's `==`**, so non-comparable element types are fine (no comparability caveat at all).  Precondition (documented, skip_list wording): both sides must use consistent comparison functions.  `Clone` **copies the backing array** — the array copy preserves the heap property exactly, so the clone keeps the receiver's exact layout and pop sequence; no re-heapify needed.  All total functions (nil→empty semantics; `Clone(nil)`→nil).  The `heap_ts` twin: `Slice` = `snapshot()`; `Equal` snapshots each side sequentially (never two locks — deadlock-free in opposite directions); `Clone` snapshots then rebuilds locally; `cmp` is constructor-written only so reading it unlocked is safe (the sll_ts `eq` precedent); no new `Nl*` (the capabilities are self-locking, not compounds).  Tests: `capabilities_test.go` (multiset Equal incl. genuinely-different-arrangement proof `!slices.Equal(a.Slice(), b.Slice())`, `[1 1 2]` vs `[1 2 2]`, tie-heavy multisets, reversed-comparator consistency, non-destructive check, clone layout preservation, 800-step PCG(1,42) model with `checkHeapInvariant`+`checkCapModel` every 37 steps, shuffled-rebuild-must-be-equal finish) and `capabilities_example_test.go`; the twin adds `TestCapabilitiesConcurrent` + `TestCapabilitiesEqualNoDeadlock`.
