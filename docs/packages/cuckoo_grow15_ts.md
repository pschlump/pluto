# cuckoo_grow15_ts notes

`cuckoo_grow15_ts` is the experimental sibling of `cuckoo_ts` — same thread-safe cuckoo scheme (four candidate slots, full 64-bit base hash stored beside each element, kick chains with rollback, background threshold resizes, `Lock`/`Unlock` + `Nl*`), but the candidate positions come from **Lemire multiply-shift reduction over rotations** (`hi64(rotl4k(h) * size)`) instead of nibble shifts masked to a power of two — which is what allows the table to **grow ×1.5 and shrink ÷3** at any size instead of doubling/halving powers of two.  `NewHashTabFunc` avalanches the caller hash with `mix64` first (multiply-shift reads the *top* bits, so a poorly dispersed caller hash would collide the candidates).  No `mask` field, and no `Info`/resize-counter fields — `Capacity`/`Saturation` only.  The README's "why this is not the default" section holds the benchmark verdict (×1.5 loses ~10–12% time and ~45% bytes to `cuckoo_ts` at n≈96k) — the package exists to document that experiment.

`capabilities.go` (set-capabilities phase 1) adds the go-set surface (`Slice`/`String`/`StringFunc`/`Equal`/`Clone`/`Contains`/`ContainsSlice`/`ContainsAny`/`InsertSlice`/`InsertIter`/`DeleteSlice`/`DeleteFunc`), method-for-method the `cuckoo_ts` implementation with the prefix `cuckoo_grow15_ts:` in the insert-contract panics.  `Clone` copies slots by value plus the scalar set this struct actually has (size, length, growAt/shrinkAt, growLen/shrinkLen, eq, hash — no mask, no counters, no generation) and does **not** copy the `resizing` flag (the clone never has a resizer in flight; its own mutations spawn its own).  `DeleteFunc` is collect-then-delete, mandatory as in cuckoo (a shrink rebuild repositions everything).  Twin lock discipline throughout: mutating batches hold the write lock once (atomic), the `DeleteFunc` predicate and `StringFunc` format run unlocked on a snapshot, `Equal` never holds two locks, no new `Nl*`.  `capabilities_test.go` = the `cuckoo_ts` file verbatim (package line and header comment aside) including the twin-only block — keep them in sync; `capabilities_example_test.go` mirrors the same way.
