= stack

A generic slice-backed *LIFO stack* — the simplest container in pluto
alongside `queue`.  The element type needs *no constraints at all*:
there is no ordering and no equality to supply, and the zero value of
`Stack` is an empty stack ready to use without a constructor.

The stack is a *struct wrapping the slice*, matching the shape of every
other pluto container.  Elements are stored and returned *by value* —
`Pop` and `Peek` return `(T, error)` — so a peeked element is an
independent copy, never a pointer aliasing the top of the stack.

Not safe for concurrent use.

== Operations

[options="header"]
|===
| Operation                    | Description                          | Complexity

| `Push`                       | Insert at the top                    | O(1) amortized
| `Pop`                        | Remove and return the top            | O(1)
| `Peek`                       | Look at the top without removing     | O(1)
| `IsEmpty` / `Len` / `Length` | Size queries                         | O(1)
| `Truncate`                   | Remove all elements                  | O(1)
| `All` / `Backward`           | Range-over-func iterators with index | O(n)
| `Slice`                      | Fresh `[]T`, TOP DOWN (All's order)  | O(n)
| `String` / `StringFunc`      | Render the elements: `[a b c]`       | O(n)
| `Equal`                      | Same sequence (ORDER-SENSITIVE)      | O(n)
| `Clone`                      | Deep copy                            | O(n)
|===

`All` iterates from the *top* (most recently pushed, index 0) to the
bottom; `Backward` iterates from the bottom to the top.  Both reflect the
live stack — pushing or popping between iterations changes what they see.
`Len` is an alias for `Length`, matching the other pluto packages.

== Set-convenience capabilities

Sequences get the minimal menu only — `Slice`, `String`/`StringFunc`,
`Equal` and `Clone`, in link:capabilities.go[`capabilities.go`].
Sequences are not sets, so there is deliberately no `Contains`, no batch
insert/delete and no predicate bulk delete: an O(n) membership scan over
a sequence would be a footgun.

`Slice` numbers from the *top*, exactly as `All` does (index 0 is the
most recently pushed element).

[source,go]
----
stk.Push(1)
stk.Push(2)

fmt.Println(stk.String())   // [2 1] — top down
fmt.Println(stk.Slice())    // [2 1]
dup := stk.Clone()
fmt.Println(stk.Equal(dup)) // true
----

`Equal` is the one *order-sensitive* `Equal` in pluto — `[2 1]` (top
down) is not equal to `[1 2]`; every set-shaped package compares
membership instead.  It compares elements pairwise with Go's `==`
through interface conversion, so the element type must be comparable: a
non-comparable element type (a slice, map or function) panics with Go's
runtime comparison panic, but only when two elements are actually
compared — stacks of different lengths, and nil or empty stacks, are
answered without touching any element.

All four are total functions: none of them panics on a nil stack, which
behaves as an empty stack.

== Errors

The empty stack is reported with an error (compare with `errors.Is`):

[options="header"]
|===
| Error | Meaning 

| `ErrEmptyStack` | `Pop`/`Peek` on an empty stack 
|===

== Usage

[source,go]
----
var stk stack.Stack[int] // no constructor needed

stk.Push(1)
stk.Push(2)

top, _ := stk.Peek() // 2 — still on the stack
v, _ := stk.Pop()    // 2 — last in, first out
----

Iteration, top to bottom and back:

[source,go]
----
for i, v := range stk.All() {
    ...
}
for i, v := range stk.Backward() {
    ...
}
----

== Panics

The package has exactly *one* panic, a programmer error with no sane
fallback:

[options="header"]
|===
| Call | Why 

| `Push` on a nil stack | a nil stack cannot store an element 
|===

Everything else — including the zero value, which is fully usable because
there is no comparison or equality function to configure — tolerates a
nil stack as an empty stack.  The capability methods add no panics of
their own; the only caveat is `Equal`, which inherits Go's runtime
comparison panic when the element type is non-comparable and two
elements are actually compared (see above).

== Memory behavior

`Pop` zeroes the vacated slot so the backing array does not keep popped
elements alive, and releases the backing array entirely when the stack
drains completely (verified by `TestStackPopZeroesSlot`).
