= multimap_ts

Thread-safe twins of `multimap.ListMultimap`, `SetMultimap`,
`SortedSetMultimap`, `LinkedListMultimap`, and `LinkedHashMultimap`. The
collection semantics and utility behavior match the plain package. Live
`GetView`/`AsMapView` operations delegate through the same lock; each view
operation is atomic, while multi-step sequences are not transactions.

Each value contains its plain multimap and one `sync.RWMutex`. Every compound
mutation holds the write lock, so PutAll and ReplaceValues are atomic to
readers. Reads use the read lock. Nil receivers behave as empty for reads and
non-storing removals; storing methods require a non-nil constructed value.

`Entries`, `Keys`, `Values`, and `KeySet` snapshot under the lock and iterate
after releasing it. `Get`, `RemoveAll`, `ReplaceValues`, `AsMap`, and
`KeyMultiset` return independent data. Iteration and callbacks may safely call
back into the same multimap.

`Index`, `InvertFrom`, and `ForMap` are available in this package as well.
Inversion snapshots all source entries before destination mutation, avoiding
nested source/destination locks and supporting aliases. Opposite-direction
inversions cannot deadlock.

Run the package and repository race suites after changes. See
`docs/packages/multimap.md` for implementation and oracle details.
