= heap_ts

A generic, *thread-safe min-heap* — the twin of
link:../heap/[pluto/heap].  Every operation is guarded by a `sync.RWMutex`:
readers run in parallel with each other, writers are exclusive.  Like
`heap`, `Pop` always removes the minimum, a reversed comparison function
turns it into a max-heap, the element type implements no interface,
elements are stored and returned by value, and out-of-range index
operations report `false`.

The public API is identical to `heap`, *plus* the real `Lock`/`Unlock`
pair and the `Nl*` (no-lock) methods for compound operations.

== Locking behavior

* *Reads* (`Peek`, `GetValue`, `Search`, `Len`, `Length`, `IsEmpty`)
take the read lock and release it before returning — they can run in
parallel with each other — and return *value copies* taken under the
lock, never pointers aliasing elements in the heap.
* *Writes* (`Push`, `Pop`, `Delete`, `Fix`/`SetValue`, `Truncate`,
`AppendHeap`, `Heapify`) take the write lock.  `Pop`/`Delete` (and
`NlPop`/`NlDelete`) zero the vacated slot and release the backing
array on a full drain.
* *`All` operates on a snapshot* copied under the read lock when it is
called (one O(n) copy).  It is safe to mutate the heap while iterating
— including from inside the loop — and an iterator never observes
modifications made after it was created.  `All` yields internal
breadth-first order, *not* sorted order.
* *`Dump` holds the read lock for the whole dump*, so the writer must
not call methods on the same heap.
* *`Lock`/`Unlock` expose the write lock* for compound operations that
must be atomic.  While the lock is held, only the `Nl*` methods may be
called — calling a regular method will deadlock:
`NlLen`, `NlGetValue`, `NlPush`, `NlPop`, `NlDelete`, `NlFix`,
`NlAppendHeap`, `NlHeapify`.

[source,go]
----
hp.Lock()
if v, found := hp.NlGetValue(0); found && v > 3 {
    hp.NlFix(0, 3) // atomic clamp of the minimum
}
hp.Unlock()
----

== Errors and panics

Identical to `heap`: no errors — every empty or out-of-range outcome is a
`false` return — and exactly three panics:

[options="header"]
|===
| Call                                     | Why

| `NewHeapFunc(nil)`                       | nil comparison function, caught at construction time
| `Push`/`AppendHeap` on a nil heap        | a nil heap cannot store an element
| `Push`/`AppendHeap` on a zero-value heap | no comparison function; the message names the constructors
|===

Everything else tolerates a nil heap and the zero value as an empty heap.

== Usage

[source,go]
----
package main

import (
    "fmt"
    "sync"

    "github.com/pschlump/pluto/heap_ts"
)

func main() {
    hp := heap_ts.NewHeap[int]()

    // Writers from many goroutines share one heap.
    var wg sync.WaitGroup
    for p := 0; p < 8; p++ {
        wg.Add(1)
        go func(p int) {
            defer wg.Done()
            for i := 0; i < 100; i++ {
                hp.Push(p*1000 + i)
            }
        }(p)
    }
    wg.Wait()
    fmt.Println(hp.Len()) // 800

    // Concurrent pops drain it in ascending order overall.
    for !hp.IsEmpty() {
        if _, found := hp.Pop(); !found {
            break
        }
    }
    fmt.Println(hp.IsEmpty()) // true
}
----
