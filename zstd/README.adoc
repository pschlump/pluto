= zstd — the Zstandard format (RFC 8878), from scratch

`Compress(data []byte) []byte` writes a legal *stored* frame: raw
blocks under a 128 KiB window, no checksum — every zstd decoder reads
it, and it is about 0.003% larger than the input.  `Expand(z []byte)
[]byte` reads everything zstd(1) writes: every preset (`-1`..`-19`,
`--ultra -22`, `--long=25`), Huffman literals (one stream or four with
the jump table; direct 4-bit weights or FSE-coded weights with two
interleaved states; treeless repeats), FSE / predefined / RLE / repeat
sequence tables, raw / RLE / compressed blocks, content checksums,
concatenated frames, and skippable frames.  nil from Expand means
malformed.  `NewReader`/`NewWriter` stream block by block.

Honest scope: **decode is complete; encode stores**.  The compressor
side of zstd (match finder, FSE/Huffman table *writers*, the backward
interleaved bitstream encoder) is a project of its own; storing keeps
every byte legal and interoperable.  Use it where the format matters
more than the ratio.

== Wire shape

A frame: magic `28 B5 2F FD`, a descriptor byte (content-size flag,
single-segment, checksum, dictionary-id size), an optional window
byte (`windowLog = 10 + exponent`, mantissa in eighths of the base),
then 3-byte block headers (last flag, type 0 raw / 1 RLE / 2
compressed, 21-bit size — the on-disk size for raw and compressed,
the *regenerated* size for RLE) and their contents, then an optional
4-byte XXH64-low-32 content checksum.  Block_Maximum_Size is
min(window, 128 KiB), and it bounds every block's stated size — for
compressed blocks it bounds the *compressed* bytes; the regenerated
size is whatever the sequences produce.

A compressed block is a literals section, then a sequences section.
Literals: raw / RLE / Huffman-compressed / treeless (previous table),
with size formats from 2-2-5 through 2-2-20 (raw) and 2-2-10 through
2-2-18 (compressed, the third field being Compressed_Size).  Four
Huffman streams split the regenerated size in quarters (ceil), a
6-byte jump table carries the first three compressed sizes.  A
Huffman table is a list of *weights* (nbBits = MaxBits+1-weight), the
last weight implied by completing the shares Σ2^(w-1) to the next
power of two; the description is either direct 4-bit pairs or an FSE
stream with two interleaved states.

Sequences: a 1-3 byte count, a modes byte (LL/OF/ML each predefined /
RLE / FSE / repeat), optional FSE table descriptions (forward
LSB-first bitstreams: accuracy log, variable-width counts, zero runs
as chains of 2-bit repeat fields), then ONE backward bitstream
carrying all three interleaved: initial states LL→OF→ML, and per
sequence the extra bits OF→ML→LL, then state updates LL→ML→OF —
skipped for the final sequence.  Offset values 1-3 are repeat codes
(with the no-literals shift and the rep1-1 case); larger values
resolve as value-3.

== Tests

Corpus round trips; goldens from zstd(1) across levels, `--check`,
and `--long=25` (`-T1` — with `-T0` the CLI's job scheduling changes
the framing between runs); zstd(1) tests and decodes ours both
whole-buffer and streamed; concat/skippable; malformed vectors and a
3,000-case flip/truncate/overwrite sweep (errors only, never panics);
the empty-frame byte shape pinned.  `stream_test.go`: byte-at-a-time
reads, multi-frame streams, truncation, writer round trips, system
interop.

Interop reality (Nov 2026, zstd 1.5.7): every direction byte-exact;
see docs/packages/zstd.md for the wire facts that bit.
