= skip_list

A generic *skip list* — an ordered collection built from multiple levels
of linked lists, where each higher level acts as an "express lane" that
skips over roughly half the nodes below it.  Insert, Search and Delete are
*O(log₂ n) expected*, and — unlike an unbalanced
link:../binary_tree/[`binary_tree`] — performance does not degrade when items
arrive in sorted order.  See
link:https://en.wikipedia.org/wiki/Skip_list[]
for the theory; link:../avl_tree/[`avl_tree`] and link:../rb_tree/[`rb_tree`]
are the deterministic self-balancing alternatives.

* Elements are stored and returned *by value* (`T`, not `*T`); find-style
operations return `(T, bool)`.
* Lists of ordered key types (integers, floats, strings) are ordered by the
built-in `<` / `>` operators: `skip_list.NewSkipList[int]()`.
* Lists of any other type — including structs ordered by a single field —
take a plain comparison function, with no interface to implement:
`skip_list.NewSkipListFunc(func(a, b Item) int { ... })`.

Runnable, tested copies of the examples live in
link:example_test.go[`example_test.go`] — they run under `go test` and appear
on pkg.go.dev.

== Operations

[options="header"]
|===
| Operation                    | Description                                      | Complexity

| `Insert`                     | Add an item; duplicates replace the stored value | O(log₂ n) expected
| `Delete`                     | Remove an item; reports whether it was found     | O(log₂ n) expected
| `Search`                     | Return the stored item equal to the probe        | O(log₂ n) expected
| `FindMin` / `DeleteAtHead`   | Smallest item / remove it                        | O(1) / O(1) amortized
| `FindMax` / `DeleteAtTail`   | Largest item / remove it                         | O(log₂ n) expected
| `IsEmpty` / `Len` / `Length` | Size queries                                     | O(1)
| `Truncate`                   | Remove all items                                 | O(1)
| `Dump`                       | Per-level picture of the list, for debugging     | O(n)
| `All`                        | Ascending range-over-func iterator               | O(n), O(1) space
| `Backward`                   | Descending range-over-func iterator              | O(n), O(n) space
|===

`Insert` returns `true` when a new node was added and `false` when a
duplicate replaced the stored value.

Skip lists are *probabilistic*: the expected cost of the ordered
operations is O(log₂ n) but the worst case is O(n).  Node tower heights
are drawn (from the global `math/rand/v2` source, promotion probability
0.5, up to 32 levels); the observable ordering semantics are deterministic
regardless of the heights drawn.

The list is *not* safe for concurrent use.

== Usage

[source,go]
----
list := skip_list.NewSkipList[int]()

// Sorted input is no problem for a skip list.
for i := range 1000 {
    list.Insert(i)
}

min, _ := list.FindMin()
max, _ := list.FindMax()
fmt.Println(min, max) // 0 999
----

Structs ordered by a field — the element type implements no interface, and
the exported `Compare` helper builds the field comparison:

[source,go]
----
type Employee struct {
    ID   int
    Name string
}

byID := skip_list.NewSkipListFunc(func(a, b Employee) int {
    return skip_list.Compare(a.ID, b.ID)
})
byID.Insert(Employee{ID: 3, Name: "Ada"})

// A search probe only needs the fields the comparison reads: the ID.
if e, found := byID.Search(Employee{ID: 3}); found {
    fmt.Println(e.Name) // Ada
}
----

== Iteration

`All()` walks the level-0 chain directly (O(1) extra space).
`Backward()` collects the chain into a slice first and yields it in
reverse, because skip list nodes have no back pointers (O(n) extra
space).  Both support early exit via `break`, and the list must not be
modified while an iterator is being consumed.

[source,go]
----
for v := range list.All() {
    ...
}
for v := range list.Backward() {
    ...
}
----

== Panics

The package panics in exactly three situations — all programmer errors
with no sane fallback:

[options="header"]
|===
| Call                          | Why

| `NewSkipListFunc(nil)`        | nil comparison function, caught at construction time
| `Insert` on a nil `*SkipList` | a nil list cannot store an element
| `Insert` on a zero-value list | no comparison function; the message names the constructors
|===

Everything else tolerates a nil list and the zero value as an empty list:
searches find nothing, deletes return `false`, and the iterators visit
nothing.
